# 5. What Is a Process?

Before learning `subprocess`, you need one operating-system concept.

A process is a running instance of a program.

When you run:

```bash
python health_check.py
```

the operating system creates a Python process.

When that Python program starts:

```bash
df -h
```

another process is created.

Conceptually:

```text
Shell
 |
 v
Python process
 |
 +--> df process
 |
 +--> free process
 |
 +--> uptime process
```

The programs started by Python are child processes relative to the Python process.

---

# 6. What Is a Subprocess?

A subprocess is a process started and managed by another process.

In our case:

```text
Python process
      |
      v
child process
      |
      v
Linux command
```

Python's `subprocess` module provides tools for starting and interacting with these external processes.

---

# 7. Importing `subprocess`

`subprocess` is part of Python's standard library.

Use:

```python
import subprocess
```

You do not normally need:

```bash
pip install subprocess
```

It comes with Python.

# 8. The Main Function: `subprocess.run()`

One of the most important functions is:

```python
subprocess.run()
```

It runs a command and waits for it to finish.

Basic example:

```python

subprocess.run(
    ["uptime"]
)
```

Save this as:

```text
uptime_check.py
```

Run:

```bash
python uptime_check.py
```

Python starts the external:

```text
uptime
```

program.

---

# 9. What Happens Internally?

When Python executes:

```python
subprocess.run(
    ["uptime"]
)
```

the flow is roughly:

```text
Python
  |
  v
Create child process
  |
  v
Execute uptime
  |
  v
Wait for command
  |
  v
Command finishes
  |
  v
Receive completion information
  |
  v
Continue Python program
```

This is different from simply writing text to the terminal.

Python is actually starting another program.

# 34. Why `stderr` Alone Is Not a Failure Test

Some programs write warnings or progress information to `stderr` even when they ultimately succeed.

Therefore, this is unreliable:

```python
if result.stderr:
    print(
        "FAILED"
    )
```

Better:

```python
if result.returncode != 0:
    print(
        "FAILED"
    )
```

Then use `stderr` for diagnostic information.

# 36. `check=True`

Python can automatically raise an exception when a command returns a nonzero exit status.

Use:

```python
check=True
```

Example:

```python
result = subprocess.run(
    ["uptime"],
    capture_output=True,
    text=True,
    check=True

```

If the command succeeds:

```text

```

If it fails:

```text

```

---

# 37. `CalledProcessError`

When:

```python
check=True
```

and the command exits nonzero, Python raises:

```python
subprocess.CalledProcessError
```

This allows normal Python exception handling.

---

# 38. Handling `CalledProcessError`

```python
import subprocess


try:
    result = subprocess.run(
        [
            "ls",
            "/missing-directory"
        ],
        capture_output=True,
        text=True,
        check=True
    )

except subprocess.CalledProcessError as error:

    print(
        "Command failed"
    )

    print(
        f"Return code: "
        f"{error.returncode}"
    )

    print(
        f"Error: "
        f"{error.stderr}"
    )
```

This combines Part 10 exception handling with external command execution.

# 42. Commands Can Hang

Imagine Python runs:

```text
network command
```

but the network is broken.

Or:

```text
external CLI
```

waits indefinitely.

Your automation may never finish.

That is why timeouts matter.

# 43. Adding a Timeout

Use:

```python
timeout=
```

Example:

```python
result = subprocess.run(
    ["uptime"],
    capture_output=True,
    text=True,
    timeout=10
)
```

This means Python allows the command approximately 10 seconds before timing out.

---

# 44. `TimeoutExpired`

If the command exceeds the timeout, Python raises:

```python
subprocess.TimeoutExpired
```

Example:

```python
try:
    result = subprocess.run(
        command,
        capture_output=True,
        text=True,
        timeout=5
    )

except subprocess.TimeoutExpired:

    print(
        "Command timed out"
    )
```

---

# 45. Why Timeouts Are Essential

Without a timeout:

```text
Python automation
      |
      v
Run command
      |
      v
Command hangs
      |
      v
Python waits
      |
      v
Pipeline waits
      |
      v
Deployment waits
      |
      v

```

A timeout creates a boundary.

---

# 46. Choose Timeouts Intentionally

Do not use:

```python

```

for every command simply because shorter sounds safer.

For example:


# 50. A Reusable Command Runner

Let's build a reusable function.

```python
import subprocess


def run_command(
    command: list[str],
    timeout: int = 30
) -> dict:

    try:
        result = subprocess.run(
            command,
            capture_output=True,
            text=True,
            timeout=timeout
        )

    except FileNotFoundError:

        return {
            "status": "NOT_FOUND",
            "returncode": None,
            "stdout": "",
            "stderr": (
                f"Command not found: "
                f"{command[0]}"
            )
        }

    except subprocess.TimeoutExpired:

        return {
            "status": "TIMEOUT",
            "returncode": None,
            "stdout": "",
            "stderr": (
                f"Command timed out: "
                f"{command[0]}"
            )
        }

    if result.returncode == 0:

        status = "SUCCESS"

    else:

        status = "FAILED"

    return {
        "status": status,
        "returncode": result.returncode,
        "stdout": result.stdout.strip(),
        "stderr": result.stderr.strip()
    }
```

---

# 51. Why Return a Dictionary?

The function returns structured information:

```python
{
    "status": "SUCCESS",
    "returncode": 0,
    "stdout": "...",
    "stderr": ""
}
```

The caller can decide:

```text
Print it
Log it
Parse it
Store it
Alert on it
Combine it with other checks
```

The runner does not make every application decision itself.

---

# 52. Function Flow

```text
run_command()
     |
     v
Try to start process
     |
     +--> command missing
     |        |
     |        v
     |    NOT_FOUND
     |
     v
Wait with timeout
     |
     +--> timeout
     |       |
     |       v
     |    TIMEOUT
     |
     v
Inspect return code
     |
     +--> 0 ------> SUCCESS
     |
     +--> nonzero -> FAILED
```

This is reusable automation design.

# 53. Running Commands Safely

Before running an external command, ask:

1. What exact executable is being run?
2. What arguments are being supplied?
3. Which arguments come from users?
4. Which arguments come from APIs or files?
5. Does the command modify the system?
6. Could it delete data?
7. Could it restart services?
8. Could it expose secrets?
9. Does it require elevated privileges?
10. What happens if it hangs?
11. What happens if it fails halfway?
12. How will success be verified?

Running a command from Python does not make it safe.

---

# 54. Shell vs Non-Shell Execution

This is one of the most important concepts in this part.

Consider:

```python
subprocess.run(
    [
        "ping",
        "-c",
        "4",
        "example.com"
    ]
)
```

By default:

```text
shell=False
```

Python starts the executable directly.

Conceptually:

```text
Python
  |
  v
ping
  |
  +--> -c
  +--> 4
  +--> example.com
```

No shell is required to interpret the command string.

---

# 55. What Is a Shell?

A shell is a command interpreter.

Common Unix-like shells include:

```text
bash
sh
zsh
```

A shell understands special syntax such as:

```text
|
>
>>
&&
||
*
$VARIABLE
$(command)
```

These are not ordinary command arguments.

They are shell syntax.

---

# 56. Example of Shell Syntax

You may manually run:

```bash
ps aux | grep nginx
```

The:

```text
|
```

is a pipe interpreted by the shell.

It means roughly:

```text
stdout of ps aux
        |
        v
stdin of grep nginx
```

The `ps` program itself does not interpret the pipe.

The shell does.

---

# 57. `shell=True`

Python allows:

```python
subprocess.run(
    "ps aux | grep nginx",
    shell=True
)
```

This asks a shell to interpret the command string.

But `shell=True` introduces important security risks.

Do not use it merely because it seems easier.

---

# 58. Why `shell=True` Is Risky

When a shell interprets text, special characters can become commands or control operators.

Suppose:

```python
host = input(
    "Enter host: "
)
```

Then:

```python
command = (
    f"ping -c 1 {host}"
)
```

And:

```python
subprocess.run(
    command,
    shell=True
)
```

You have allowed user-controlled text to enter shell syntax.

That can become command injection.

---

# 59. What Is Command Injection?

Command injection occurs when untrusted input changes the command that the program executes.

Suppose the program expects:

```text
example.com
```

But malicious input contains shell control syntax.

Instead of:

```text
ping one host
```

the shell may interpret the text as:

```text
run intended command
+
run another command
```

The attacker has changed program behavior.

---

# 60. Why This Is Dangerous

The injected command runs with the permissions of the Python process.

If the process has access to:

* Application files.
* Credentials.
* Cloud tokens.
* Deployment systems.
* Production servers.
* Kubernetes credentials.
* CI/CD secrets.

the consequences can be severe.

This is why command construction is a security boundary.

---

# 61. Safer Non-Shell Execution

Instead of:

```python
command = (
    f"ping -c 1 {host}"
)

subprocess.run(
    command,
    shell=True
)
```

prefer:

```python
subprocess.run(
    [
        "ping",
        "-c",
        "1",
        host
    ]
)
```

Now the value of:

```python
host
```

is passed as one argument to `ping`.

It is not automatically interpreted as shell syntax.

---

# 84. Service Check Function

```python
import subprocess


def check_service(
    service: str
) -> dict:

    try:
        result = subprocess.run(
            [
                "systemctl",
                "is-active",
                service
            ],
            capture_output=True,
            text=True,
            timeout=10
        )

    except FileNotFoundError:

        return {
            "service": service,
            "status": "UNKNOWN",
            "message": (
                "systemctl not found"
            )
        }

    except subprocess.TimeoutExpired:

        return {
            "service": service,
            "status": "UNKNOWN",
            "message": (
                "service check timed out"
            )
        }

    state = (
        result.stdout
        .strip()
        .lower()
    )

    if (
        result.returncode == 0
        and
        state == "active"
    ):

        status = "HEALTHY"

    else:

        status = "UNHEALTHY"

    return {
        "service": service,
        "status": status,
        "state": state,
        "returncode": result.returncode,
        "error": result.stderr.strip()
    }
```

rather than treating every check failure as a service failure.

# 121. Build a Command Runner with `check=True`

Another design:

```python
import subprocess


def run_required_command(
    command: list[str],
    timeout: int = 30
) -> str:

    try:
        result = subprocess.run(
            command,
            capture_output=True,
            text=True,
            check=True,
            timeout=timeout
        )

    except FileNotFoundError as error:

        raise RuntimeError(
            f"Command not found: "
            f"{command[0]}"
        ) from error

    except subprocess.TimeoutExpired as error:

        raise RuntimeError(
            f"Command timed out: "
            f"{command[0]}"
        ) from error

    except subprocess.CalledProcessError as error:

        message = (
            error.stderr.strip()
            or
            "No error output"
        )

        raise RuntimeError(
            f"Command failed: "
            f"{message}"
        ) from error

    return (
        result.stdout
        .strip()
    )
```

# 129. Environment Variables for Child Processes

A subprocess normally inherits the parent's environment.

Conceptually:

```text
Shell environment
      |
      v
Python process
      |
      v
Child command
```

This can include:

* `PATH`.
* Cloud configuration.
* Application settings.
* Authentication variables.

Be aware of what you are passing to child processes.

# 130. Providing a Custom Environment

You can create a modified environment:

```python
import os


environment = os.environ.copy()

environment[
    "APP_ENV"
] = "staging"
```

Then:

```python
result = subprocess.run(
    command,
    env=environment,
    capture_output=True,
    text=True
)
```

The child receives the modified environment.

# 131. Do Not Accidentally Replace the Entire Environment

If you write:

```python
env={
    "APP_ENV": "staging"
}
```

the child may lose important inherited variables such as:

```text
PATH
HOME
```

depending on your environment and command.

A common pattern is:

```python
environment = os.environ.copy()
```

then modify only what is required.

# 132. Environment Security

Copying:

```python

```

may also pass secrets to child processes.

Ask:

```text
Does this child process need all inherited environment variables?
```

# 156. `command.py`

Create:

```python
import subprocess


def run_command(
    command: list[str],
    timeout: int = 15
) -> dict:

    if not command:
        raise ValueError(
            "Command cannot be empty"
        )

    try:
        result = subprocess.run(
            command,
            capture_output=True,
            text=True,
            timeout=timeout
        )

    except FileNotFoundError:

        return {
            "status": "NOT_FOUND",
            "returncode": None,
            "stdout": "",
            "stderr": (
                f"Executable not found: "
                f"{command[0]}"
            )
        }

    except subprocess.TimeoutExpired:

        return {
            "status": "TIMEOUT",
            "returncode": None,
            "stdout": "",
            "stderr": (
                f"Command timed out: "
                f"{command[0]}"
            )
        }

    if result.returncode == 0:

        status = "SUCCESS"

    else:

        status = "FAILED"

    return {
        "status": status,
        "returncode": result.returncode,
        "stdout": result.stdout.strip(),
        "stderr": result.stderr.strip()
    }
```
