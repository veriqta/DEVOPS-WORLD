# Part 12: Arrays, Associative Arrays, and Structured Shell Data

So far, most of your Bash variables have held one value at a time.

For example:

```bash
server="web01"
```

or:

```bash
service="nginx"
```

or:

```bash
environment="production"
```

That works when you need one item.

But real DevOps automation often deals with collections.

You may need to work with:

```text
10 servers
6 services
3 environments
20 configuration files
multiple ports
multiple deployment targets
several application versions
lists of failed resources
```

You could create separate variables:

```bash
server1="web01"
server2="web02"
server3="web03"
```

But this quickly becomes awkward.

What if you have 40 servers?

What if the number changes?

What if you need to loop through them?

What if you need to add another server dynamically?

This is where arrays become useful.

An array allows one variable to hold multiple related values.

For example:

```bash
servers=("web01" "web02" "web03")
```

Now the variable:

```text
servers
```

represents a collection.

You can:

* access one element
* access all elements
* count the elements
* add elements
* remove elements
* loop through them
* pass them to functions
* use them as server lists
* store service names
* build environment mappings
* create reusable monitoring tools

Bash also provides associative arrays.

Instead of numeric positions:

```text
0
1
2
```

associative arrays use meaningful keys.

For example:

```text
production → api.example.com
staging    → staging-api.example.com
development → localhost
```

That relationship can be represented as:

```bash
declare -A endpoints

endpoints[production]="api.example.com"
endpoints[staging]="staging-api.example.com"
endpoints[development]="localhost"
```

This lets Bash handle simple structured data.

By the end of Part 12, you should understand:

* why arrays are useful
* indexed arrays
* how to create arrays
* how to access individual elements
* how to access all elements
* array length
* adding elements
* removing elements
* iterating through arrays
* array indexes
* associative arrays
* key-value relationships
* declaring associative arrays
* accessing keys and values
* iterating over keys and values
* safe array quoting
* passing arrays to functions
* common array mistakes
* server lists
* service lists
* environment mappings
* how to build a practical multi-service monitoring script

# 1. Why Arrays Matter

Imagine you need to check three servers.

Without an array:

```bash
server1="web01"
server2="web02"
server3="web03"

printf 'Checking %s\n' "$server1"
printf 'Checking %s\n' "$server2"
printf 'Checking %s\n' "$server3"
```

This works.

But it does not scale.

With an array:

```bash
servers=("web01" "web02" "web03")
```

and:

```bash
for server in "${servers[@]}"; do
    printf 'Checking %s\n' "$server"
done
```

Now adding a fourth server requires changing only the data:

```bash
servers=("web01" "web02" "web03" "web04")
```

The loop remains unchanged.

---

# 2. Arrays Separate Data from Logic

This is an important engineering principle.

Without arrays:

```text
Data mixed with repeated logic
```

With arrays:

```text
Data
 |
 v
servers=("web01" "web02" "web03")
 |
 v
Reusable loop
 |
 v
check each server
```

The same logic can operate on different collections.

---

# 3. What Is an Indexed Array?

An indexed array stores values using numeric indexes.

Example:

```bash
servers=("web01" "web02" "web03")
```

Bash assigns indexes beginning at:

```text
0
```

So:

```text
Index 0 → web01
Index 1 → web02
Index 2 → web03
```

Think:

```text
servers
   |
   +--> [0] web01
   +--> [1] web02
   +--> [2] web03
```

---

# 4. Arrays Start at Index 0

This is important for beginners.

If:

```bash
servers=("web01" "web02" "web03")
```

the first element is:

```bash
"${servers[0]}"
```

not:

```bash
"${servers[1]}"
```

The second is:

```bash
"${servers[1]}"
```

The third:

```bash
"${servers[2]}"
```

---

# 5. Creating an Indexed Array

The simplest syntax is:

```bash
servers=("web01" "web02" "web03")
```

Values are separated by spaces inside parentheses.

Do not use commas:

Incorrect:

```bash
servers=("web01","web02","web03")
```

Those commas may become part of the values.

Correct:

```bash
servers=("web01" "web02" "web03")
```

---

# 6. Arrays Can Contain Values with Spaces

Example:

```bash
teams=("Platform Engineering" "Site Reliability" "Cloud Operations")
```

Each quoted string is one element.

Access:

```bash
printf '%s\n' "${teams[0]}"
```

Output:

```text
Platform Engineering
```

This is another reason quoting matters.

---

# 7. Declare an Indexed Array Explicitly

You may also write:

```bash
declare -a servers
```

Then:

```bash
servers=("web01" "web02" "web03")
```

The:

```text
-a
```

means indexed array.

For simple arrays, explicit declaration is not always required.

But it can make intent clear.

---

# 8. Assign Elements Individually

You can also write:

```bash
servers[0]="web01"
servers[1]="web02"
servers[2]="web03"
```

Then:

```bash
printf '%s\n' "${servers[1]}"
```

returns:

```text
web02
```

---

# 9. Sparse Arrays

Indexes do not have to be consecutive.

Example:

```bash
servers[0]="web01"
servers[5]="web06"
servers[10]="web11"
```

This is valid.

The array has elements at:

```text
0
5
10
```

not necessarily:

```text
0 through 10
```

This matters when counting and iterating through indexes.

---

# 10. Accessing One Element

Given:

```bash
services=("nginx" "redis" "postgresql")
```

First element:

```bash
printf '%s\n' "${services[0]}"
```

Output:

```text
nginx
```

Second:

```bash
printf '%s\n' "${services[1]}"
```

Output:

```text
redis
```

---

# 11. Why Use Braces?

Prefer:

```bash
"${services[1]}"
```

rather than relying on ambiguous forms.

The braces clearly define the array expansion.

This follows the same principle from normal variables:

```bash
"${variable}"
```

---

# 12. Access All Elements

Use:

```bash
"${services[@]}"
```

Example:

```bash
printf '%s\n' "${services[@]}"
```

If:

```bash
services=("nginx" "redis" "postgresql")
```

output is:

```text
nginx
redis
postgresql
```

Each element remains a separate argument.

---

# 13. `[@]` vs `[*]`

Like positional parameters, Bash arrays have:

```text
[@]
```

and:

```text
[*]
```

These behave differently when quoted.

Preferred for preserving array elements:

```bash
"${services[@]}"
```

This expands each element separately.

Quoted:

```bash
"${services[*]}"
```

combines the array into one string using the first character of `IFS` as the separator.

---

# 14. Demonstrating `"${array[@]}"`

Create:

```bash
services=("api service" "payment service" "auth service")
```

Run:

```bash
for service in "${services[@]}"; do
    printf '<%s>\n' "$service"
done
```

Output:

```text
<api service>
<payment service>
<auth service>
```

Each value remains one element.

---

# 15. Demonstrating `"${array[*]}"`

Run:

```bash
printf '<%s>\n' "${services[*]}"
```

Output is conceptually:

```text
<api service payment service auth service>
```

It becomes one combined string.

For most array iteration and argument passing, use:

```bash
"${array[@]}"
```

---

# 16. Array Length

To determine the number of elements:

```bash
"${#services[@]}"
```

Example:

```bash
services=("nginx" "redis" "postgresql")

printf 'Service count: %s\n' "${#services[@]}"
```

Output:

```text
Service count: 3
```

---

# 17. Array Length Is Not Highest Index

Suppose:

```bash
servers[0]="web01"
servers[5]="web06"
servers[10]="web11"
```

Then:

```bash
printf '%s\n' "${#servers[@]}"
```

returns:

```text
3
```

because there are three elements.

The highest index is:

```text
10
```

These are not the same concept.

---

# 18. String Length of One Element

Be careful.

This:

```bash
"${#servers[0]}"
```

means:

> length of the string stored in element 0.

If:

```text
web01
```

then the result is:

```text
5
```

But:

```bash
"${#servers[@]}"
```

means:

> number of array elements.

---

# 19. Adding Elements

Start:

```bash
servers=("web01" "web02")
```

Add one:

```bash
servers+=("web03")
```

Now:

```bash
printf '%s\n' "${servers[@]}"
```

prints:

```text
web01
web02
web03
```

---

# 20. Add Multiple Elements

You can append several:

```bash
servers+=("web04" "web05")
```

Now:

```text
web01
web02
web03
web04
web05
```

---

# 21. Add a Value with Spaces

Correct:

```bash
teams+=("Cloud Operations")
```

Do not write:

```bash
teams+=(Cloud Operations)
```

unless you intentionally want two elements:

```text
Cloud
Operations
```

---

# 22. Assign a Specific Index

You can write:

```bash
servers[7]="web08"
```

This creates or replaces index 7.

Again, the array may become sparse.

---

# 23. Replace an Existing Element

Example:

```bash
servers=("web01" "web02" "web03")

servers[1]="api02"
```

Now:

```text
Index 0 → web01
Index 1 → api02
Index 2 → web03
```

---

# 24. Removing an Element

Use:

```bash
unset 'servers[1]'
```

The quotes prevent the shell from interpreting special characters unexpectedly.

After:

```bash
servers=("web01" "web02" "web03")
unset 'servers[1]'
```

the array now contains:

```text
Index 0 → web01
Index 2 → web03
```

Index 1 disappears.

---

# 25. Removing Does Not Automatically Reindex

This surprises beginners.

After:

```bash
unset 'servers[1]'
```

you do not necessarily get:

```text
0 → web01
1 → web03
```

Instead:

```text
0 → web01
2 → web03
```

Bash indexed arrays can have gaps.

---

# 26. Unset an Entire Array

Use:

```bash
unset servers
```

Now the array variable is removed.

You can inspect:

```bash
declare -p servers
```

and Bash should report that it does not exist.

---

# 27. Iterating Through Array Values

The standard pattern is:

```bash
for server in "${servers[@]}"; do
    printf 'Checking server: %s\n' "$server"
done
```

This should become familiar.

It preserves each array element.

---

# 28. Why Quoting Matters in Array Loops

Suppose:

```bash
servers=("web01" "database primary" "web03")
```

Safe:

```bash
for server in "${servers[@]}"; do
    printf '<%s>\n' "$server"
done
```

Output:

```text
<web01>
<database primary>
<web03>
```

Unsafe:

```bash
for server in ${servers[@]}; do
```

may split:

```text
database primary
```

into:

```text
database
primary
```

---

# 29. Iterating Through Array Indexes

Use:

```bash
"${!servers[@]}"
```

Example:

```bash
for index in "${!servers[@]}"; do
    printf 'Index %s: %s\n' \
        "$index" "${servers[$index]}"
done
```

If:

```bash
servers=("web01" "web02" "web03")
```

output:

```text
Index 0: web01
Index 1: web02
Index 2: web03
```

---

# 30. Why Index Iteration Is Useful

Use indexes when you need:

* element positions
* parallel arrays
* element replacement
* debugging
* identifying missing indexes
* comparing adjacent items

Example:

```bash
for index in "${!servers[@]}"; do
    printf 'Checking server number %s: %s\n' \
        "$((index + 1))" "${servers[$index]}"
done
```

---

# 31. Sparse Index Example

Create:

```bash
servers[0]="web01"
servers[3]="web04"
servers[8]="web09"
```

Then:

```bash
printf '%s\n' "${!servers[@]}"
```

might produce indexes:

```text
0
3
8
```

Do not assume:

```bash
for ((i=0; i<${#servers[@]}; i++))
```

will visit every existing sparse index correctly.

---

# 32. Safer Sparse Array Iteration

Use:

```bash
for index in "${!servers[@]}"; do
    printf '%s\n' "${servers[$index]}"
done
```

This iterates over actual indexes.

---

# 33. Loop by Numeric Position for Dense Arrays

If you know an indexed array is dense:

```bash
servers=("web01" "web02" "web03")
```

you can write:

```bash
for (( index=0; index<${#servers[@]}; index++ )); do
    printf '%s\n' "${servers[$index]}"
done
```

But value iteration is simpler when you do not need the index:

```bash
for server in "${servers[@]}"; do
```

```bash
    "web01"
```

This multiline style is easier to read when arrays grow.

Then:

# 35. Practical Service List

Create:

```bash
services=(
    "nginx"
```

# 36. Arrays from Command Output

You may see:

```bash
servers=($(some_command))
```

This is dangerous for many kinds of data.

Why?

Because command substitution and unquoted expansion can perform word splitting and filename expansion.

If output contains:

```text
database primary
```

it may become two elements.

Avoid this unless you fully control the format.

---

# 37. `mapfile`

Bash provides:

```bash
mapfile
```

to read lines into an array.

Example:

```bash
printf '%s\n' \
    "web01" \
    "database primary" \
    "web03" > servers.txt
```

Then:

```bash
mapfile -t servers < servers.txt
```

Now:

```bash
printf '<%s>\n' "${servers[@]}"
```

preserves:

```text
<web01>
<database primary>
<web03>
```

---

# 38. What Does `mapfile -t` Mean?

`mapfile` reads lines into an indexed array.

The:

```text
-t
```

removes trailing newline characters from each stored line.

Without `-t`, line delimiters may remain attached depending on usage.

---

# 39. `readarray`

You may also encounter:

```bash
readarray
```

In Bash, `readarray` is effectively another name for `mapfile`.

Example:

```bash
readarray -t servers < servers.txt
```

---

# 40. `mapfile` Portability Note

`mapfile` is a Bash feature.

It is not a generic POSIX `sh` command.

That is fine for this Bash-focused series.

But always know whether your script is explicitly Bash or intended for another shell.

# 41. Build an Array from a Loop

You can also append values conditionally.

Example:

```bash
failed_services=()

for service in "${services[@]}"; do

    if [[ "$service" == "redis" ]]; then
        failed_services+=("$service")
    fi

done
```

Then:

```bash
printf '%s\n' "${failed_services[@]}"
```

This is useful for collecting results.

---

# 42. Empty Arrays

Create:

```bash
failed_services=()
```

Length:

```bash
printf '%s\n' "${#failed_services[@]}"
```

Output:

```text
0
```

This is a useful pattern when a script will collect failures dynamically.

---

# 43. Check Whether an Array Is Empty

Example:

```bash
if (( ${#failed_services[@]} == 0 )); then
    printf 'No failed services.\n'
else
    printf 'Failures detected.\n'
fi
```

---

# 44. Check Whether an Array Has Elements

Example:

```bash
if (( ${#failed_services[@]} > 0 )); then
    printf 'Failed services:\n'

    printf '  %s\n' "${failed_services[@]}"
fi
```

---

# 45. Copy an Array

Suppose:

```bash
production_servers=("web01" "web02" "web03")
```

Copy:

```bash
servers_copy=("${production_servers[@]}")
```

Now:

```bash
printf '%s\n' "${servers_copy[@]}"
```

contains the same elements.

---

# 46. Do Not Copy an Array as One String

Wrong when you want separate elements:

```bash
servers_copy="${production_servers[*]}"
```

Now:

```text
servers_copy
```

is an ordinary string, not an array copy.

Correct:

```bash
servers_copy=("${production_servers[@]}")
```

---

# 47. Passing Arrays to Functions

Bash does not pass arrays as a distinct function argument type in the simple way some languages do.

A common technique is expanding the array into separate function arguments.

Example:

```bash
show_servers() {
    local server

    for server in "$@"; do
        printf 'Server: %s\n' "$server"
    done
}
```

Call:

```bash
servers=("web01" "web02" "web03")

show_servers "${servers[@]}"
```

Inside the function:

```text
$1 = web01
$2 = web02
$3 = web03
```

---

# 48. Why `"${array[@]}"` Is Important When Passing

Correct:

```bash
show_servers "${servers[@]}"
```

Each element becomes one argument.

If an element is:

```text
database primary
```

it remains one argument.

Avoid:

```bash
show_servers ${servers[@]}
```

because word splitting may corrupt element boundaries.

---

# 49. Convert Function Arguments Back into an Array

Inside the function:

```bash
show_servers() {
    local servers=("$@")
    local server

    for server in "${servers[@]}"; do
        printf '%s\n' "$server"
    done
}
```

This creates a local indexed array from the function arguments.

---

# 50. Passing Additional Arguments with an Array

Suppose the function needs:

```text
environment
followed by servers
```

Call:

```bash
check_servers "production" "${servers[@]}"
```

Inside:

```bash
check_servers() {
    local environment="$1"
    shift

    local servers=("$@")

    ...
}
```

The:

```bash
shift
```

removes the first non-array argument.

The remaining positional parameters represent the array elements.

---

# 51. Example

```bash
check_servers() {
    local environment="$1"
    shift

    local servers=("$@")
    local server

    printf 'Environment: %s\n' "$environment"

    for server in "${servers[@]}"; do
        printf 'Checking %s\n' "$server"
    done
}
```

Call:

```bash
servers=("web01" "web02" "api01")

check_servers production "${servers[@]}"
```

---

# 52. Returning Arrays from Functions

Returning arrays is more complicated than returning ordinary text.

A simple beginner pattern is to print one value per line and capture it with:

```bash
mapfile
```

Example:

```bash
get_servers() {
    printf '%s\n' \
        "web01" \
        "web02" \
        "database primary"
}
```

Capture:

```bash
mapfile -t servers < <(get_servers)
```

Now:

```bash
printf '<%s>\n' "${servers[@]}"
```

preserves one server per line.

---

# 53. Process Substitution

This:

```bash
< <(get_servers)
```

is called process substitution.

The function output is exposed as input to `mapfile`.

You saw a preview of this concept in Part 7.

We do not need to explore every detail yet.

The important concept is:

```text
Function outputs lines
       |
       v
mapfile reads lines
       |
       v
Array elements
```

# 54. Associative Arrays

Indexed arrays use numeric indexes.

Associative arrays use keys.

Example:

```text
production → prod.example.com
staging    → staging.example.com
development → localhost
```

This is a key-value relationship.

---

# 55. Why Associative Arrays Are Useful

Imagine environment endpoints.

Without an associative array:

```bash
production_endpoint="prod.example.com"
staging_endpoint="staging.example.com"
development_endpoint="localhost"
```

This works.

But an associative array provides one structured mapping:

```bash
declare -A endpoints
```

then:

```bash
endpoints[production]="prod.example.com"
endpoints[staging]="staging.example.com"
endpoints[development]="localhost"
```

Now the relationship is explicit.

---

# 56. Declare an Associative Array

You must normally declare it using:

```bash
declare -A endpoints
```

The capital:

```text
-A
```

means associative array.

Do not confuse with:

```text
-a
```

which represents indexed arrays.

---

# 57. Create Values

Example:

```bash
declare -A service_ports

service_ports[nginx]="80"
service_ports[redis]="6379"
service_ports[postgresql]="5432"
```

Now:

```text
nginx      → 80
redis      → 6379
postgresql → 5432
```

---

# 58. Associative Array Literal

You can also initialize:

```bash
declare -A service_ports=(
    [nginx]="80"
    [redis]="6379"
    [postgresql]="5432"
)
```

This is readable for static configuration.

---

# 59. Access One Value

Example:

```bash
printf '%s\n' "${service_ports[redis]}"
```

Output:

```text
6379
```

---

# 60. Meaningful Keys

Unlike indexed arrays:

```text
[0]
[1]
[2]
```

associative arrays let you use keys such as:

```text
production
staging
redis
api
database
```

This makes code easier to understand.

---

# 61. Environment Mapping

Example:

```bash
declare -A endpoints=(
    [development]="http://localhost:8080"
    [staging]="https://staging-api.example.com"
    [production]="https://api.example.com"
)
```

Then:

```bash
environment="staging"

printf 'Endpoint: %s\n' "${endpoints[$environment]}"
```

Output:

```text
Endpoint: https://staging-api.example.com
```

---

# 62. Check Whether a Key Exists

Modern Bash supports:

```bash
[[ -v 'endpoints[$environment]' ]]
```

Example:

```bash
environment="production"

if [[ -v 'endpoints[$environment]' ]]; then
    printf 'Endpoint: %s\n' "${endpoints[$environment]}"
else
    printf 'ERROR: unknown environment\n' >&2
fi
```

This distinguishes missing keys from simply guessing.

---

# 63. Empty Value vs Missing Key

Suppose:

```bash
endpoints[test]=""
```

The key:

```text
test
```

exists, but its value is empty.

This is different from:

```text
qa
```

not existing at all.

Checking only:

```bash
[[ -n "${endpoints[$environment]}" ]]
```

does not clearly distinguish those cases.

When existence matters, use an existence test.

---

# 64. All Associative Array Keys

Use:

```bash
"${!service_ports[@]}"
```

Example:

```bash
printf '%s\n' "${!service_ports[@]}"
```

This prints keys such as:

```text
nginx
redis
postgresql
```

The order is not something you should normally rely on.

---

# 65. All Associative Array Values

Use:

```bash
"${service_ports[@]}"
```

This prints all values.

Example:

```text
80
6379
5432
```

Again, ordering is not guaranteed in a meaningful user-defined sequence.

---

# 66. Iterate Over Keys and Values

Example:

```bash
for service in "${!service_ports[@]}"; do
    printf '%s uses port %s\n' \
        "$service" "${service_ports[$service]}"
done
```

Possible output:

```text
nginx uses port 80
redis uses port 6379
postgresql uses port 5432
```

Do not depend on this specific order.

---

# 67. Why Associative Arrays Are Not Ordered Maps

Associative arrays are useful for lookup.

They are not designed as predictable ordered collections.

If report order matters, use a separate indexed array containing the desired order.

Example:

```bash
services=("nginx" "redis" "postgresql")
```

and:

```bash
declare -A service_ports=(
    [nginx]="80"
    [redis]="6379"
    [postgresql]="5432"
)
```

Then:

```bash
for service in "${services[@]}"; do
    printf '%s %s\n' \
        "$service" "${service_ports[$service]}"
done
```

Now order is controlled by the indexed array.

---

# 68. Combining Indexed and Associative Arrays

This is a very useful pattern.

Indexed array:

```bash
services=("nginx" "redis" "postgresql")
```

Associative array:

```bash
declare -A service_ports=(
    [nginx]="80"
    [redis]="6379"
    [postgresql]="5432"
)
```

Another mapping:

```bash
declare -A service_hosts=(
    [nginx]="127.0.0.1"
    [redis]="127.0.0.1"
    [postgresql]="127.0.0.1"
)
```

Now:

```text
services
    |
    +--> ordered list

service_ports
    |
    +--> lookup by service

service_hosts
    |
    +--> lookup by service
```

# 69. Structured Shell Data

But combining:

* associative arrays
* functions
* naming conventions

```text
    nginx
```

```text
redis
```

# 74. Quoting Arrays Safely

This is one of the most important sections.

For indexed arrays, prefer:

```bash
"${array[@]}"
```

when:

* iterating
* passing to functions
* forwarding arguments
* printing one element per argument

Avoid:

```bash
${array[@]}
```

unless you intentionally want shell splitting and glob expansion.

---

# 75. Safe Indexed Array Loop

Correct:

```bash
for item in "${items[@]}"; do
    printf '<%s>\n' "$item"
done
```

Unsafe:

```bash
for item in ${items[@]}; do
```

if elements may contain whitespace or wildcard characters.

---

# 76. Safe Associative Keys

Correct:

```bash
for key in "${!mapping[@]}"; do
    printf '%s\n' "$key"
done
```

Then:

```bash
printf '%s\n' "${mapping[$key]}"
```

Quote values when used as command arguments.

---

# 77. Array Values Can Contain Wildcards

Suppose:

```bash
patterns=("*.log" "*.txt")
```

If you use:

```bash
printf '%s\n' ${patterns[@]}
```

Bash may expand those patterns against actual files.

If you want the literal strings:

```bash
printf '%s\n' "${patterns[@]}"
```

This keeps the elements as data.

---

# 78. Common Mistake: Forgetting Braces

Beginners may write:

```bash
echo "$servers[0]"
```

This does not mean the same thing as:

```bash
echo "${servers[0]}"
```

Use braces around array expansions.

---

# 79. Common Mistake: Starting at Index 1

Incorrect assumption:

```text
first element = [1]
```

In Bash indexed arrays:

```text
first element = [0]
```

---

# 80. Common Mistake: Assuming Removing an Element Reindexes

After:

```bash
unset 'servers[1]'
```

the remaining array may contain indexes:

```text
0
2
```

not:

```text
0
1
```

Use actual indexes:

```bash
"${!servers[@]}"
```

when gaps may exist.

---

# 81. Common Mistake: Using `[*]` Instead of `[@]`

If:

```bash
servers=("web01" "database primary")
```

then:

```bash
some_function "${servers[*]}"
```

passes one combined argument.

But:

```bash
some_function "${servers[@]}"
```

passes two arguments.

Usually you want `[@]`.

---

# 82. Common Mistake: Creating Arrays from Unquoted Command Substitution

Risky:

```bash
servers=($(cat servers.txt))
```

A line:

```text
database primary
```

becomes two elements.

Prefer:

```bash
mapfile -t servers < servers.txt
```

for line-based input.

---

# 83. Common Mistake: Depending on Associative Array Order

Do not assume:

```bash
for key in "${!mapping[@]}"
```

will produce keys in insertion order.

If order matters, maintain a separate indexed list.

---

# 84. Common Mistake: Using Arrays Without Declaring Associative Type

This:

```bash
ports[nginx]="80"
```

without:

```bash
declare -A ports
```

can behave incorrectly because Bash may treat it as an indexed array expression.

Always declare associative arrays explicitly.

---

# 85. Common Mistake: Treating Arrays Like Strings

Suppose:

```bash
servers=("web01" "web02")
```

This:

```bash
servers="web03"
```

changes the meaning of the variable and can overwrite element 0 behavior.

Use:

```bash
servers+=("web03")
```

to append.

---

# 86. Common Mistake: Global Arrays Inside Functions

Suppose a function writes:

```bash
failed_services=()
```

without:

```bash
local
```

It may overwrite a global array.

Inside functions, prefer:

```bash
local -a failed_services=()
```

for local indexed arrays.

---

# 87. Local Indexed Arrays

Example:

```bash
check_services() {
    local -a services=("$@")
    local service

    for service in "${services[@]}"; do
        printf '%s\n' "$service"
    done
}
```

The:

```text
-a
```

explicitly declares a local indexed array.

---

# 88. Local Associative Arrays

Inside a function:

```bash
local -A status_map=()
```

creates a local associative array.

Example:

```bash
build_status_map() {
    local -A status_map=()

    status_map[nginx]="healthy"
    status_map[redis]="failed"

    ...
}
```

# 89. Bash Version Requirement for Associative Arrays

Associative arrays require Bash 4 or later.

This matters especially on systems that may ship older Bash versions.

Check:

```bash
printf '%s\n' "$BASH_VERSION"
```

If your script depends on associative arrays, document the requirement.

# 90. macOS Compatibility Note

Some older macOS systems historically shipped Bash 3.2 as the system Bash.

On those systems:

```bash
declare -A
```

will not work.

If your script needs associative arrays, confirm the Bash version or use an updated Bash installation.

Do not assume every machine has the same Bash version.

# 106. Port Check Function

Add:

```bash
check_port() {
    local port="$1"

    if [[ ! "$port" =~ ^[0-9]+$ ]]; then
        return 2
    fi

    ss -ltn |
        awk -v expected_port="$port" '
        NR > 1 {
            address = $4

            if (
                address ~ (":" expected_port "$") ||
                address ~ ("\\]:" expected_port "$")
            ) {
                found = 1
            }
        }

        END {
            exit(found ? 0 : 1)
        }
        '
}
```

This needs careful explanation.

---

# 107. What Does `ss -ltn` Do?

`ss` displays socket information.

Options:

```text
-l   listening sockets
-t   TCP sockets
-n   numeric output
```

So:

```bash
ss -ltn
```

asks:

> Show listening TCP sockets using numeric addresses and ports.

Example output may include:

```text
LISTEN 0 511 0.0.0.0:80 0.0.0.0:*
LISTEN 0 128 127.0.0.1:6379 0.0.0.0:*
```

Exact columns vary by implementation/version.

---

# 108. Why Use `awk` for Port Matching?

We want to detect whether the local address ends in:

```text
:80
```

or an IPv6 form such as:

```text
[::]:80
```

Rather than using a loose text search like:

```bash
grep 80
```

which could accidentally match:

```text
8080
```

we check for the expected port at the end of the address field.

```bash
    while getopts ":s:h" option; do

                address ~ ("\\]:" expected_port "$")

            }

            exit(found ? 0 : 1)
        }
        '
}

    local process_ok=false
    local port_ok=false

    process_name="${service_processes[$service]}"
    port="${service_ports[$service]}"

    if check_process "$process_name"; then
        process_ok=true

    fi

    return 1
}

print_service_result() {
    local service="$1"

    printf '%-12s status=%-9s process=%-15s port=%s\n' \
        "$service" \
        "${service_status[$service]}" \
        "${service_processes[$service]}" \
        "${service_ports[$service]}"
}

monitor_all_services() {
    local service

    for service in "${services[@]}"; do

        check_service "$service" || true

        print_service_result "$service"

    done
}

monitor_selected_service() {

    check_service "$selected_service" || true

    print_service_result "$selected_service"
}

    printf '\nSUMMARY\n'
    printf '=======\n'
```

# 147. Design Principle: Keep Configuration Near the Top

For small Bash utilities, static arrays often belong near the top:


# 148. Design Principle: Keep Related Keys Consistent

If your ordered array contains:


# 149. Validate Metadata Completeness

For every service:

```bash
for service in "${services[@]}"; do

    if [[ ! -v 'service_processes[$service]' ]]; then
        printf 'ERROR: no process mapping for %s\n' "$service" >&2
    fi

    if [[ ! -v 'service_ports[$service]' ]]; then
        printf 'ERROR: no port mapping for %s\n' "$service" >&2
    fi

done
```

This is useful when configuration arrays grow.

---

# 150. Configuration Validation Function

You could create:

```bash
validate_configuration() {
    local service
    local errors=0

    for service in "${services[@]}"; do

        if [[ ! -v 'service_processes[$service]' ]]; then
            printf 'ERROR: missing process for %s\n' "$service" >&2
            ((errors += 1))
        fi

        if [[ ! -v 'service_ports[$service]' ]]; then
            printf 'ERROR: missing port for %s\n' "$service" >&2
            ((errors += 1))
        fi

    done

    (( errors == 0 ))
}
```

This prevents the monitoring phase from running with incomplete metadata.

---

# 151. Add Configuration Validation to Main

Before checking services:

```bash
if ! validate_configuration; then
    printf 'ERROR: monitoring configuration is invalid\n' >&2
    return 1
fi
```

Now the script verifies its own internal data before acting.


and how to pass arrays into functions:

```bash
some_function "${array[@]}"
```

You also learned associative arrays:

```bash
declare -A mapping
```

which provide:

```text
key → value
```

relationships.

For example:

```text
nginx → 80
redis → 6379
postgresql → 5432
```

or:

```text
development → localhost
staging → staging.example.com
production → example.com
```

Associative arrays allow configuration lookup:

```bash
"${mapping[$key]}"
```

while indexed arrays remain useful for stable ordering.

A common Bash structure is therefore:

```text
Indexed list
     |
     +--> determines order

Associative mappings
     |
     +--> provide metadata
```

The monitoring project used:

```text
services[]
    |
    +--> ordered names

service_processes[]
    |
    +--> process lookup

service_ports[]
    |
    +--> port lookup

service_status[]
    |
    +--> collected health state

failed_services[]
    |
    +--> failures for final report
```

The most important engineering lesson from Part 12 is:

> Arrays let Bash automate collections, but good array design still requires clear data contracts, safe quoting, consistent keys, validation, and deliberate failure handling.
