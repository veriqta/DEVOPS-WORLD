# Part 2: OSI and TCP/IP Models: Understanding the Networking Layers

In Part 1, you learned the basic idea of computer networking.

A source sends data.

The data moves through a network.

A destination receives it.

But real communication is not handled by one single networking technology.

Different technologies solve different problems.

For example:

* Ethernet moves frames across a local network.
* IP identifies and routes packets between networks.
* TCP provides reliable transport for many applications.
* UDP provides connectionless transport.
* DNS resolves names.
* HTTP defines how web clients and servers communicate.

If you try to learn all of these technologies as separate facts, networking quickly becomes confusing.

Networking models solve that problem.

They divide communication into layers.

Each layer has a specific responsibility.

That gives us a structure for understanding:

* What each protocol does
* Where different devices operate
* How data moves through the network
* Where failures can occur
* How to troubleshoot systematically

The two most important networking models are:

* The OSI model
* The TCP/IP model

This part explains both from the beginning.

---

# 1. Why Networking Models Exist

Imagine trying to design one giant networking system responsible for everything.

It would need to handle:

* Electrical or radio transmission
* Cables
* Wi-Fi
* MAC addresses
* Local network delivery
* IP addressing
* Routing
* Ports
* Reliability
* Connections
* Encryption
* Data representation
* Application communication

That would be extremely difficult to build, maintain, and troubleshoot.

Instead, networking is divided into layers.

Conceptually:

```text
Application
    |
    v
Transport
    |
    v
Network
    |
    v
Data Link
    |
    v
Physical
```

Each layer focuses on a smaller part of the communication problem.

This creates several advantages.

## Standardization

Different vendors can build technologies that work together.

Your laptop does not need to be manufactured by the same company as:

* Your router
* Your switch
* Your Internet provider's equipment
* The remote server

Standards allow different systems to communicate.

## Modularity

A technology at one layer can change without completely redesigning everything above it.

For example, an application can communicate over:

* Ethernet
* Wi-Fi
* Fiber
* Cellular networking

The application does not need to understand the electrical details of every physical medium.

## Troubleshooting

Layers help engineers isolate failures.

Suppose:

```text
Application does not work
```

Instead of randomly changing settings, you can investigate layer by layer:

```text
Is the physical connection working?
        |
        v
Is local network communication working?
        |
        v
Is IP addressing correct?
        |
        v
Can packets reach the destination?
        |
        v
Is the required port reachable?
        |
        v
Is the application responding?
```

This is one of the most valuable uses of networking models.

---

# 2. The OSI Model

OSI stands for:

Open Systems Interconnection.

The OSI model contains seven layers.

They are numbered from Layer 1 through Layer 7.

```text
Layer 7    Application
Layer 6    Presentation
Layer 5    Session
Layer 4    Transport
Layer 3    Network
Layer 2    Data Link
Layer 1    Physical
```

When data is being sent, you can think of it moving downward:

```text
Layer 7
   |
   v
Layer 6
   |
   v
Layer 5
   |
   v
Layer 4
   |
   v
Layer 3
   |
   v
Layer 2
   |
   v
Layer 1
```

When data is received, it moves conceptually upward:

```text
Layer 1
   |
   v
Layer 2
   |
   v
Layer 3
   |
   v
Layer 4
   |
   v
Layer 5
   |
   v
Layer 6
   |
   v
Layer 7
```

The OSI model is primarily a conceptual framework.

Real networking implementations do not always map perfectly to every OSI layer.

But the model remains extremely useful for:

* Learning
* Design discussions
* Troubleshooting
* Understanding protocols
* Communicating with other engineers

---

# 3. Layer 7: Application

Layer 7 is the Application layer.

This is the layer closest to the applications that users interact with.

It provides network services to applications.

Common examples include protocols such as:

* HTTP
* HTTPS
* DNS
* SMTP
* FTP
* SSH
* DHCP

Do not confuse the Application layer with the application program itself.

For example:

```text
Browser
   |
   v
HTTP
```

Your browser is an application.

HTTP is an application-layer protocol used by the browser to communicate with web servers.

---

# 4. What the Application Layer Does

The Application layer defines how applications communicate over networks.

For example, HTTP defines things such as:

* Request methods
* Headers
* Response formats
* Status codes

A browser might send:

```http
GET /index.html HTTP/1.1
Host: example.com
```

The server might respond:

```http
HTTP/1.1 200 OK
Content-Type: text/html
```

This is application-layer communication.

---

# 5. Application Layer Example: DNS

Suppose you type:

```text
www.example.com
```

Your computer may need to determine the corresponding IP address.

DNS performs this job.

Conceptually:

```text
Computer
   |
   | What is the IP address of example.com?
   v
DNS Server
   |
   | Here is the IP address
   v
Computer
```

DNS is therefore commonly considered an Application-layer protocol.

---

# 6. Application Layer Troubleshooting

Suppose a network connection exists, but the website returns:

```text
HTTP 500 Internal Server Error
```

This points strongly toward an application-layer problem.

The network may already be working correctly enough to reach the web server.

The server received the request.

It produced an error response.

That means you should not begin by replacing network cables.

The evidence points higher in the stack.

Possible Application-layer failures include:

* Web server misconfiguration
* Application crash
* DNS misconfiguration
* Invalid HTTP requests
* Authentication problems
* API failures
* Incorrect application settings

---

# 7. Layer 6: Presentation

Layer 6 is the Presentation layer.

Its role is related to how data is represented.

It can be associated conceptually with:

* Data formatting
* Data encoding
* Encryption
* Decryption
* Compression
* Decompression
* Serialization

The Presentation layer helps ensure that data produced by one system can be interpreted correctly by another.

---

# 8. Data Representation

Computers can represent information in different formats.

Examples include:

* Text
* JSON
* XML
* Images
* Audio
* Video
* Binary formats

Suppose an application sends JSON:

```json
{
  "name": "Ann",
  "role": "engineer"
}
```

The receiving application must understand how that data is represented.

Encoding and serialization concepts help systems represent structured information consistently.

---

# 9. Encryption and the Presentation Layer

Encryption is often associated conceptually with the Presentation layer in OSI discussions.

For example, HTTPS uses TLS to encrypt communication.

Conceptually:

```text
Readable application data
        |
        v
Encryption
        |
        v
Encrypted data
        |
        v
Network
```

At the receiving side:

```text
Encrypted data
        |
        v
Decryption
        |
        v
Readable application data
```

Real protocol implementations do not always fit cleanly into one OSI layer.

TLS, for example, is often discussed between the Application and Transport layers.

The OSI model is a conceptual aid, not a strict description of every real protocol implementation.

---

# 10. Presentation Layer Failure Examples

Possible problems associated with this area include:

* Unsupported data format
* Encoding problems
* TLS certificate problems
* Encryption incompatibility
* Compression errors
* Serialization failures

Example:

A client connects successfully to a server but rejects its TLS certificate.

The lower layers may be functioning.

The problem may relate to certificate validation or encrypted communication.

---

# 11. Layer 5: Session

Layer 5 is the Session layer.

The Session layer is associated with establishing, managing, and ending communication sessions between applications.

A session is a logical conversation between systems.

Conceptually:

```text
Client
   |
   | Establish session
   v
Server
   |
   | Exchange information
   |
   | End session
```

The Session layer can be associated with concepts such as:

* Session establishment
* Session maintenance
* Session termination
* Checkpoints
* Dialog control

Again, modern protocols often combine responsibilities that the OSI model separates.

---

# 12. Understanding Sessions

Suppose you log into an application.

You authenticate once.

Then the application remembers that you are logged in while you navigate between pages.

That user session is not exactly the same thing as the OSI Session layer, but it helps illustrate the broader idea of maintaining communication state.

Another example might involve a long-running connection between two systems.

```text
Client
   |
   | Session begins
   |
   | Data
   |
   | Data
   |
   | Data
   |
   | Session ends
   v
Server
```

---

# 13. Session Layer Failure Examples

Conceptual session-related failures might include:

* Session unexpectedly terminating
* Session timeout
* Authentication session loss
* Communication state becoming inconsistent
* Application needing to reconnect repeatedly

In real troubleshooting, these issues may involve multiple layers and application behavior.

---

# 14. Layer 4: Transport

Layer 4 is the Transport layer.

This is one of the most important layers for practical networking.

The Transport layer is responsible for communication between applications on different systems.

Two major protocols dominate here:

* TCP
* UDP

Layer 4 introduces the concept of ports.

---

# 15. Why Ports Exist

A computer may run many network applications simultaneously.

For example:

```text
Server
 |
 +---- SSH
 |
 +---- Web Server
 |
 +---- Database
 |
 +---- DNS
```

An IP address identifies the host.

A port helps identify the application or service on that host.

Conceptually:

```text
IP address = Which computer?

Port = Which service on that computer?
```

For example:

```text
192.0.2.10:22
```

might represent SSH.

```text
192.0.2.10:443
```

might represent HTTPS.

---

# 16. TCP

TCP stands for Transmission Control Protocol.

TCP provides connection-oriented, reliable transport.

It includes mechanisms for:

* Connection establishment
* Sequencing
* Acknowledgments
* Retransmission
* Flow control
* Reliable delivery

Conceptually:

```text
Client                       Server
  |                             |
  |------- SYN ---------------->|
  |<------ SYN-ACK -------------|
  |------- ACK ---------------->|
  |                             |
  |======= Data ===============>|
```

This three-step process is called the TCP three-way handshake.

You will study it deeply in Part 9.

---

# 17. UDP

UDP stands for User Datagram Protocol.

UDP provides connectionless transport.

It does not establish a TCP-style connection before sending data.

Conceptually:

```text
Sender
  |
  |------ Datagram ------> Receiver
```

UDP has less built-in reliability than TCP.

Applications may choose UDP when:

* Low overhead matters
* Speed matters
* Occasional data loss can be tolerated
* The application handles reliability itself

Examples include certain uses of:

* DNS
* Streaming
* Voice traffic
* Gaming
* Real-time communication

---

# 18. Transport Layer Troubleshooting

Common Layer 4 problems include:

* Port not listening
* Firewall blocking a port
* TCP connection refused
* TCP connection timeout
* Connection reset
* Excessive retransmissions
* UDP traffic not reaching destination

For example:

```text
ping server
```

might work.

But:

```text
curl https://server
```

might fail.

This can happen because IP connectivity exists, but the required TCP port is unavailable.

That is why:

```text
Ping works
```

does not prove:

```text
Application works
```

---

# 19. Layer 3: Network

Layer 3 is the Network layer.

The Network layer is responsible for logical addressing and routing between networks.

The most important protocol here is IP.

Examples include:

* IPv4
* IPv6
* ICMP

Routers primarily operate at this layer.

---

# 20. IP Addressing

IP addresses identify hosts and network interfaces logically.

Example IPv4 address:

```text
192.168.1.10
```

Example IPv6 address:

```text
2001:db8::10
```

IP helps answer:

```text
Where is the destination?
```

But IP addresses alone are not enough.

Routers need to determine how to move packets toward the destination.

---

# 21. Routing

Routing determines the path packets take between networks.

Consider:

```text
Computer A
192.168.1.10
     |
     v
Router
     |
     v
Internet
     |
     v
Router
     |
     v
Server
203.0.113.20
```

Computer A cannot directly deliver Ethernet frames across the entire Internet.

It sends packets toward a router.

Routers examine destination IP addresses and forwarding information.

They move packets from network to network.

---

# 22. Network Layer Troubleshooting

Common Layer 3 problems include:

* Incorrect IP address
* Incorrect subnet mask
* Missing route
* Incorrect default gateway
* Routing loop
* Destination unreachable
* IP conflict
* Incorrect route table
* Network unreachable

Common symptoms include:

```text
Network is unreachable
```

or:

```text
No route to host
```

although exact messages depend on the system and failure.

---

# 23. Layer 2: Data Link

Layer 2 is the Data Link layer.

It handles communication across a local link.

Ethernet is one of the most important Layer 2 technologies.

Important Layer 2 concepts include:

* MAC addresses
* Ethernet frames
* Switches
* VLANs
* ARP relationships
* Local delivery

---

# 24. MAC Addresses

A MAC address identifies a network interface at Layer 2.

An example might look like:

```text
00:1A:2B:3C:4D:5E
```

MAC addresses are used in local Ethernet communication.

Conceptually:

```text
Source MAC
      |
      v
Ethernet Frame
      |
      v
Destination MAC
```

Switches learn which MAC addresses are reachable through which switch ports.

---

# 25. Layer 2 and Local Communication

Suppose two computers are on the same Ethernet network.

```text
Computer A
   |
   v
Switch
   |
   v
Computer B
```

The switch forwards Ethernet frames based on MAC addresses.

It does not normally need to make an IP routing decision for local Layer 2 forwarding.

---

# 26. Layer 2 Troubleshooting

Common Layer 2 problems include:

* Wrong VLAN
* Switch port down
* MAC learning problems
* Layer 2 loop
* Incorrect trunk configuration
* ARP failure
* Ethernet framing issues
* Duplex mismatch

Symptoms can include:

* Device appears connected but cannot reach local systems
* Only devices in one VLAN are affected
* Broadcast storms
* Intermittent local communication

---

# 27. Layer 1: Physical

Layer 1 is the Physical layer.

It represents the actual transmission of bits.

Examples include:

* Copper cables
* Fiber-optic cables
* Radio signals
* Connectors
* Transceivers
* Electrical signaling
* Optical signaling

At Layer 1, information is ultimately represented as physical signals.

---

# 28. Layer 1 Is About Bits

The unit associated with Layer 1 is:

```text
Bits
```

A bit is:

```text
0
```

or:

```text
1
```

Computers ultimately transmit encoded bits through physical media.

For example:

```text
101101001011
```

Those bits may be represented using:

* Electrical voltage changes
* Light pulses
* Radio signals

depending on the physical technology.

---

# 29. Layer 1 Failure Examples

Common Layer 1 failures include:

* Cable unplugged
* Damaged cable
* Failed network interface
* Failed switch port
* Fiber problem
* Weak wireless signal
* Radio interference
* Transceiver failure
* No link detected

If Layer 1 fails completely, higher-layer communication cannot work across that path.

Conceptually:

```text
Layer 7 Application
Layer 6 Presentation
Layer 5 Session
Layer 4 Transport
Layer 3 Network
Layer 2 Data Link
Layer 1 Physical  X
```

Everything above depends on the physical connectivity below.

---

# 30. The Complete OSI Model

Now put all seven layers together.

```text
+-----------------------------+
| Layer 7: Application        |
+-----------------------------+
| Layer 6: Presentation       |
+-----------------------------+
| Layer 5: Session            |
+-----------------------------+
| Layer 4: Transport          |
+-----------------------------+
| Layer 3: Network            |
+-----------------------------+
| Layer 2: Data Link          |
+-----------------------------+
| Layer 1: Physical           |
+-----------------------------+
```

A simplified responsibility map:

| Layer          | Main idea                             |
| -------------- | ------------------------------------- |
| 7 Application  | Network services used by applications |
| 6 Presentation | Representation, encoding, encryption  |
| 5 Session      | Communication-session management      |
| 4 Transport    | End-to-end transport and ports        |
| 3 Network      | IP addressing and routing             |
| 2 Data Link    | Local link delivery and frames        |
| 1 Physical     | Transmission of bits                  |

---

# 31. A Practical Way to Remember the Layers

Do not rely only on a mnemonic.

Understand the progression.

From top to bottom:

```text
Application
What does the application need to communicate?

Presentation
How is that information represented?

Session
How is the conversation maintained?

Transport
Which application should receive it, and how should it be transported?

Network
Which host and network should receive it?

Data Link
How should it move across the local link?

Physical
How are the bits actually transmitted?
```

Understanding this logic is more useful than memorizing seven words.

---

# 32. The TCP/IP Model

The TCP/IP model is another networking model.

It is more closely aligned with the protocols used by the Internet.

A common four-layer version is:

```text
Application
Transport
Internet
Network Access
```

Some sources use a five-layer version by separating Data Link and Physical.

For this article, we will focus mainly on the common four-layer structure.

---

# 33. TCP/IP Application Layer

The TCP/IP Application layer combines responsibilities that the OSI model separates into:

* Application
* Presentation
* Session

So:

```text
OSI

Application
Presentation
Session

        |
        v

TCP/IP

Application
```

Protocols commonly associated with this layer include:

* HTTP
* HTTPS
* DNS
* SSH
* SMTP
* FTP
* DHCP

---

# 34. TCP/IP Transport Layer

The TCP/IP Transport layer corresponds closely to OSI Layer 4.

Major protocols:

```text
TCP
UDP
```

Responsibilities include:

* Port numbers
* Application-to-application transport
* Reliability where required
* Connection management for TCP

---

# 35. TCP/IP Internet Layer

The TCP/IP Internet layer corresponds broadly to the OSI Network layer.

Major protocols include:

* IPv4
* IPv6
* ICMP

Responsibilities include:

* Logical addressing
* Packet forwarding
* Routing between networks

---

# 36. TCP/IP Network Access Layer

The TCP/IP Network Access layer generally combines concepts from:

* OSI Data Link
* OSI Physical

It includes technologies related to:

* Ethernet
* Wi-Fi
* Frames
* MAC addresses
* Physical transmission

Conceptually:

```text
TCP/IP Network Access

      |
      +---- Data Link responsibilities
      |
      +---- Physical responsibilities
```

---

# 37. OSI vs TCP/IP

A useful comparison:

| OSI          | TCP/IP         |
| ------------ | -------------- |
| Application  | Application    |
| Presentation | Application    |
| Session      | Application    |
| Transport    | Transport      |
| Network      | Internet       |
| Data Link    | Network Access |
| Physical     | Network Access |

Visually:

```text
OSI                         TCP/IP

Application  --------\
Presentation ---------+---- Application
Session --------------/

Transport ---------------- Transport

Network ------------------ Internet

Data Link -----------\
                      +---- Network Access
Physical ------------/
```

---

# 38. Which Model Should You Use?

You should understand both.

The TCP/IP model maps more directly to Internet protocol architecture.

The OSI model is extremely useful for:

* Learning
* Troubleshooting
* Discussing network functions
* Categorizing technologies

Engineers frequently say things such as:

```text
Layer 2 problem
```

```text
Layer 3 routing issue
```

```text
Layer 4 connectivity issue
```

```text
Layer 7 error
```

So even though real networking does not perfectly follow the OSI model, the terminology remains valuable.

---

# 39. Protocol Data Units

As data moves through different layers, the unit of information may have different names.

These units are often called Protocol Data Units, or PDUs.

A simplified mapping is:

```text
Application layers    Data
Transport             Segment / Datagram
Network               Packet
Data Link             Frame
Physical              Bits
```

More precisely:

* TCP transport unit: segment
* UDP transport unit: datagram
* IP unit: packet
* Ethernet unit: frame
* Physical transmission: bits

---

# 40. Bits

Bits are associated with Layer 1.

Example:

```text
1010101101010010
```

These bits are transmitted using the physical medium.

You normally do not troubleshoot application failures by manually reading electrical bits.

But every network communication eventually becomes signals carrying bits.

---

# 41. Frames

Frames operate at Layer 2.

For Ethernet, a simplified frame concept looks like:

```text
+----------------------+
| Destination MAC      |
+----------------------+
| Source MAC           |
+----------------------+
| Type / Control info  |
+----------------------+
| Payload              |
+----------------------+
| Trailer              |
+----------------------+
```

The payload can contain an IP packet.

So:

```text
Ethernet Frame
    |
    +---- Ethernet header
    |
    +---- IP packet
    |
    +---- Trailer
```

---

# 42. Packets

Packets operate at Layer 3.

A simplified IP packet:

```text
+----------------------+
| IP Header            |
+----------------------+
| Transport Data       |
+----------------------+
```

The IP header contains important information such as:

* Source IP address
* Destination IP address

For a TCP communication, the packet payload may contain a TCP segment.

---

# 43. TCP Segments

A TCP segment belongs to Layer 4.

Simplified:

```text
+----------------------+
| TCP Header           |
+----------------------+
| Application Data     |
+----------------------+
```

TCP header information includes things such as:

* Source port
* Destination port
* Sequence number
* Acknowledgment information
* TCP flags

---

# 44. UDP Datagrams

UDP also operates at Layer 4.

Its unit is commonly called a UDP datagram.

Simplified:

```text
+----------------------+
| UDP Header           |
+----------------------+
| Application Data     |
+----------------------+
```

The UDP header is simpler than TCP's.

It contains fields such as:

* Source port
* Destination port
* Length
* Checksum

---

# 45. One Piece of Data Becomes Multiple Nested Units

Suppose an application wants to send:

```text
HELLO
```

At the Application layer:

```text
HELLO
```

TCP adds information:

```text
[TCP HEADER][HELLO]
```

This becomes a TCP segment.

IP adds its header:

```text
[IP HEADER][TCP HEADER][HELLO]
```

This becomes an IP packet.

Ethernet adds Layer 2 information:

```text
[ETHERNET HEADER][IP HEADER][TCP HEADER][HELLO][TRAILER]
```

This becomes an Ethernet frame.

Finally, the frame is transmitted as bits.

```text
101001010101110...
```

This is encapsulation.

---

# 46. Encapsulation Step by Step

Consider a browser sending an HTTP request.

## Step 1: Application Layer

The browser creates an HTTP request.

```http
GET / HTTP/1.1
Host: example.com
```

At this stage, we can think of it as application data.

---

## Step 2: Transport Layer

TCP adds a TCP header.

Conceptually:

```text
[TCP HEADER]
[HTTP DATA]
```

The TCP header includes ports.

For example:

```text
Source port: 53000
Destination port: 443
```

The resulting unit is a TCP segment.

---

## Step 3: Network Layer

IP adds an IP header.

```text
[IP HEADER]
[TCP HEADER]
[HTTP DATA]
```

The IP header includes:

```text
Source IP
Destination IP
```

This is now an IP packet.

---

## Step 4: Data Link Layer

Ethernet adds local-link information.

```text
[ETHERNET HEADER]
[IP HEADER]
[TCP HEADER]
[HTTP DATA]
[ETHERNET TRAILER]
```

This is an Ethernet frame.

---

## Step 5: Physical Layer

The frame is converted into signals representing bits.

```text
101101001010...
```

These bits travel across:

* Copper
* Fiber
* Radio

depending on the technology.

---

# 47. Decapsulation Step by Step

At the receiving system, the reverse occurs.

## Step 1: Physical Layer

Signals are received and interpreted as bits.

## Step 2: Data Link Layer

The Ethernet frame is processed.

Layer 2 information is examined.

The contained IP packet is passed upward.

## Step 3: Network Layer

The IP header is processed.

The destination information is examined.

The transport data is passed upward.

## Step 4: Transport Layer

TCP processes:

* Port information
* Sequence information
* Connection state

The application data is passed upward.

## Step 5: Application Layer

The web server receives the HTTP request.

Conceptually:

```text
Bits
  |
  v
Frame
  |
  v
Packet
  |
  v
Segment
  |
  v
Application Data
```

---

The complete mental model is:

```text
SENDER

Application
    |
    | Data
    v
Transport
    |
    | Segment / Datagram
    v
Network
    |
    | Packet
    v
Data Link
    |
    | Frame
    v
Physical
    |
    | Bits
    v
================ NETWORK ================
    |
    v
Physical
    |
    | Bits
    v
Data Link
    |
    | Frame
    v
Network
    |
    | Packet
    v
Transport
    |
    | Segment / Datagram
    v
Application

RECEIVER
```

This is one of the most important diagrams in networking.

# 49. Intermediate Devices Do Not Always Process Every Layer

Suppose:

```text
Laptop
   |
   v
Switch
   |
   v
Router
   |
   v
Server
```

Different devices focus on different layers.

The laptop and server process the full stack for their applications.

The switch primarily works with Layer 2 information.

The router primarily makes Layer 3 forwarding decisions.

Conceptually:

```text
Laptop
Layers 1-7

Switch
Mostly Layers 1-2

Router
Mostly Layers 1-3

Server
Layers 1-7
```

This is simplified, because modern devices can perform functions across multiple layers.

But it is a useful beginner mental model.

---

# 50. Layer 1 Devices

Devices associated with Layer 1 include technologies such as:

* Repeaters
* Hubs
* Cables
* Transceivers

A hub repeats incoming electrical signals to other ports.

Unlike a modern switch, it does not make intelligent Layer 2 forwarding decisions.

---

# 51. Layer 2 Devices

The classic Layer 2 device is the Ethernet switch.

A switch examines MAC addresses.

Conceptually:

```text
Frame arrives
     |
     v
Read destination MAC
     |
     v
Check MAC address table
     |
     v
Forward frame
```

Switching will be covered deeply in later parts.

---

# 52. Layer 3 Devices

The classic Layer 3 device is the router.

A router examines IP addresses and routing tables.

Conceptually:

```text
Packet arrives
     |
     v
Read destination IP
     |
     v
Check routing table
     |
     v
Choose next hop
     |
     v
Forward packet
```

---

# 53. Layer 4 Devices and Functions

Some devices can inspect:

* TCP
* UDP
* Port numbers

Examples include certain:

* Firewalls
* Load balancers
* Network security systems

A Layer 4 load balancer might distribute connections based on:

```text
IP address
+
TCP/UDP port
```

# 54. Layer 7 Devices and Functions

Layer 7 systems understand application-layer information.

Examples include:

* Reverse proxies
* Web application firewalls
* Application load balancers
* API gateways

A Layer 7 load balancer can potentially inspect:

* HTTP hostname
* URL path
* Headers
* Cookies

For example:

```text
/api/*      ---> API servers

/images/*   ---> Image servers

/admin/*    ---> Admin servers
```

This requires understanding application-level data.

# 57. Why Layered Troubleshooting Works

Suppose someone says:

```text
I cannot access the website.
```

This could involve many layers.

Start low and gather evidence.

Conceptually:

```text

        |
        v

Layer 2

        |
        v

Layer 3
Is IP addressing and routing working?

        |
        v

Layer 4
Can I reach the service port?

        |
        v
```

# 58. Layer 1 Failure Example

Scenario:

A server cannot communicate with anything.

The interface shows:

```text
NO-CARRIER
```

or the physical link light is off.

Possible causes:

* Cable disconnected
* Switch port down
* Interface hardware failure
* Transceiver problem

You should investigate Layer 1 before changing DNS.

Why?

DNS cannot work if the server cannot transmit anything physically.

---

# 59. Layer 2 Failure Example

Scenario:

A host has an IP address.

Its cable is connected.

But it cannot communicate with another machine on the same VLAN.

Possible Layer 2 causes include:

* Wrong VLAN assignment
* Switch configuration
* MAC forwarding issue
* Layer 2 loop
* ARP-related problem

You would investigate local-link communication.

---

# 60. Layer 3 Failure Example

Scenario:

A server can communicate with systems on its own subnet.

But it cannot reach remote networks.

That strongly suggests investigating Layer 3.

Possible causes include:

* Missing default route
* Incorrect gateway
* Incorrect subnet mask
* Router problem
* Route table issue

Conceptually:

```text
Local network works
       |
       v
Remote network fails
       |
       v
Investigate routing
```

---

# 61. Layer 4 Failure Example

Scenario:

You can ping the server.

But HTTPS does not work.

```text
ping server
SUCCESS
```

But:

```text
TCP port 443
FAILURE
```

Possible causes include:

* Web service not listening
* Firewall blocking TCP 443
* Load balancer issue
* TCP connection failure

The host is reachable at Layer 3.

The problem may now exist around Layer 4 or higher.

---

# 62. Layer 7 Failure Example

Scenario:

You connect successfully to the server.

The TCP connection succeeds.

But the server responds:

```text
HTTP 500 Internal Server Error
```

This means much of the lower-layer path has already worked.

The request reached the application infrastructure.

The problem is likely higher in the stack.

Investigate:

* Application logs
* Web server configuration
* Backend dependencies
* Application code
* Database connectivity

# 63. Layer-by-Layer Troubleshooting Example

Suppose:

```text
User
 |
 v
Wi-Fi
 |
 v
Router
 |
 v
Internet
 |
 v
Web Server
```

The user reports:

```text
Website does not load.
```

## Layer 1

Check:

* Is Wi-Fi enabled?
* Is there a signal?
* Is Ethernet connected if wired?
* Is the interface up?

If no connectivity exists here, fix it first.

## Layer 2

Check:

* Is the device properly connected to the local network?
* Is the correct VLAN being used?
* Can it communicate locally?

## Layer 3

Check:

* Does the device have an IP address?
* Is the subnet correct?
* Is there a default gateway?
* Can it reach external IPs?

## Layer 4

Check:

* Can the destination TCP port be reached?
* Is the service listening?
* Is a firewall blocking the port?

## Layer 7

Check:

* Does DNS resolve?
* Does the HTTP request succeed?
* What status code is returned?
* Is the application healthy?

Notice how each step narrows the problem.

# 64. Bottom-Up Troubleshooting

Bottom-up troubleshooting starts at Layer 1.

```text
Physical
   |
   v
Data Link
   |
   v
Network
   |
   v
Transport
   |
   v
Application
```

This approach is useful when:

* You suspect connectivity problems
* The device appears completely disconnected
* Little information is available

Example:

```text
No network connectivity at all
```

Start with:

```text
Cable?
Interface?
Link?
```

before investigating the application.

# 65. Top-Down Troubleshooting

Top-down troubleshooting starts with the application.

```text
Application
   |
   v
Transport
   |
   v
Network
   |
   v
Data Link
   |
   v
Physical
```

This is useful when:

* Physical networking obviously works
* Only one application is affected
* Other network services work normally

For example:

```text
SSH works
DNS works
Ping works
Only website fails
```

Starting at Layer 1 may waste time.

The evidence already points higher.

---

# 66. Divide-and-Conquer Troubleshooting

Experienced engineers often begin somewhere in the middle.

For example:

```text
Can I reach the destination IP?
```

If yes:

Layer 1 through much of Layer 3 are probably functioning.

Then investigate:

```text
Layer 4+
```

If no:

Investigate:

```text
Layer 1-3
```

This is called a divide-and-conquer approach.

It helps narrow the problem quickly.

---

# 67. Important Warning: Do Not Treat Layers as Absolute

The OSI model is extremely useful, but real-world failures can cross layers.

Example:

A firewall may inspect:

* IP addresses
* Ports
* Application data

A load balancer may operate at:

* Layer 4
* Layer 7

TLS can be discussed at different conceptual layers.

DNS is an Application-layer protocol but commonly uses UDP or TCP underneath.

So do not think:

```text
Every technology belongs perfectly to exactly one layer.
```

Instead think:

```text
Layers help organize responsibilities.
```

That is the correct mental model.

# 73. What Changes at a Router?

This is a very important concept.

Suppose:

```text
Computer A
   |
   v
Router
   |
   v
Computer B
```

The Layer 2 frame used between Computer A and the router is not necessarily the same Layer 2 frame used between the router and Computer B.

The router removes the incoming Layer 2 frame, processes the IP packet, and creates a new appropriate Layer 2 frame for the next link.

Conceptually:

```text
Computer A
   |
   | Frame 1
   v
Router
   |
   | Frame 2
   v
Computer B
```

The IP packet generally continues toward the destination, although certain fields can change during forwarding.

This distinction is critical:

```text
Layer 2 information changes hop by hop.

Layer 3 information identifies the end-to-end IP communication.
```

There are exceptions and modifications such as NAT, which you will learn later.

# 83. Common Beginner Mistakes

## Mistake 1: Memorizing the OSI model without understanding it

Being able to say:

```text
Application
Presentation
Session
Transport
Network
Data Link
Physical
```

is not enough.

You need to understand what problems each layer solves.

---

## Mistake 2: Thinking protocols exist independently

HTTP does not magically travel directly over a cable.

It relies on lower-layer protocols.

Conceptually:

```text
HTTP
 |
TCP
 |
IP
 |
Ethernet/Wi-Fi
 |
Physical transmission
```

---

## Mistake 3: Assuming every technology belongs perfectly to one OSI layer

The OSI model is conceptual.

Real protocols can span responsibilities or fit imperfectly.

Use the model to understand functions, not to force reality into rigid boxes.

---

## Mistake 4: Starting at the wrong layer during troubleshooting

If a cable is disconnected, troubleshooting HTTP headers is pointless.

If only one API endpoint is returning HTTP 500 while all networking works, replacing the cable is equally pointless.

Let evidence guide where you investigate.

---

## Mistake 5: Confusing IP addresses with MAC addresses

Remember:

```text
MAC
Mostly local Layer 2 delivery

IP
Layer 3 addressing and routing
```

They solve different problems.

---

## Mistake 6: Confusing ports with IP addresses

An IP address identifies a host or interface.

A port identifies an application endpoint on that host.

Conceptually:

```text
IP = building address

Port = room/service inside the building
```

This analogy is simplified but useful.
