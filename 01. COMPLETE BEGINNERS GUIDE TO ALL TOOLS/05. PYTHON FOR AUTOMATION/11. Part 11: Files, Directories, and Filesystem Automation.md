# 1. What Is a Filesystem?

A filesystem is the structure an operating system uses to organize and store data.

At a simplified level:

```text
Filesystem
    |
    +-- directories
    |      |
    |      +-- subdirectories
    |      |
    |      +-- files
    |
    +-- files
```

For example, on Linux:

```text
/
|
+-- etc/
|
+-- home/
|    |
|    +-- ann/
|         |
|         +-- projects/
|         |
|         +-- logs/
|
+-- var/
     |
     +-- log/
```

The filesystem gives files and directories locations.

Those locations are represented using:

```text
paths
```

Understanding paths is the foundation of filesystem automation.

---

# 2. What Is a File?

A file is a named collection of data stored by a filesystem.

Examples:

```text
app.log
servers.json
deployment.yaml
main.py
README.md
terraform.tf
report.txt
```

Files can contain many kinds of data:

```text
Plain text
JSON
YAML
Python code
Images
Executables
Compressed archives
Binary data
Certificates
Database files
```

Python can work with both text and binary files.

This part primarily focuses on text files because they are common in beginner DevOps automation.

---

# 3. What Is a Directory?

A directory is a filesystem container used to organize files and other directories.

For example:

```text
project/
|
+-- main.py
|
+-- config/
|    |
|    +-- servers.json
|
+-- logs/
|    |
|    +-- app.log
|
+-- reports/
```

Here:

```text
project
config
logs
reports
```

are directories.

And:

```text
main.py
servers.json
app.log
```

are files.

---

# 4. Directory vs Folder

In everyday use:

```text
directory
```

and:

```text
folder
```

usually refer to the same concept.

Technical documentation often uses:

```text
directory
```

because that is the traditional filesystem term.

# 5. What Is a Path?

A path describes the location of a file or directory.

Example:

```text
/home/ann/projects/app/config.json
```

This tells the operating system where:

```text
config.json
```

is located.

You can think of a path as an address.

```text
Filesystem
    |
    v
/home
    |
    v
ann
    |
    v
projects
    |
    v
app
    |
    v
config.json
```

---

# 6. Linux and macOS Path Separators

Linux and macOS commonly use:

```text
/
```

between path components.

Example:

```text
/home/ann/logs/app.log
```

---

# 7. Windows Paths

Windows commonly uses backslashes:

```text
C:\Users\Ann\logs\app.log
```

Backslashes can be significant inside Python strings because sequences such as:

```text
\n
\t
```

have special meanings.

This is one reason `pathlib` is valuable.

It allows you to work with filesystem paths more cleanly instead of manually joining path strings.

---

# 8. Absolute Paths

An absolute path describes a location starting from the filesystem's root or another platform-specific absolute starting point.

Linux example:

```text
/var/log/nginx/access.log
```

This starts with:

```text
/
```

which represents the root directory.

Conceptually:

```text
/
|
+-- var
     |
     +-- log
          |
          +-- nginx
               |
               +-- access.log
```

---

# 9. Windows Absolute Path

A Windows example might be:

```text
C:\Users\Ann\logs\app.log
```

The exact filesystem conventions differ across operating systems.

The important concept is:

```text
Absolute path
=
a path that identifies a location independently
of your program's current working directory
```

---

# 10. Relative Paths

A relative path is interpreted relative to another location, usually the program's current working directory.

Example:

```text
config/servers.json
```

This does not tell Python the complete filesystem location.

Python must combine it with the current working directory.

Suppose the current directory is:

```text
/home/ann/project
```

Then:

```text
config/servers.json
```

refers to:

```text
/home/ann/project/config/servers.json
```

---

# 11. Absolute vs Relative

Suppose:

```text
Current working directory:
/home/ann/project
```

Relative:

```text
logs/app.log
```

resolves to:

```text
/home/ann/project/logs/app.log
```

Absolute:

```text
/var/log/app.log
```

refers directly to:

```text
/var/log/app.log
```

regardless of the current working directory.

---

# 12. Why Relative Paths Cause Beginner Problems

Consider:

```python
open("config.json")
```

A beginner may think Python automatically looks beside the Python script.

Not necessarily.

A relative path is normally interpreted from:

```text
the current working directory
```

not automatically from:

```text
the directory containing the script
```

This distinction causes many:

```text
FileNotFoundError
```

problems.

---

# 13. What Is the Current Working Directory?

The current working directory, often abbreviated:

```text
CWD
```

is the directory from which relative filesystem operations are resolved.

Suppose your terminal shows:

```text
/home/ann/project
```

and you run:

```bash
python main.py
```

Your process may begin with:

```text
/home/ann/project
```

as its current working directory.

```python
from pathlib import Path


print(
    Path.cwd()
```

`cwd` means:

```text
current working directory
```

Possible output:

```text
/home/ann/project
```

# 15. Using `os.getcwd()`

You may also see:

```python
import os


print(
```

Both approaches are useful.

For modern path-oriented Python code, we will emphasize:

```text
pathlib
```

---

# 16. Why CWD Matters

Suppose:

```python
with open(
    "logs/app.log",
    "r"
) as file:
    content = file.read()
```

Python effectively asks:

```text
Current working directory
        +
logs/app.log
```

If CWD is:

```text
/home/ann/project
```

Python looks for:

```text
/home/ann/project/logs/app.log
```

If CWD is:

```text
/home/ann
```

it looks for:

```text
/home/ann/logs/app.log
```

Same code.

Different target.

# 17. Troubleshooting Relative Paths

When you receive:

```text
FileNotFoundError
```

do not immediately conclude:

```text
The file does not exist.
```

First investigate:

```python
from pathlib import Path


print(
    "Current directory:",
    Path.cwd()
)

path = Path(
    "config/servers.json"
)

print(
    "Resolved path:",
    path.resolve()
)
```

Now you can see where Python is actually looking.

```python
from pathlib import Path

    path.resolve()
)
```

If your CWD is:

```text
/home/ann/project
```

```text
/home/ann/project/logs/app.log
```

This is extremely useful for debugging path problems.

# 19. What Is `open()`?

Python provides the built-in:

```python
open()
```

function for opening files.

Basic syntax:

```python
open(
    file,
    mode
)
```

For example:

```python
open(
    "app.log",
    "r"
)
```

Here:

```text
app.log
```

is the path.

And:

```text
r
```

means:

```text
read mode
```

---

# 20. Opening a File

Example:

```python
file = open(
    "app.log",
    "r"
)
```

The returned object represents the opened file.

You can then interact with it.

For example:

```python
content = file.read()
```

When finished:

```python
file.close()
```

---

# 21. Why Files Should Be Closed

Opening a file uses operating-system resources.

Leaving many files open unnecessarily can create resource problems.

Closing also helps ensure buffered writes are properly finalized.

Instead of manually managing:

```python
open()
```

and:

```python
close()
```

Python provides a cleaner pattern:

```text
with
```

---

# 22. The `with` Statement

Example:

```python
with open(
    "app.log",
    "r"
) as file:
    content = file.read()
```

The file is automatically managed by the context manager.

When execution leaves the `with` block, Python closes the file appropriately.

---

# 23. Understanding `with`

Conceptually:

```text
Enter with block
      |
      v
Open resource
      |
      v
Use resource
      |
      v
Leave block
      |
      v
Cleanup/close resource
```

This remains useful even if an exception occurs inside the block.

---

# 24. Why `with` Is Preferred

Instead of:

```python
file = open(
    "app.log",
    "r"
)

content = file.read()

file.close()
```

prefer:

```python
with open(
    "app.log",
    "r"
) as file:
    content = file.read()
```

The second approach is:

* Cleaner.
* Safer.
* Easier to read.
* Less likely to forget cleanup.

# 26. Read Mode: `r`

Example:

```python
with open(
    "app.log",
    "r"

```

`r` means:

```text
Open this file for reading.
```

```text
FileNotFoundError
```

# 27. Reading an Entire File

Suppose:

`app.log` contains:

```text
Application started

```

```python
with open(
    "app.log",
```

# 28. What Does `.read()` Return?

For a text file:

```python
content = file.read()
```

normally returns a:

```text
string
```

You can verify:

```python
print(
    type(content)
)
```

Output:

```text
<class 'str'>
```

That means all the string-processing techniques from Part 3 can be applied.

---

# 29. Reading Entire Files and Memory

Consider a file that is:

```text
2 KB
```

Reading it all at once is usually trivial.

But what if the file is:

```text
20 GB
```

Using:

```python
file.read()
```

attempts to read the entire content into memory.

That may be inappropriate.

Large files are often better processed incrementally.

---

# 30. Reading Line by Line

A file object is iterable.

You can write:

```python
with open(
    "app.log",
    "r"
) as file:

    for line in file:
        print(
            line
        )
```

This processes one line at a time.

It is useful for:

* Large logs.
* Configuration files.
* Reports.
* Streaming-style processing.

---

# 31. Why Line-by-Line Reading Helps

Instead of:

```text
Load entire 10 GB log
        |
        v
Process it
```

you can:

```text
Read line
   |
   v
Process
   |
   v
Discard/continue
   |
   v
Read next line
```

Memory usage can remain much smaller.

---

# 32. Newline Characters

When reading lines, the string may include:

```text
\n
```

at the end.

Example:

```python
for line in file:
    print(
        repr(line)
    )
```

You might see:

```text
'Application started\n'
```

Remember from Part 3:

```text
\n
```

represents a newline.

---

# 33. Cleaning Lines

You may use:

```python
line = line.strip()
```

Example:

```python
with open(
    "app.log",
    "r"
) as file:

    for line in file:
        line = line.strip()

        print(
            line
        )
```

Be aware that `strip()` removes whitespace from both ends, not only newline characters.

If exact whitespace matters, choose your cleaning method intentionally.

---

# 34. `.readline()`

You may also read one line manually:

```python
with open(
    "app.log",
    "r"
) as file:
    first_line = file.readline()
```

Each subsequent call reads the next line.

Example:

```python
first = file.readline()
second = file.readline()
```

For many tasks, however:

```python
for line in file:
```

is simpler.

---

# 35. `.readlines()`

You may encounter:

```python
lines = file.readlines()
```

This reads lines into a list.

Example result:

```python
[
    "Application started\n",
    "Database connected\n",
    "Server ready\n"
]
```

This can be convenient for smaller files.

But remember:

```text
readlines()
```

can load the whole file's lines into memory.

---

# 36. Choosing a Reading Strategy

Use:

```text
read()
```

when:

* File is reasonably small.
* You need the whole content.

Use:

```text
for line in file
```

when:

* File may be large.
* You can process lines independently.

Use:

```text
readline()
```

when:

* You deliberately need one line at a time under manual control.

Use:

```text
readlines()
```

when:

* You need a list of all lines and the file size is manageable.

# 37. Write Mode: `w`

Example:

```python
with open(
    "report.txt",
    "w"
) as file:
    file.write(
        "Infrastructure report"
    )
```

`w` means:

```text
Open for writing.
```

If the file does not exist, it is normally created.

If it already exists:

```text
its existing content is truncated.
```

This is extremely important.

---

# 38. The Danger of Write Mode

Suppose:

`report.txt` contains:

```text
Critical production investigation notes
```

Then:

```python
with open(
    "report.txt",
    "w"
) as file:
    file.write(
        "New report"
    )
```

The old content is replaced.

Afterward:

```text
New report
```

may be all that remains.

Therefore:

```text
w
```

is potentially destructive.

---

# 39. Always Ask Before Using `w`

Before writing:

```python
open(
    path,
    "w"
)
```

ask:

```text
Does this file already exist?

Is replacing it intentional?

Should I create a backup?

Should I refuse to overwrite?

Should I use append mode instead?

Should I use exclusive creation?
```

Do not use `w` blindly in automation.

---

# 40. Writing Text

Example:

```python
with open(
    "report.txt",
    "w",
    encoding="utf-8"
) as file:

    file.write(
        "Server: web01\n"
    )

    file.write(
        "Status: healthy\n"
    )
```

File:

```text
Server: web01
Status: healthy
```

---

# 41. `.write()` Does Not Automatically Add Newlines

This:

```python
file.write(
    "Server: web01"
)

file.write(
    "Status: healthy"
)
```

may produce:

```text
Server: web01Status: healthy
```

You must add:

```text
\n
```

when needed.

# 42. `.write()` Returns a Value

`write()` returns the number of characters written for text streams.

Example:

```python
count = file.write(
    "healthy"
)
```

`count` would normally be:

```text

```

You will not always need this return value, but understanding it helps when reading documentation.

# 43. Writing Multiple Lines

You can write:

```python
lines = [
    "web01 healthy\n",
    "web02 healthy\n",
    "web03 failed\n"
```

# 44. `writelines()` Does Not Add Newlines Automatically

The strings must already contain newline characters if you want separate lines.

This:

```python
[
    "web01",
    "web02",
    "web03"
]
```

may be written as:

```text
web01web02web03
```

unless you include separators.

---

# 45. Append Mode: `a`

Append mode adds data to the end of a file instead of replacing existing content.

Example:

```python
with open(
    "health.log",
    "a",
    encoding="utf-8"
) as file:

    file.write(
        "web01 healthy\n"
    )
```

If the file already contains data, that data is preserved.

---

# 46. Append Mode for Logs

Suppose:

```text
health.log
```

contains:

```text
08:00 web01 healthy
08:05 web01 healthy
```

Then:

```python
with open(
    "health.log",
    "a",
    encoding="utf-8"
) as file:

    file.write(
        "08:10 web01 failed\n"
    )
```

results in:

```text
08:00 web01 healthy
08:05 web01 healthy
08:10 web01 failed
```

This is why append behavior is useful for simple logs.

Later, Part 18 will show why Python's:

```text
logging
```

module is usually better for real application logging.

---

# 47. Write vs Append

```text
w
|
+--> create if missing
|
+--> replace/truncate content if existing


a
|
+--> create if missing
|
+--> preserve existing content
|
+--> add new content at end
```

Choose deliberately.

---

# 48. Exclusive Creation Mode: `x`

Suppose you want to create a file only if it does not already exist.

Use:

```python
with open(
    "report.txt",
    "x",
    encoding="utf-8"
) as file:

    file.write(
        "New report\n"
    )
```

If:

```text
report.txt
```

already exists, Python raises:

```text
FileExistsError
```

---

# 49. Why `x` Can Be Safer

Compare:

```text
w
=
overwrite existing file
```

with:

```text
x
=
refuse if file already exists
```

For automation that must never overwrite an existing artifact accidentally:

```text
x
```

can be useful.

# 50. Creating Files

Several operations can create files.

For example:

```python
open(
    "report.txt",
    "w"
)
```

can create a missing file.

So can:

```python
open(
    "report.txt",
    "a"
)
```

And:

```python
open(
    "report.txt",
    "x"

```

`pathlib` also provides:


# 51. `Path.touch()`

Example:

```python
from pathlib import Path


path = Path(
    "health.log"
)

path.touch()
```

If the file does not exist, it is created.

If it already exists, its timestamps may be updated depending on the operation and options.

For strict create-only behavior:

```python
path.touch(
    exist_ok=False
)
```

can raise:

```text
FileExistsError
```

if the file already exists.

# 52. What Is File Encoding?

Text is stored as bytes.

An encoding defines how characters map to those bytes.

Examples include:

```text
UTF-8
ASCII
UTF-16
```

Modern text automation commonly uses:

```text
UTF-8
```

---

# 53. Why Encoding Matters

Suppose a file contains:

```text
México
São Paulo
東京
```

Python needs to know how the underlying bytes should be interpreted as characters.

If you use the wrong encoding, you may receive:

```text
UnicodeDecodeError
```

or produce corrupted-looking text.

---

# 54. Specify Encoding Explicitly

For text files, a good practice is often:

```python
with open(
    "report.txt",
    "r",
    encoding="utf-8"
) as file:

    content = file.read()
```

Likewise when writing:

```python
with open(
    "report.txt",
    "w",
    encoding="utf-8"
) as file:

    file.write(
        "Deployment successful\n"
    )
```

This makes your expectation explicit.

---

# 55. Encoding Failure

Suppose Python expects:

```text
UTF-8
```

but the file contains bytes encoded differently.

You may see:

```text
UnicodeDecodeError
```

Do not immediately solve this using:

```text
ignore every invalid character
```

because silently dropping characters can damage data.

First determine the actual encoding.

---

# 56. Binary Files

Text mode is not appropriate for every file.

Images, archives, executables, and many other files contain binary data.

Binary modes include:

```text
rb
wb
ab
```

meaning:

```text
read binary
write binary
append binary
```

Example:

```python
with open(
    "archive.zip",
    "rb"
) as file:

    data = file.read()
```

The result is bytes rather than a text string.

For this part, our main focus remains text automation.

# 57. Introducing `pathlib`

Python's standard library provides:

```python
pathlib
```

for object-oriented filesystem paths.

Import:

```python
from pathlib import Path
```

Then:

```python
path = Path(
    "logs/app.log"
)
```

Instead of treating a path only as a string, you now have a:

```text
Path object
```

with useful filesystem methods.

---

# 58. Why `pathlib` Is Useful

Without `pathlib`, beginners may build paths like:

```python
base = "/home/ann/project"
path = base + "/logs/" + filename
```

This is fragile.

With `pathlib`:

```python
base = Path(
    "/home/ann/project"
)

path = (
    base
    / "logs"
    / filename
)
```

This is easier to read and more portable.

---

# 59. The `/` Operator with `Path`

This may initially look unusual:

```python
path = (
    Path("project")
    / "logs"
    / "app.log"
)
```

`Path` overloads the `/` operator to join path components.

The result conceptually represents:

```text
project/logs/app.log
```

on systems using that path representation.

---

# 64. Multiple Suffixes

For:


# 100. Adding Dry Run

```python
def delete_file(
```


```python
from pathlib import Path


log_dir = Path(

                    f"{line_number}: "
                    f"{line.strip()}"

```

# 124. Per-File Exception Handling

```python
for path in config_dir.glob(
    "*.conf"
):

    if not path.is_file():
        continue

    try:
        content = path.read_text(
            encoding="utf-8"
        )

    except PermissionError as error:
        print(
            f"Permission denied: "
            f"{path}"
        )

        continue

    except UnicodeDecodeError as error:
        print(
            f"Encoding problem: "
            f"{path}"
        )

        continue

    print(
        f"Processed: {path}"
    )
```

This uses the item-level failure strategy from Part 10.

# 125. Track Failed Files

Better than merely printing:

```python
failures = []


for path in config_dir.glob(

            encoding="utf-8"

        PermissionError,
        UnicodeDecodeError

                "path": str(path),

```

# 127. Permissions-Related Failures

Filesystem permissions determine which operations a process is allowed to perform.

A process may need permission to:

```text
Read a file
Write a file
Create a file
Delete a file
Access a directory
Create a directory

```

If permission is denied, Python may raise:


# 128. Linux Permission Basics

A detailed Linux permissions course is outside this Python part, but you need the foundation.

You may see:

```text
-rw-r--r--
```

or:

```text
drwxr-xr-x
```

The first character helps identify the entry type.

For example:

```text
-
```

commonly indicates a regular file.

```text

```

indicates a directory.

The remaining characters represent permission bits.

---

# 129. `r`, `w`, and `x`

At a simplified level:

```text
r = read
w = write
x = execute
```

For directories, the meaning of these permissions affects directory traversal and modification behavior.

# 165. `discovery.py`

```python
from pathlib import Path


def find_files(
    directory: Path,
    pattern: str
) -> list[Path]:
    """Find regular files matching pattern."""

    if not directory.is_dir():
        raise NotADirectoryError(
            f"Directory not found: "
            f"{directory}"
        )

    return [
        path
        for path in directory.rglob(
            pattern
        )
        if path.is_file()
    ]
```


# 167. `operations.py`: Count Errors

```python
from pathlib import Path


def count_errors(
    path: Path
) -> int:
    """Count lines containing ERROR."""

    count = 0

    with path.open(
        "r",
        encoding="utf-8"
    ) as file:

        for line in file:

            if "ERROR" in line:
                count += 1

    return count
```

This processes the file line by line.

# 169. `operations.py`: Safe Archive Copy

```python
from pathlib import Path
import shutil


def archive_file(
    source: Path,
    archive_dir: Path,
    dry_run: bool = True
) -> Path:
    """Copy a file to the archive."""

    if not source.is_file():
        raise FileNotFoundError(
            f"Source file missing: "
            f"{source}"
        )

    archive_dir.mkdir(
        parents=True,
        exist_ok=True
    )

    destination = (
        archive_dir
        / source.name
    )

    if destination.exists():
        raise FileExistsError(
            f"Archive already exists: "
            f"{destination}"
        )

    if dry_run:
        print(
            f"DRY RUN: "
            f"{source} -> "
            f"{destination}"
        )

        return destination

    shutil.copy2(
        source,
        destination
    )

    if not destination.is_file():
        raise RuntimeError(
            f"Archive verification "
            f"failed: {destination}"
        )

    return destination
```

For this beginner project, copying is safer.

If you immediately move the only source file and something goes wrong elsewhere, recovery may be harder.

A production workflow might:

```text
Copy
  |
  v

  |
  v
Only then remove source
```

depending on requirements.

# 175. Main Processing Function

```python
def main(
    dry_run: bool = True
) -> int:

    files = find_files(
        INCOMING_DIR,
        "*.log"
    )

    results = []

    failures = 0

    for path in files:

        try:
            error_count = (
                count_errors(
                    path
                )
            )

            archive_file(
                path,
                ARCHIVE_DIR,
                dry_run=dry_run
            )

        except (
            PermissionError,
            UnicodeDecodeError,
            FileExistsError,
            FileNotFoundError,
            OSError
        ) as error:

            failures += 1

            results.append(
                {
                    "file": str(path),
                    "status": (
                        f"FAILED: {error}"
                    ),
                    "errors": 0
                }
            )

            continue

        results.append(
            {
                "file": str(path),
                "status": (
                    "DRY RUN"
                    if dry_run
                    else "SUCCESS"
                ),
                "errors": error_count
            }
        )

    write_report(
        results,
        REPORT_PATH
    )

    if failures:
        return 1

    return 0
```

# 192. Atomic Replacement Concept

Suppose you need to update an important configuration file.

Dangerous pattern:

```text
Open original with w
      |
      v
Original immediately truncated
      |
      v
Write new data
      |
      +--> process crashes halfway
```

You may leave a partially written configuration.

A safer strategy can be:

```text
Write new temporary file
        |
        v
Validate new file
        |
        v
Replace original
```

This reduces the window in which the important file contains partial output.

Exact atomicity guarantees depend on filesystem and operation.

```text

```

directly.

The script truncates it.

Then the machine loses power.

Now your configuration may be empty or incomplete.

Production configuration automation needs more care than:

```python
open(
    "nginx.conf",
    "w"
)
```

```text

   |
   v

   |
   v

   |
   v
Write new content
   |
   v
Validate new content
   |
   v
Apply/reload
   |
   v
Verify service
```

This does not solve every failure scenario, but it is much safer than blind overwriting.

```text
Copy/move/write/delete


Verification
   |
   v
Did intended state occur?


Reporting
   |
   v
What succeeded or failed?
```

This separation makes automation easier to reason about.

# 198. Do Not Mix Everything Into One Loop

A beginner might write:

```python
for path in directory.rglob("*"):
    # read
    # rename
    # copy
    # delete
    # report
    # catch everything
```

This becomes difficult to test.

Prefer functions such as:

```text
discover_files()
validate_file()
process_file()
archive_file()
verify_archive()
write_report()
```

This uses the reusable-function design from Part 7.

# 199. Designing a File Operation Function

A good function should answer:

```text
What operation does it perform?

What input does it require?

What does it return?

What exceptions can occur?

Does it modify the filesystem?

Can it overwrite?

Can it delete?

Does it support dry run?

How is success verified?
```

Filesystem functions should make side effects obvious.

# 200. Naming Side-Effect Functions Clearly

Existing file content disappears.

truncated the file.

# 241. Troubleshooting: File Not Found

## Problem

```text
FileNotFoundError
```

## What you see

Python says the target path cannot be found.

## Possible causes

* Typo.
* Wrong current working directory.
* Wrong relative path.
* File not deployed.
* Case mismatch.
* File moved.
* File deleted.
* Wrong environment configuration.

## Investigate

```python
print(
    Path.cwd()
)

print(
    path.resolve()
)

print(
    path.exists()
)
```

## Fix

Correct the actual path or deployment/configuration.

## Verify

Confirm:

```python
path.is_file()
```

when a file is required.

---

# 242. Troubleshooting: Directory Not Found

## Problem

Automation cannot find its input directory.

## Investigate

```python
print(
    directory.resolve()
)

print(
    directory.exists()
)

print(
    directory.is_dir()
)
```

## Possible causes

* Wrong CWD.
* Typo.
* Missing deployment directory.
* Wrong environment configuration.

## Fix

Correct the path or create the directory only if your application is supposed to create it.

Do not create missing input directories blindly.

---

# 243. Troubleshooting: Permission Denied

## Problem

```text
PermissionError
```

## Possible causes

* Wrong owner.
* Insufficient file permission.
* Insufficient directory permission.
* Process running as unexpected user.
* Read-only filesystem.
* Security controls outside ordinary permission bits.

## Investigate

On Linux:

```bash
whoami
```

and:

```bash
ls -l path
```

For directories:

```bash
ls -ld directory
```

## Fix

Grant only the required access.

## Verify

Run the operation again under the intended identity.

---

# 244. Troubleshooting: UnicodeDecodeError

## Problem

Python cannot decode the file as expected.

## Possible cause

Wrong encoding assumption.

## Investigate

Determine how the file was produced and its actual encoding.

## Fix

Use the correct encoding.

Do not immediately use:

```text
errors="ignore"
```

because silently dropping data may hide corruption.

---

# 245. Troubleshooting: Destination Already Exists

## Problem

```text
FileExistsError
```

## Possible causes

* Previous run already created it.
* Archive naming strategy is not unique.
* Job restarted.
* Two processes are handling the same file.

## Investigate

Check:

```python
destination.exists()
```

Then determine whether the existing file is:

* The same artifact.
* An older artifact.
* A partial copy.
* A collision.

Do not automatically overwrite it.

---

# 246. Troubleshooting: Directory Is Not Empty

## Problem

Trying to remove a directory with:

```python
rmdir()
```

fails.

## Why

The directory contains entries.

## Safe response

Inspect the directory.

Do not immediately replace:

```python
rmdir()
```

with recursive deletion.

The failure may be protecting important data.
