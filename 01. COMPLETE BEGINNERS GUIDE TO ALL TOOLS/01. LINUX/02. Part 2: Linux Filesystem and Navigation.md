# Part 2: Linux Filesystem and Navigation

In Part 1, you learned what Linux is, what the kernel does, how the terminal and shell work, how Linux commands are structured, and how to run your first commands.

Now you need to understand where things live.

Linux organizes almost everything through a filesystem.

Configuration files, application files, user data, logs, devices, running-process information, and many other resources appear somewhere inside the Linux directory tree.

If you do not understand Linux paths and navigation, many later tasks become confusing.

For example, an engineer may tell you:

```text
The Nginx configuration is under /etc/nginx.
```

Or:

```text
Check the logs in /var/log.
```

Or:

```text
Go back to your home directory.
```

To follow those instructions confidently, you need to understand:

* What a filesystem is
* How the Linux directory tree works
* What `/` means
* Where important Linux directories are located
* Absolute and relative paths
* Your home directory
* Your current working directory
* How `pwd`, `cd`, and `ls` work
* What `.` and `..` mean
* How hidden files work
* How to troubleshoot path problems

By the end of this part, you should be able to move confidently around a Linux filesystem and understand where you are at any point.

---

# 1. What Is a Filesystem?

A filesystem is the structure an operating system uses to organize, store, locate, and manage data.

Without a filesystem, data on a disk would simply exist as blocks of information without a convenient human-readable organization.

A filesystem allows Linux to represent information using:

* Files
* Directories
* Names
* Paths
* Metadata
* Permissions
* Ownership

A simple filesystem might look like this:

```text
/
|
+-- home
|   |
|   +-- ann
|       |
|       +-- notes.txt
|       +-- projects
|
+-- etc
|
+-- var
    |
    +-- log
```

The structure resembles an upside-down tree.

At the top is:

```text
/
```

This is called the root directory.

Everything else exists somewhere underneath it.

---

# 2. Filesystem vs Physical Disk

A filesystem and a physical disk are related, but they are not the same thing.

A disk is storage hardware.

Examples include:

* SSD
* HDD
* Virtual cloud disk

A filesystem is the organizational structure placed on storage.

You can think of it approximately like this:

```text
Physical or virtual storage
          |
          v
      Filesystem
          |
          v
Files and directories
```

Later in this Linux series, you will learn about:

* Disks
* Partitions
* Filesystems
* Mounting
* Mount points

For now, focus on how Linux presents files and directories to you.

---

# 3. Files and Directories

Two fundamental filesystem objects are:

* Files
* Directories

## What Is a File?

A file stores information.

Examples include:

```text
report.txt
application.log
nginx.conf
backup.tar.gz
deploy.sh
```

Files may contain:

* Text
* Program code
* Configuration
* Logs
* Images
* Executable programs
* Compressed data

Linux does not require every file to have a familiar extension such as `.txt`.

You may encounter files such as:

```text
hosts
passwd
fstab
```

These are still files.

## What Is a Directory?

A directory organizes files and other directories.

Windows users often call directories folders.

For example:

```text
projects/
```

could contain:

```text
projects/
|
+-- website/
+-- scripts/
+-- documentation/
```

Directories can contain other directories, producing the Linux directory tree.

---

# 4. Understanding the Linux Directory Tree

Windows users may be familiar with paths such as:

```text
C:\Users\Ann\Documents
```

Linux does not normally organize its main directory tree around drive letters such as:

```text
C:
D:
E:
```

Instead, Linux presents one unified directory hierarchy beginning at:

```text
/
```

A simplified Linux directory tree looks like:

```text
/
|
+-- home
+-- root
+-- etc
+-- var
|   |
|   +-- log
|
+-- tmp
+-- usr
+-- bin
+-- sbin
+-- opt
+-- mnt
+-- media
+-- dev
+-- proc
+-- sys
```

Do not try to memorize this immediately.

You will encounter these directories repeatedly.

---

# 5. Why Everything Begins at `/`

The forward slash:

```text
/
```

has a special meaning when it appears by itself.

It represents the root directory.

The root directory is the top of the Linux filesystem hierarchy.

Every absolute filesystem path starts from `/`.

For example:

```text
/home/ann
```

means:

```text
/
|
+-- home
    |
    +-- ann
```

And:

```text
/var/log
```

means:

```text
/
|
+-- var
    |
    +-- log
```

A path such as:

```text
/etc/nginx/nginx.conf
```

can be read as:

1. Start at `/`.
2. Enter `etc`.
3. Enter `nginx`.
4. Find `nginx.conf`.

This way of reading paths will become very important.

# 6. Root Directory vs Root User

Beginners frequently confuse two Linux concepts that use the word root.

They are not the same thing.

## Root Directory

The root directory is:

```text
/
```

It is the top of the filesystem.

## Root User

The root user is:

```text
root
```

It is the powerful administrative account you learned about in Part 1.

## Root User's Home Directory

The root user's home directory is usually:

```text
/root
```

So these three things are different:

```text
/       Root directory

root    Administrative user

/root   Root user's home directory
```

Remember this distinction.

# 7. Filesystem Hierarchy Standard

Linux systems generally follow conventions describing where different types of files should be stored.

One important specification is the Filesystem Hierarchy Standard, commonly shortened to:

```text
FHS
```

The FHS helps define the purposes of major directories.

For example:

```text
/etc
```

is generally associated with system configuration.

```text
/var
```

contains variable data.

```text
/home
```

contains regular users' home directories.

The exact contents can differ between Linux distributions.

Modern Linux distributions may also use symbolic links or slightly different layouts.

The important beginner lesson is that Linux directories are not randomly organized.

Major directories have expected purposes.

# 10. `/root`

`/root` is normally the home directory of the root user.

It is not the same as:

```text
/
```

Compare:

```text
/        filesystem root

/root    root user's home directory
```

A regular user may not have permission to inspect everything inside `/root`.

For example:

```bash
ls /root
```

may return:

```text
Permission denied
```

That is not necessarily a problem.

# 11. `/etc`

`/etc` contains system-wide configuration.

You will encounter this directory constantly in Linux administration.

Applications and services often store configuration here.

Examples may include:

```text
/etc/hosts
/etc/passwd
/etc/group
/etc/fstab
/etc/ssh/
/etc/nginx/
```

A simplified example:

```text
/etc
|
+-- ssh
|   |
|   +-- sshd_config
|
+-- nginx
|   |
|   +-- nginx.conf
|
+-- hosts
+-- passwd
+-- group
```

When someone says:

```text
Check the service configuration.
```

there is a good chance you will eventually look somewhere under `/etc`.

Do not modify unfamiliar files in `/etc` simply to experiment.

Incorrect system configuration can break services or system behavior.

# 12. `/var`

`/var` contains variable data.

Variable data means information expected to change while the system operates.

Examples include:

* Logs
* Caches
* Application state
* Queues
* Spool data

You may see directories such as:

```text
/var/log
/var/cache
/var/lib
/var/tmp
```

For DevOps and troubleshooting, `/var` is extremely important.

# 13. `/var/log`

`/var/log` is a common location for logs.

A log records events that occur on a system or inside an application.

Examples include:

* Service startup
* Service failures
* Authentication attempts
* Application errors
* System events

You may inspect the directory with:

```bash
ls /var/log
```

The contents depend on your Linux distribution and installed software.

You might see entries related to:

* Package management
* Authentication
* Web servers
* System services

Later, you will learn how to inspect logs using tools such as:

```text
tail
grep
less
journalctl
```

For now, remember:

```text
/var/log
```

is one of the first places Linux administrators think about when troubleshooting.

---

# 14. `/tmp`

`/tmp` is used for temporary files.

Applications and users can place temporary data here.

Example:

```text
/tmp
```

Temporary data should not be treated as permanent storage.

Depending on the system configuration, files in `/tmp` may be removed automatically.

Do not store important permanent data there.

# 15. `/usr`

`/usr` contains a large amount of user-space software and related resources.

You may see directories such as:

```text
/usr/bin
/usr/sbin
/usr/lib
/usr/share
/usr/local
```

A simplified structure:

```text
/usr
|
+-- bin
+-- sbin
+-- lib
+-- share
+-- local
```

Many commands and applications installed on Linux live somewhere under `/usr`.

Despite the name, `/usr` is not normally where individual users store their personal files.

Personal user data usually belongs under:

```text
/home
```

# 16. `/bin`

Historically:

```text
/bin
```

contained essential user commands required for basic system operation.

Examples traditionally include commands such as:

```text
ls
cp
mv
cat
```

On many modern Linux systems, `/bin` is actually a symbolic link to:

```text
/usr/bin
```

You can sometimes observe this with:

```bash

```

You may see something similar to:

```text
/bin -> usr/bin
```

Do not worry about symbolic links yet.

You will learn them properly in Part 3.

For now, understand that `/bin` is associated with important command-line programs.

---

# 17. `/sbin`

Historically:

```text
/sbin
```

contained important system-administration programs.

On many modern distributions, it may point to:

```text
/usr/sbin
```

Tools here are often associated with system management rather than ordinary user tasks.

Again, exact filesystem layouts vary between distributions.

# 18. `/opt`

`/opt` is commonly used for optional or third-party software.

An application installed separately from the distribution's normal package structure might be placed under:

```text
/opt/application-name
```

For example:

```text
/opt/company-app
```

Do not assume every third-party program uses `/opt`, but you will encounter it often enough that you should recognize its purpose.

# 19. `/mnt`

`/mnt` is traditionally used as a location for manually mounted filesystems.

For example, an administrator might mount additional storage at:

```text
/mnt/data
```

You will learn what mounting means in detail in Part 14.

For now, think of mounting as making another filesystem accessible at a directory within the Linux directory tree.

Example:

```text
Additional disk
      |
      v
/mnt/data
```

---

# 20. `/media`

`/media` is commonly associated with removable media.

Examples include:

* USB drives
* External disks
* Other removable storage

Desktop Linux environments may automatically create mount locations underneath `/media`.

For example:

```text
/media/ann/USB_DRIVE
```

Exact behavior depends on the distribution and desktop environment.

---

# 21. `/dev`

`/dev` contains device representations.

Linux follows an important Unix-like concept where many resources can be accessed through file-like interfaces.

Examples under `/dev` may represent:

* Disks
* Terminals
* Special devices

You may encounter names such as:

```text
/dev/sda
/dev/nvme0n1
/dev/null
```

These are not ordinary text files.

They represent devices or special kernel interfaces.

For example:

```text
/dev/null
```

is a special device that discards data written to it.

You will use `/dev/null` later when learning redirection.

Do not randomly modify resources inside `/dev`.

---

# 22. `/proc`

`/proc` is unusual.

It does not behave like an ordinary directory stored permanently on disk.

It is a virtual filesystem that exposes information from the kernel, especially information about:

* Processes
* CPU
* Memory
* Kernel state
* Runtime system information

For example:

```text
/proc/cpuinfo
```

contains CPU-related information.

You can inspect it with:

```bash
cat /proc/cpuinfo
```

Another example:

```text
/proc/meminfo
```

contains memory-related information.

```bash
cat /proc/meminfo
```

You do not need to understand the output yet.

The important idea is:

```text
/proc
```

provides a window into information maintained by the running kernel.

---

# 23. `/sys`

`/sys` is another virtual filesystem.

It exposes information about:

* Devices
* Drivers
* Kernel objects
* Hardware relationships

You will rarely need to manipulate `/sys` as a complete beginner.

However, you should recognize it when you see it.

A simplified view is:

```text
Kernel
 |
 +-- /proc
 |
 +-- /sys
```

Both expose runtime information, but they serve different purposes.

# 28. What Is the Working Directory?

# 39. Absolute Paths

An absolute path describes a location beginning from the root directory.

Absolute paths begin with:

```text
/
```

Examples:

```text
/home/ann
```

```text
/etc/ssh
```

```text
/var/log
```

```text
/usr/bin
```

```text

```

```bash

```

# 40. Relative Paths

A relative path describes a location relative to your current working directory.

Suppose your current location is:

```text
/home/ann
```

and the directory tree is:

```text
/home/ann
|
+-- projects
|   |
|   +-- linux
|
+-- documents
```

Instead of:

```bash
cd /home/ann/projects
```

you can run:

```bash
cd projects
```

Because Linux interprets `projects` relative to:

```text
/home/ann
```

Similarly:

```bash
cd projects/linux
```

takes you to:

```text
/home/ann/projects/linux
```

---

# 41. Absolute vs Relative Paths

Suppose:

```bash
pwd
```

returns:

```text
/home/ann
```

You want to reach:

```text
/home/ann/projects/linux
```

## Absolute Method

```bash
cd /home/ann/projects/linux
```

This begins at `/`.

## Relative Method

```bash
cd projects/linux
```

This begins from your current directory.

Both can reach the same destination.

The difference is the starting point.

```text
Absolute path
Start at /
     |
     v
/home/ann/projects/linux
```

```text
Relative path
Start at current directory
     |
     v
projects/linux
```

Absolute.


* Owner

* Size

# 49. What Makes a File Hidden in Linux?

Linux uses a simple convention.

A filename beginning with a dot is treated as hidden by many tools.

Examples:

```text
.bashrc
.profile
.gitconfig
.ssh
```

Hidden files are often used for:

* User configuration
* Application settings
* Shell settings
* Credentials-related directories

Hidden does not mean encrypted.

Hidden does not mean secure.

It mainly means the file is omitted from normal directory listings unless you request hidden entries.

```text

```


# 56. Understanding `No such file or directory`

One of the most common Linux errors is:

```text
No such file or directory
```

Example:

```bash
cd /home/ann/project
```

Linux might respond:

```text
bash: cd: /home/ann/project: No such file or directory
```

This means Linux could not resolve the path you provided as written.

Do not immediately assume Linux is malfunctioning.

Several simple causes are possible.

---

# 57. Cause 1: The Directory Does Not Exist

You type:

```bash
cd /home/ann/project
```

but the real directory is:

```text
/home/ann/projects
```

Notice:

```text
project
```

vs:

```text
projects
```

Check the parent:

```bash
ls /home/ann
```

Then use the correct name.

---

# 58. Cause 2: Wrong Capitalization

Suppose the directory is:

```text
Projects
```

You type:

```bash
cd projects
```

Linux may return:

```text
No such file or directory
```

Remember:

```text
Projects
```

and:

```text
projects
```

are different names.

Linux is case-sensitive.

---

# 59. Cause 3: Wrong Working Directory

Suppose your filesystem contains:

```text
/home/ann/projects
```

You assume you are in:

```text
/home/ann
```

and run:

```bash
cd projects
```

But your actual location is:

```text
/var/log
```

Linux interprets the relative path as:

```text
/var/log/projects
```

If that directory does not exist, you receive an error.

Check:

```bash
pwd
```

Then either navigate correctly or use the absolute path:

```bash
cd /home/ann/projects
```

This is one of the most important beginner troubleshooting lessons.

Relative paths depend on your current working directory.

---

# 60. Cause 4: Typing Error

You intend:

```bash
cd /var/log
```

but type:

```bash
cd /var/lgo
```

Linux does exactly what you requested.

It tries to locate:

```text
/var/lgo
```

If that path does not exist, the command fails.

Use Tab completion to reduce typing mistakes.

---

# 61. Cause 5: Spaces in a Path

Suppose a directory is named:

```text
Linux Projects
```

If you type:

```bash
cd Linux Projects
```

the shell sees two separate arguments:

```text
Linux
Projects
```

You can quote the path:

```bash
cd "Linux Projects"
```

Or escape the space:

```bash
cd Linux\ Projects
```

For beginners, quoting is often easier to read.

You will study shell quoting more deeply later.

```bash
pwd
cd /
cd ..
cd ~
cd -
ls
ls -l
ls -a
ls -la
ls -lh
ls -lah
```

Do not focus only on remembering the commands.

The more important skill is understanding what Linux is doing with the path you provide.

When you type:

```bash
cd /var/log
```

you should mentally see:

```text
/
|
+-- var
    |
    +-- log
```

When you type:

```bash
cd ..
```

you should understand that Linux is moving your shell's working directory to the parent.

When you type:

```bash
cd projects
```

you should immediately recognize that `projects` is being interpreted relative to your current location.

That mental model is the real objective of Part 2.
