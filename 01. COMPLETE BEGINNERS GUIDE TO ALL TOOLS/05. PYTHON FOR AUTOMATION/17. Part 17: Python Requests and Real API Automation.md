# 2. Why Use the `requests` Library?

Python includes lower-level networking and HTTP tools in its standard library.

But the third-party `requests` package provides a very readable interface for common HTTP operations.

For example:

```python
requests.get(url)
```

is much easier for beginners than manually building an HTTP client with lower-level modules.

`requests` is widely used for:

* REST APIs
* Internal services
* Cloud APIs
* Monitoring APIs
* Git hosting APIs
* CI/CD platforms
* Ticketing systems
* Security tooling
* Automation scripts

# 24. Safe JSON Parsing

A beginner-friendly pattern:

```python
import requests


response = requests.get(
    url,
    timeout=10
)

response.raise_for_status()


try:
    data = response.json()

except ValueError as error:
    raise RuntimeError(
        "Response body was not "
        "valid JSON"
    ) from error
```

The exact JSON-related exception hierarchy depends on the library/runtime, so handling `ValueError` is a practical general approach for this level.

# 75. A Reusable GET Function

```python
import requests


def get_json(
    url: str,
    *,
    headers: dict | None = None,
    params: dict | None = None,
    timeout: int = 10
):
    try:
        response = requests.get(
            url,
            headers=headers,
            params=params,
            timeout=timeout
        )

        response.raise_for_status()

    except requests.exceptions.Timeout as error:
        raise RuntimeError(
            f"GET timed out: {url}"
        ) from error

    except requests.exceptions.ConnectionError as error:
        raise RuntimeError(
            f"Connection failed: "
            f"{url}"
        ) from error

    except requests.exceptions.HTTPError as error:
        raise RuntimeError(
            f"GET returned HTTP "
            f"{response.status_code}"
        ) from error

    try:
        return response.json()

    except ValueError as error:
        raise RuntimeError(
            "Response was not "
            "valid JSON"
        ) from error
```

---

# 76. Be Careful Referencing `response`

In exception code, ensure:

```python
response
```

actually exists before using it.

This is why exception handling should respect the failure layer.

# 77. A Cleaner HTTP Error Pattern

Inside the HTTP error block:

```python
except requests.exceptions.HTTPError as error:

    status = (
        error.response.status_code
        if error.response is not None
        else "UNKNOWN"
    )

    raise RuntimeError(
        f"GET failed with "
        f"HTTP {status}"
    ) from error
```

This avoids assuming a response variable exists.

# 92. Pagination with `requests`

Imagine:


---

# 93. Page-Based Pagination Function

```python
def get_all_servers(
    session,
    url: str
) -> list[dict]:

    all_items = []

    page = 1

    while True:

        response = session.get(
            url,
            params={
                "page": page,
                "limit": 100
            },
            timeout=10
        )

        response.raise_for_status()

        data = response.json()

        items = data.get(
            "items",
            []
        )

        if not isinstance(
            items,
            list
        ):
            raise ValueError(
                "items must be "
                "a list"
            )

        all_items.extend(
            items
        )

        total_pages = data.get(
            "total_pages"
        )

        if not isinstance(
            total_pages,
            int
        ):
            raise ValueError(
                "total_pages must "
                "be an integer"
            )

        if page >= total_pages:
            break

        page += 1

    return all_items
```

---

# 94. Why Validate Pagination Fields?

Do not assume:

```python
data["items"]
```

is always a list.

Do not assume:

```python
data["total_pages"]
```

is always an integer.

External API data must be validated.

```python
def get_all_items(
    session,
    url: str
) -> list[dict]:

    all_items = []

    cursor = None

    while True:

        params = {}

        if cursor is not None:
            params[
                "cursor"
            ] = cursor

        response = session.get(
            url,
            params=params,
            timeout=10
        )

        response.raise_for_status()

        data = response.json()

        items = data.get(
            "items",
            []
        )

        if not isinstance(
            items,
            list

                "a list"

        all_items.extend(
            items

        cursor = data.get(
            "next_cursor"
```

# 103. Manual Retry Loop

A simple educational pattern:

```python
import time

import requests


def get_with_retry(
    url: str,
    attempts: int = 3
):
    delay = 1

    for attempt in range(
        1,
        attempts + 1
    ):

        try:
            response = requests.get(
                url,
                timeout=10
            )

            if (
                response.status_code
                not in {
                    429,
                    500,
                    502,
                    503,
                    504
                }
            ):
                response.raise_for_status()

                return response

        except requests.exceptions.Timeout:

            if attempt == attempts:
                raise

        except requests.exceptions.ConnectionError:

            if attempt == attempts:
                raise

        if attempt < attempts:

            time.sleep(
                delay
            )

            delay *= 2

    raise RuntimeError(
        "Request failed after retries"
    )
```

---

# 104. Why This Retry Example Is Limited

It is intentionally educational.

Real production retry behavior should consider:

* `Retry-After`
* Jitter
* Idempotency
* Request method
* Server guidance
* Connection failures
* Retry budgets
* Overall deadline

Do not blindly copy one retry function everywhere.

# 171. Redirects and Credentials

HTTP redirects can complicate authentication and host trust.

For sensitive integrations, understand:

* Whether hostname changes
* Whether credentials are preserved or stripped
* Whether the redirected host is trusted

Do not casually accept arbitrary redirects for privileged clients.

```python
def check_api_health(
```

# 214. Common Beginner Mistake: Infinite Retry

without limits.

* Backoff
* Retry classification
* Overall deadline

# 215. Common Beginner Mistake: Retrying POST Blindly

# 216. Common Beginner Mistake: Ignoring Pagination

# 217. Common Beginner Mistake: No Pagination Guardrail

Track cursors or maximum pages.

# 218. Common Beginner Mistake: Giant API Function

```text
 +--> retries
 +--> parses JSON
```

# 219. Common Beginner Mistake: Mixing HTTP and Business Logic

The HTTP client should not decide:

```text

```

That belongs in application logic.

# 220. Common Beginner Mistake: Treating `response.ok` as Complete Truth

An HTTP response may be technically successful while application data indicates failure.

Always inspect the contract.

Use:

```text
1. Configuration
   |
   +--> base URL
   +--> token present
   +--> environment

2. DNS / network
   |
   +--> connection possible?

3. TLS
   |
   +--> certificate trusted?
   +--> hostname valid?

4. HTTP
   |
   +--> method?
   +--> path?
   +--> status?

5. Authentication
   |
   +--> token valid?

6. Authorization
   |
   +--> permissions sufficient?

7. Request validation
   |
   +--> params?
   +--> JSON?
   +--> headers?

8. Response parsing
   |
   +--> valid JSON?
   +--> expected shape?

9. Business logic
   |
   +--> actual resource state?

10. Retry / pagination
    |
    +--> rate limit?
    +--> more pages?
    +--> safe to retry?
```
