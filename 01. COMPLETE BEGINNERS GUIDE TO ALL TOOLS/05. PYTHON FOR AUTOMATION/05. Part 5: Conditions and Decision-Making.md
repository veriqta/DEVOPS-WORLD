# Part 5: Conditions and Decision-Making

Automation becomes useful when a script can examine what is happening and decide what to do next.

A script that can only store and print information is limited.

A real infrastructure automation script needs to answer questions such as:

* Is disk usage above 80%?
* Is this server reachable?
* Is this the production environment?
* Did the API return an error?
* Does this configuration file exist?
* Is this service in the critical-services list?
* Should the script continue?
* Should it display a warning?
* Should it stop before making a dangerous change?

Python makes these decisions using conditions.

The basic pattern is:

```text
Observe a value
      |
      v
Evaluate a condition
      |
      v
True or False
      |
   +--+--+
   |     |
 True   False
   |     |
   v     v
Action  Different action
```

This is one of the foundations of automation.

---

# 1. What Is a Condition?

A condition is an expression that Python evaluates as either:

```python
True
```

or:

```python
False
```

For example:

```python
disk_usage = 92

print(disk_usage > 80)
```

Output:

```text
True
```

Python evaluates:

```python
disk_usage > 80
```

as a question:

```text
Is disk_usage greater than 80?
```

Since:

```text
92 > 80
```

the result is:

```python
True
```

This Boolean result can then control what the script does.

```python
False
```

# 13. Understanding the Structure of `if`

Look carefully:

```python
if disk_usage > 80:
    print("Warning: disk usage is high")
```

There are several important pieces.

```text
if
```

starts the conditional statement.

```text
disk_usage > 80
```

is the condition.

```text
:
```

ends the condition line.

The indented code:

```python
print("Warning: disk usage is high")
```

belongs to the `if` block.

---

# 14. Indentation Controls the Block

Python uses indentation to determine which statements belong to a condition.

Correct:

```python
disk_usage = 92

if disk_usage > 80:
    print("Disk usage is high")
    print("Investigate the filesystem")
```

Both `print()` statements belong to the `if`.

If the condition is false, neither runs.

---

# 15. Code Outside the `if`


```text

```

The warning does not run.

Why?

```text

```

is false.

But:

```python
print("Disk check complete")
```

is not indented, so it is outside the conditional block.

# 19. The `elif` Statement

Real decisions often have more than two possibilities.

Suppose:

```text
Disk < 70%
Healthy

Disk 70–89%
Warning

Disk >= 90%
Critical
```

You can use:

```python
if
elif
else
```

Example:

```python
disk_usage = 82

if disk_usage >= 90:
    print("CRITICAL: disk usage is extremely high")
elif disk_usage >= 70:
    print("WARNING: disk usage is high")
else:
    print("OK: disk usage is normal")
```

Output:

```text
WARNING: disk usage is high
```

---

# 20. How `elif` Works

Python checks conditions from top to bottom.

For:

```python
disk_usage = 95

if disk_usage >= 90:
    print("CRITICAL")
elif disk_usage >= 70:
    print("WARNING")
else:
    print("OK")
```

Python evaluates:

```text
95 >= 90?
```

Yes.

Therefore:

```text
CRITICAL
```

runs.

Python does not continue to the `elif`.

---

# 21. Order Matters

Consider this incorrect logic:

```python
disk_usage = 95

if disk_usage >= 70:
    print("WARNING")
elif disk_usage >= 90:
    print("CRITICAL")
```

Output:

```text
WARNING
```

That is logically wrong.

`95 >= 70` is already true, so Python stops there.

The critical condition is never reached.

Better:

```python
if disk_usage >= 90:
    print("CRITICAL")
elif disk_usage >= 70:
    print("WARNING")
else:
    print("OK")
```

When ranges overlap, test the more restrictive condition first.

---

# 22. Multiple `elif` Branches

```python
    print("Critical")

    print("Warning")
elif cpu_usage >= 50:
    print("Moderate")
else:
    print("Normal")
```

Output:

```text

```

# 29. Dangerous Type Comparison Mistake

This fails:

```python
disk_usage = "90"

if disk_usage > 80:
    print("High disk usage")
```

Python cannot directly compare a string and integer using `>`.

You will receive a `TypeError`.

Fix:

```python
disk_usage = int(disk_usage)

if disk_usage > 80:
    print("High disk usage")
```

Always understand the type of values entering your script.

# 30. Logical Operators

Sometimes one condition is not enough.

Python provides:


# 31. The `and` Operator

`and` requires both conditions to be true.

Example:

```python
environment = "production"
disk_usage = 92

if environment == "production" and disk_usage > 90:
    print("Critical production disk alert")
```

Both conditions are true.

Therefore the message is printed.

---

# 32. Understanding `and`

For:

```text
Condition A and Condition B
```

the result is true only when both are true.

```text
A       B       A and B
------------------------
True    True    True
True    False   False
False   True    False
False   False   False
```

Think:

```text
Is this production?
       AND
Is disk usage critical?
       |
       v
Both must be true
```

---

# 33. Practical `and` Example

Suppose you should restart a service only when:

1. The service is stopped.
2. Automatic recovery is enabled.

```python
service_status = "stopped"
auto_recovery = True

if service_status == "stopped" and auto_recovery:
    print("Automatic recovery can begin")
```

This prevents the script from acting based on only one requirement.

# 34. The `or` Operator

`or` requires at least one condition to be true.


Output:

```text

```

CPU is above the threshold.

Memory does not need to be.

# 35. Understanding `or`

# 56. Nested Conditions

A condition can contain another condition.

Example:

```python

```

---

# 57. Understanding Nested Flow

Conceptually:

```text

        |
    +---+---+
    |       |
   Yes      No
    |
    v

    |
 +--+--+
 |     |
Yes    No
 |

```

# 58. Nested `if` vs `and`

These can sometimes represent the same requirement.

Nested:

```python
if environment == "production":
    if disk_usage > 90:
        print("Critical production disk alert")
```

Combined:

```python
if environment == "production" and disk_usage > 90:
    print("Critical production disk alert")
```

The second version is often simpler.

Nested conditions are useful when the second decision only makes sense after the first one.

---

# 59. Avoid Excessive Nesting

Code like this becomes difficult to follow:

```python
if environment == "production":
    if server_reachable:
        if disk_usage > 90:
            if not maintenance_mode:
                print("Alert")
```

It may be valid, but deep nesting increases complexity.

Often:

```python
if (
    environment == "production"
    and server_reachable
    and disk_usage > 90
    and not maintenance_mode
):
    print("Alert")
```

is easier to understand.

Use whichever structure communicates the decision most clearly.

A threshold is a boundary that determines when some action should occur.

Examples:

```text

Failed requests >= 10
Queue depth > 5000
```

Python conditions can evaluate these values.

# 63. Disk Usage Automation

Suppose your script obtains:

```python
disk_usage = 91
```

You want:

```text
0–69       OK
70–84      WARNING
85–94      HIGH
95–100     CRITICAL
```

You can write:

```python
disk_usage = 91

if disk_usage >= 95:
    print("CRITICAL: disk almost full")
elif disk_usage >= 85:
    print("HIGH: disk usage requires attention")
elif disk_usage >= 70:
    print("WARNING: disk usage increasing")
else:
    print("OK: disk usage normal")
```

Output:

```text
HIGH: disk usage requires attention
```

---

# 64. Why Threshold Order Matters

Do not write:

```python
if disk_usage >= 70:
    print("WARNING")
elif disk_usage >= 95:
    print("CRITICAL")
```

If:

```python
disk_usage = 98
```

Python sees:

```text
98 >= 70
```

first.

That is true.

It prints:

```text
WARNING
```

and stops checking.

Always design overlapping thresholds carefully.

---

# 65. Validate Threshold Data

Suppose:

```python
disk_usage = 140
```

Disk usage percentage should normally be between:

```text
0 and 100
```

Before evaluating severity, you might validate:

```python
if disk_usage < 0 or disk_usage > 100:
    print("Invalid disk usage value")
elif disk_usage >= 95:
    print("CRITICAL")
elif disk_usage >= 85:
    print("HIGH")
else:
    print("OK")
```

Automation should not blindly trust data.

# 66. Checking Whether Disk Usage Is Too High

```python
disk_usage = 88

```

Using a variable for the threshold is better than repeating a magic number throughout a script.

# 70. Important: What Does "Reachable" Mean?

Do not assume that one successful check means the entire server is healthy.

A server could:

* Respond to ICMP ping
* But have nginx stopped
* Have port 443 blocked
* Have the application crashed
* Have DNS problems
* Have a database dependency failure

So:

```text
Reachable
```

does not necessarily mean:

```text
Healthy
```

Later we will perform actual network and service checks.

# 113. Common Mistake: Confusing `None` with Zero


# 129. What You Should Now Understand

You should now understand:

* Conditions allow scripts to make decisions.
* Conditions ultimately evaluate truth.
* `True` and `False` are Boolean values.
* Comparison operators produce Boolean results.
* `==` checks equality.
* `!=` checks inequality.
* `>` and `<` compare relative size.
* `>=` and `<=` include the boundary value.
* `=` assigns while `==` compares.
* `if` executes code when a condition is true.
* `else` handles the false branch.
* `elif` provides additional alternatives.
* Python evaluates `if`/`elif` branches from top to bottom.
* Threshold order matters.
* Indentation defines conditional blocks.
* `and` requires both conditions.
* `or` requires at least one.
* `not` reverses truth.
* Parentheses can make complex logic clearer.
* Empty collections and strings are falsy.
* Zero is falsy.
* `None` is falsy.

# 133. Part 5 Summary

Before this part, your Python scripts could store and organize information.

For example:

```python
environment = "production"
disk_usage = 92
failed_services = ["nginx"]
```

Now your script can reason about that information:

```python
if environment == "production" and disk_usage >= 90:
    print("Critical production disk alert")
```

The fundamental automation flow is becoming:

```text
Collect data
    |
    v
Store data
    |
    v
Evaluate conditions
    |
    v
Make decision
    |
    v
Choose action
```

You can now build logic around:

```text
Disk usage
CPU usage
Server reachability
Environment names
HTTP status codes
Files
Services
Configuration
Collections
Cloud-resource properties
```

Most importantly, conditions are not just Python syntax.

They express operational decisions.

A production automation script might eventually follow:

```text
Observe system
      |
      v
Is there a problem?
      |
   +--+--+
   |     |
  No    Yes
   |     |
   v     v
Continue  Determine severity
              |
              v
        Is action safe?
              |
           +--+--+
           |     |
          No    Yes
           |     |
           v     v
          Stop   Act
                  |
                  v
                Verify
```

In Part 6, loops will add another major capability.

Instead of checking one server:

```python
hostname = "web01"
```

you will be able to work through collections such as:

```python
servers = [
    "web01",
    "web02",
    "web03",
    "api01",
    "db01"
]
```

and apply the same decision logic repeatedly.

That moves your Python automation from:

```text
Make one decision
```

to:

```text
Process many resources
       |
       v
Evaluate each one
       |
       v
Take the correct action
       |
       v
Collect results
```

That is the foundation for server inventories, health checks, log processing, API pagination, cloud-resource inspection, service monitoring, and large-scale infrastructure automation.
