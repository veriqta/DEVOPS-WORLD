# Part 4: Python Collections for Infrastructure Data

Infrastructure automation rarely works with only one value at a time.

A script may need to work with:

* A list of servers
* Several failed services
* Multiple cloud resources
* Application settings
* Environment configuration
* API records
* Host inventories
* Kubernetes objects
* Security findings
* Monitoring results
* Deployment targets

Python provides several built-in collection types that make this possible.

The four most important beginner collection types are:

```text
list
tuple
set
dictionary
```

Each one solves a different kind of problem.

In this part, we will learn how to create, read, update, add to, remove from, sort, copy, and choose between these collections.

We will also use realistic DevOps examples rather than abstract data.

---

# 1. What Is a Collection?

A collection is a structure that stores multiple values.

Instead of writing:

```python
server1 = "web01"
server2 = "web02"
server3 = "web03"
```

you can store all three servers together:

```python
servers = ["web01", "web02", "web03"]
```

Now:

```text
servers
```

represents a group of related values.

Conceptually:

```text
servers
   |
   +--> web01
   +--> web02
   +--> web03
```

This is much easier to manage when automation must work across many systems.

---

# 2. Why Collections Matter in DevOps

Imagine checking 100 servers.

You would not want:

```python
server1 = "web01"
server2 = "web02"
server3 = "web03"
...
server100 = "web100"
```

Instead, you want one collection:

```python
servers = [
    "web01",
    "web02",
    "web03",
    "web04"
]
```

Later, a loop can process every server.

Conceptually:

```text
Server Collection
      |
      v
Python Loop
      |
      +--> Check web01
      +--> Check web02
      +--> Check web03
      +--> Check web04
```

Collections make automation scalable.

```text
Ordered collection intended to stay fixed

Unordered collection of unique values

Key-value mapping
```

```python

```

List.


Set.


Dictionary.

We will study each one carefully.

# 4. Lists

A list is an ordered collection of values.

Lists are written using square brackets:

```text
[ ]
```

Example:

```python
servers = ["web01", "web02", "web03"]
```

Check the type:

```python
print(type(servers))
```

Output:

```text
<class 'list'>
```

Lists are one of the most commonly used structures in automation.

# 5. Creating Lists

You can create a list containing strings:

```python

```

Integers:


Booleans:

```python
statuses = [True, True, False]
```

Or mixed types:

```python

```

Python allows mixed types, although you should normally use clear structures that make sense.

```text

  v

  |

```

This pattern appears constantly in automation.

```text
Load balancer

```

may be intentionally ordered.

# 8. Accessing List Values

Lists use zero-based indexing.

Example:

```python
servers = ["web01", "web02", "web03"]
```

Indexes:

```text
Value:   web01   web02   web03
Index:     0       1       2
```

Access first item:

```python
print(servers[0])
```

Output:

```text
web01
```

Second:

```python
print(servers[1])
```

Output:

```text
web02
```

---

# 9. Negative Indexing with Lists

Lists also support negative indexes.

Example:

```python
servers = ["web01", "web02", "web03"]
```

```python
print(servers[-1])
```

Output:

```text
web03
```

`-1` means the last item.

This can be useful when you want the most recently added entry.

---

# 10. Index Errors

Suppose:

```python
servers = ["web01", "web02"]
```

```text
0
1
```

If you run:

```python

```

```text

```

This means you requested a position that does not exist.

Before accessing uncertain positions, real automation should verify the structure.


Output:

```text
['web01', 'web05', 'web03']
```

The second list item changed.

# 13. Practical `append()` Example

Suppose:

```python
failed_services = []
```

During a health check, nginx fails.

```python
failed_services.append("nginx")
```

```python

```

Output:

```text
['nginx', 'docker']
```

You have built a result collection dynamically.

# 14. Adding Multiple Items with `extend()`

Suppose:

```python
servers = ["web01", "web02"]
```

and you have:

```python
new_servers = ["web03", "web04"]
```

Use:

```python
servers.extend(new_servers)
```

Now:

```python
print(servers)
```

Output:

```text
['web01', 'web02', 'web03', 'web04']
```

`append()` adds one object.

`extend()` adds each item from another iterable.

---

# 15. `append()` vs `extend()`

Compare:

```python
servers = ["web01", "web02"]

servers.append(["web03", "web04"])
```

Result:

```text
['web01', 'web02', ['web03', 'web04']]
```

You added an entire list as one item.

Using:

```python
servers.extend(["web03", "web04"])
```

produces:

```text
['web01', 'web02', 'web03', 'web04']
```

Understand the difference.

# 18. What If `remove()` Cannot Find the Value?

`pop()` both removes and returns an item.

# 27. `sorted()` vs `sort()`

`sort()` changes the original list.

`sorted()` creates a new sorted result.

Example:

```python
servers = ["web03", "web01", "web02"]

sorted_servers = sorted(servers)

print(servers)
print(sorted_servers)
```

Output:

```text
['web03', 'web01', 'web02']
['web01', 'web02', 'web03']
```

This distinction matters because sometimes you need to preserve the original order.

# 28. Copying Lists

Consider:

```python
servers = ["web01", "web02"]
```

You might think:

```python
backup_servers = servers
```

creates a separate copy.

It does not.

Both names refer to the same list.

Example:

```python
servers = ["web01", "web02"]
backup_servers = servers

backup_servers.append("web03")

print(servers)
```

Output:

```text
['web01', 'web02', 'web03']
```

That may surprise beginners.

---

# 29. Correct List Copying

Use:

```python
backup_servers = servers.copy()
```

Now:

```python
servers = ["web01", "web02"]
backup_servers = servers.copy()

backup_servers.append("web03")

print(servers)
print(backup_servers)
```

Output:

```text
['web01', 'web02']
['web01', 'web02', 'web03']
```

The collections are separate.

---

# 30. Shallow Copies

`copy()` creates what is called a shallow copy.

For flat beginner lists such as:

```python
["web01", "web02", "web03"]
```

this behaves as you usually expect.

For deeply nested structures, shallow copies require more careful understanding.

We will introduce that later in this part.

# 31. Tuples

A tuple is an ordered collection similar to a list.

Tuples are commonly written using parentheses:

```python
database = ("db01", 5432)
```

Check:

```python
print(type(database))
```

Output:

```text
<class 'tuple'>
```

---

# 32. Why Use a Tuple?

A tuple is commonly used when a group of values should be treated as fixed.

For example:

```python
database_endpoint = ("db01.internal", 5432)
```

This might represent:

```text
Hostname
Port
```

You can access:

```python
print(database_endpoint[0])
print(database_endpoint[1])
```

Output:

```text
db01.internal
5432
```

---

# 33. Tuples Are Immutable

Lists can be modified.

Tuples cannot be modified in place.

This fails:

```python
database_endpoint = ("db01", 5432)

database_endpoint[0] = "db02"
```

Python raises:

```text
TypeError
```

This is useful when the collection represents something that should not be changed accidentally.

---

# 34. Creating a Single-Item Tuple

This is not a tuple:

```python
server = ("web01")
```

It is just a string inside parentheses.

For a one-item tuple:

```python
server = ("web01",)
```

The comma matters.

Check:

```python
print(type(server))
```

Output:

```text
<class 'tuple'>
```

---

# 35. Tuple Unpacking

You can assign tuple values to separate variables.

Example:

```python
database_endpoint = ("db01", 5432)

hostname, port = database_endpoint

print(hostname)
print(port)
```

Output:

```text
db01
5432
```

This is called unpacking.

It can make code more readable.

---

# 36. Practical Tuple Example

Suppose a health check targets:

```python
target = ("api.example.com", 443)
```

You can write:

```python
hostname, port = target

print(f"Checking {hostname}:{port}")
```

Output:

```text
Checking api.example.com:443
```

# 37. Sets

A set stores unique values.

Example:

```python
hosts = {"web01", "web02", "web03"}
```

Check:

```python
print(type(hosts))
```

Output:

```text
<class 'set'>
```

Sets are useful when duplicates are not meaningful.

---

# 38. Sets Do Not Preserve List-Style Positioning

You should not rely on set order.

This is wrong:

```python
hosts[0]
```

Sets do not support normal positional indexing.

A set is designed around:

```text
uniqueness
membership
set operations
```

not ordered indexing.

---

# 39. Sets Automatically Remove Duplicates

Consider:

```python
hosts = {"web01", "web02", "web01", "web03"}
```

Print:

```python
print(hosts)
```

The duplicate:

```text
web01
```

appears only once.

Conceptually:

```text
Input:
web01
web02
web01
web03

Set:
web01
web02
web03
```

This is extremely useful for cleaning host inventories.

---

# 40. Removing Duplicate Hosts from a List

Suppose:

```python
hosts = [
    "web01",
    "web02",
    "web01",
    "web03",
    "web02"
]
```

Convert to a set:

```python
unique_hosts = set(hosts)

print(unique_hosts)
```

Now duplicates are removed.

If you need a list again:

```python
unique_hosts = list(set(hosts))
```

However, converting through a set does not preserve original ordering reliably.

If order matters, use a different deduplication strategy.

---

# 41. Creating an Empty Set

This does not create a set:

```python
hosts = {}
```

It creates an empty dictionary.

To create an empty set:

```python
hosts = set()
```

This is an important beginner distinction.

---

# 42. Adding Items to a Set

Use:

```python
add()
```

Example:

```python
hosts = {"web01", "web02"}

hosts.add("web03")

print(hosts)
```

If you add an existing item:

```python
hosts.add("web01")
```

nothing new is added because sets contain unique values.

---

# 43. Removing Items from Sets

Use:

```python
remove()
```

Example:

```python
hosts.remove("web02")
```

If the value does not exist, `remove()` raises a `KeyError`.

There is another method:

```python
discard()
```

Example:

```python
hosts.discard("web09")
```

If `web09` does not exist, Python does not raise an error.

That can be useful when absence is acceptable.

---

# 44. Set Membership Testing

Sets are very useful for membership checks.

Example:

```python
allowed_hosts = {"web01", "web02", "web03"}

print("web02" in allowed_hosts)
```

Output:

```text
True
```

Membership testing is one of the reasons sets are commonly used.

---

# 45. Basic Set Operations

Suppose:

```python
expected_hosts = {"web01", "web02", "web03"}
running_hosts = {"web01", "web03"}
```

Which hosts are expected but not running?

```python
missing_hosts = expected_hosts - running_hosts

print(missing_hosts)
```

Result:

```text
{'web02'}
```

This is called set difference.

---

# 46. Finding Common Values

Suppose:

```python
production_hosts = {"web01", "web02", "db01"}
monitored_hosts = {"web01", "db01", "cache01"}
```

Find common hosts:

```python
common_hosts = production_hosts & monitored_hosts
```

Result:

```text
{'web01', 'db01'}
```

This is set intersection.

---

# 47. Combining Sets

Example:

```python
group_a = {"web01", "web02"}
group_b = {"web02", "web03"}

all_hosts = group_a | group_b

print(all_hosts)
```

Result contains:

```text
web01
web02
web03
```

This is union.

These operations become useful in inventory comparison.

# 49. Understanding Key-Value Pairs

Consider:

```python

}
```


Each key identifies a value.

This structure is ideal for configuration and API data.

---

# 50. Why Dictionaries Are Useful

You must remember.

A dictionary is clearer:

Now the meaning is explicit.

```python
        "hostname": "web02",

        "hostname": "web03",
        "ip": "10.0.1.12",

    }

```

This is a very realistic structure.

---

# 67. Understanding the Nested Structure

Conceptually:

```text
servers
  |
  +--> item 0
  |      |
  |      +--> hostname: web01
  |      +--> ip: 10.0.1.10
  |      +--> status: running
  |
  +--> item 1
  |      |
  |      +--> hostname: web02
  |      +--> ip: 10.0.1.11
  |      +--> status: running
  |
  +--> item 2
         |
         +--> hostname: web03
         +--> ip: 10.0.1.12
         +--> status: stopped
```

The outer structure is a list.

Each item is a dictionary.

---

# 68. Accessing Nested Values

Suppose:

```python
servers = [
    {
        "hostname": "web01",
        "status": "running"
    },
```

# 82. Copying Dictionaries

Like lists, dictionary assignment does not automatically create an independent copy.

Example:

```python
production = {
    "replicas": 3,
    "debug": False
}

staging = production

staging["debug"] = True

print(production)
```

You may unexpectedly see:

```text
{
    'replicas': 3,
    'debug': True
}
```

Both names referred to the same dictionary.

---

# 83. Correct Dictionary Copying

Use:

```python
staging = production.copy()
```

Example:

```python
production = {
    "replicas": 3,
    "debug": False
}

staging = production.copy()
staging["debug"] = True

print(production)
print(staging)
```

Now they are separate top-level dictionaries.

---

# 84. Shallow Copy Warning with Nested Structures

Consider:

```python
production = {
    "database": {
        "host": "db01",
        "port": 5432
    }
}
```

Then:

```python
staging = production.copy()
```

This copies the outer dictionary, but the nested dictionary is still shared.

If you change:

```python
staging["database"]["host"] = "db-stage"
```

you may also affect the nested value visible through `production`.

This happens because `.copy()` performs a shallow copy.

---

# 85. Deep Copying

For fully independent nested structures, Python provides:

```python
import copy
```

Then:

```python
staging = copy.deepcopy(production)
```

Now nested objects are copied too.

At this stage, remember:

```text
copy()
   |
   v
top-level copy

deepcopy()
   |
   v
independent nested copy
```

Do not use deep copies blindly. Understand why you need them.

# 122. What You Should Now Understand

You should now understand:

* Collections store multiple values.
* Lists are ordered and mutable.
* Lists support indexing.
* Lists allow duplicate values.
* `append()` adds one item.
* `extend()` adds items from another collection.
* `insert()` adds at a chosen position.
* `remove()` removes by value.
* `pop()` removes and returns an item.
* `len()` gives collection size.
* `in` performs membership testing.
* `sort()` modifies a list in place.
* `sorted()` returns a sorted result.
* `.copy()` creates a shallow copy.
* Tuples are ordered and immutable.
* Tuple unpacking can assign several variables.
* Sets store unique values.
* Sets are useful for deduplication and membership.
* Sets do not provide normal positional indexing.
* Set difference can find missing resources.
* Set intersection can find common resources.
* Dictionaries store key-value pairs.
* Dictionary keys should be unique.
* `get()` can safely retrieve optional values.
* Dictionaries are mutable.
* `.keys()`, `.values()`, and `.items()` expose different parts of a dictionary.
* `in` checks dictionary keys by default.
* Lists and dictionaries can be nested.
* Cloud and API data often use nested lists and dictionaries.
* Nested access should be read one layer at a time.
* Shallow copies do not fully separate nested structures.
* `copy.deepcopy()` can create independent nested copies.
* Collection choice affects readability and correctness.
* Sensitive collections should not be printed blindly.

# 126. Part 4 Summary

You now know how Python represents groups of infrastructure data.

Instead of working with isolated values:

```python
server1 = "web01"
server2 = "web02"
server3 = "web03"
```

you can use:

```python
servers = ["web01", "web02", "web03"]
```

When each resource needs additional properties:

```python
servers = [
    {
        "hostname": "web01",
        "status": "running"
    },
    {
        "hostname": "web02",
        "status": "stopped"
    }
]
```

When uniqueness matters:

```python
unique_hosts = {"web01", "web02", "web03"}
```

When values belong together and should remain fixed:

```python
endpoint = ("api.example.com", 443)
```

When configuration needs named fields:

```python
environment = {
    "name": "production",
    "region": "us-east-1",
    "replicas": 4
}
```

These structures form the foundation of real automation.

Cloud APIs, JSON responses, Kubernetes resources, inventories, CI/CD configuration, monitoring data, and security findings frequently become combinations of:

```text
Lists
   |
   +--> Dictionaries
   |       |
   |       +--> Lists
   |       +--> Dictionaries
   |
   +--> Other values
```

The important skill is not simply memorizing syntax.

It is learning to ask:

```text
Do I need order?
Do I need uniqueness?
Do I need named fields?
Will the collection change?
Are values nested?
Do duplicates matter?
```

Those questions help you choose the correct data structure.

In **Part 5: Conditions and Decision-Making**, we will teach Python how to make decisions using these values and collections.

That is where automation begins moving from:

```text
Store information
```

to:

```text
Inspect information
      |
      v
Evaluate conditions
      |
      v
Choose an action
```

We will use realistic examples such as detecting high CPU, checking service status, identifying production environments, validating ports, checking whether files or resources exist, and deciding when an automation script should continue, warn, or stop.
