# 1. What Is a Network?

A network is a group of devices or systems that can communicate with one another.

At home, you might have:

```text
Laptop
   |
   |
Wi-Fi Router
   |
   +------ Phone
   |
   +------ Television
   |
   +------ Printer
   |
   +------ Internet
```

The devices connected through your router form a network.

Cloud infrastructure works with the same fundamental idea.

Instead of only laptops and phones, cloud networks contain resources such as:

```text
EC2 instances
Load balancers
Databases
Containers
Network interfaces
Gateways
```

These resources need ways to identify and reach one another.

---

# 2. Why Do Computers Need Networks?

Suppose you create two servers:

```text
Server A

Server B
```

If there is no network relationship between them, they cannot simply exchange data.

You might want:

```text
Web Server
    |
    v
Database Server
```

The web server must know where the database exists.

The network must also provide a path between them.

At a simplified level, communication requires questions such as:

```text
Who am I?

Where is the destination?

How do I reach it?

Is communication permitted?

Where should the traffic go next?
```

Networking provides the mechanisms that answer these questions.

Suppose:

```text
Server A
10.0.1.10

Server B
10.0.1.20
```

Server A wants to communicate with Server B.

Conceptually:

```text
Server A
10.0.1.10
   |
   | traffic
   v
Network
   |
   v
Server B
10.0.1.20
```

The IP addresses help identify network interfaces participating in the communication.

This leads to one of the most important concepts in networking:

```text
IP addresses
```

Before building a VPC, you need to understand them.

---

# 4. What Is an IP Address?

IP means:

Internet Protocol.

An IP address identifies a network interface participating in an IP network.

A familiar IPv4 address looks like:

```text
192.168.1.10
```

or:

```text
10.0.1.25
```

or:

```text
172.16.20.50
```

When systems communicate using IP, addresses help determine the source and destination.

Conceptually:

```text
Source
10.0.1.10
   |
   | Packet
   |
   | Destination: 10.0.1.20
   v
Destination
10.0.1.20
```

---

# 5. IPv4

IPv4 means:

Internet Protocol version 4.

An IPv4 address contains:

```text
32 bits
```

A bit is a binary value:

```text
0
or
1
```

The 32 bits are normally displayed as four decimal numbers separated by dots.

Example:

```text
10.0.1.25
```

Each section represents eight bits.

These sections are commonly called octets.

So:

```text
10 . 0 . 1 . 25
 |   |   |    |
8b  8b  8b   8b
```

Total:

```text
8 + 8 + 8 + 8
=
32 bits
```

---

# 6. Why Is Each IPv4 Octet Between 0 and 255?

Eight bits can represent 256 different values.

The binary range is:

```text
00000000
```

through:

```text
11111111
```

In decimal:

```text
0
through
255
```

Therefore this is valid:

```text
192.168.1.200
```

But this is not a valid IPv4 address:

```text
192.168.1.300
```

because:

```text
300 > 255
```

---

# 7. Binary Basics for Networking

You do not need to become a binary mathematician before using AWS.

However, CIDR notation makes much more sense when you understand why IP addresses are based on bits.

An octet has these binary place values:

```text
128 64 32 16 8 4 2 1
```

Example:

```text
00001010
```

The active bits represent:

```text
8 + 2
=
10
```

Therefore:

```text
00001010
=
10
```

The IPv4 address:

```text
10.0.0.0
```

in binary begins:

```text
00001010.00000000.00000000.00000000
```

CIDR notation tells us how many of these bits describe the network portion.

---

# 8. Network Portion and Host Portion

An IP address can be understood as having:

```text
Network portion
+
Host portion
```

Think of a postal address.

```text
City
+
House
```

The city identifies the larger area.

The house identifies a particular location inside it.

Similarly:

```text
Network
+
Device/interface within that network
```

CIDR notation tells us where the network portion ends.

---

# 9. What Is CIDR?

CIDR means:

Classless Inter-Domain Routing.

You will constantly see CIDR notation in AWS.

Examples:

```text
10.0.0.0/16
```

```text
10.0.1.0/24
```

```text
192.168.10.0/24
```

```text
172.16.0.0/16
```

The number after `/` is called the prefix length.

For:

```text
10.0.0.0/16
```

the:

```text
/16
```

means the first 16 bits identify the network prefix.

IPv4 contains 32 bits total.

Therefore:

```text
Network bits = 16
Host bits = 32 - 16
Host bits = 16
```

---

# 10. Understanding `/24`

Consider:

```text
10.0.1.0/24
```

IPv4:

```text
32 total bits
```

CIDR:

```text
24 network bits
```

Remaining:

```text
8 host bits
```

Conceptually:

```text
10 . 0 . 1 . X
|-----------| |
   Network    Host space
```

The range is:

```text
10.0.1.0
through
10.0.1.255
```

That represents:

```text
256 total IPv4 addresses
```

---

# 11. Why `/24` Contains 256 Addresses

There are:

```text
32 - 24
=
8
```

host bits.

Each bit can be:

```text
0 or 1
```

Therefore:

```text
2^8
=
256
```

possible combinations.

This gives 256 addresses.

The general formula is:

```text
2^(32 - prefix)
```

For `/24`:

```text
2^(32 - 24)

2^8

256
```

---

# 12. Understanding `/16`

Now consider:

```text
10.0.0.0/16
```

There are:

```text
32 - 16
=
16
```

host bits.

Therefore:

```text
2^16
=
65,536
```

total IPv4 addresses in the CIDR block.

The range is:

```text
10.0.0.0
through
10.0.255.255
```

This is the CIDR we will use for our beginner VPC.

---

# 13. Common CIDR Sizes

You should begin recognizing common sizes.

| CIDR | Total IPv4 Addresses |
| ---- | -------------------: |
| /16  |               65,536 |
| /17  |               32,768 |
| /18  |               16,384 |
| /19  |                8,192 |
| /20  |                4,096 |
| /21  |                2,048 |
| /22  |                1,024 |
| /23  |                  512 |
| /24  |                  256 |
| /25  |                  128 |
| /26  |                   64 |
| /27  |                   32 |
| /28  |                   16 |

Notice:

```text
Smaller prefix number
=
Larger network
```

and:

```text
Larger prefix number
=
Smaller network
```

This initially feels backward to many beginners.

---

# 14. Why Does `/16` Have More Addresses Than `/24`?

Remember:

```text
IPv4 = 32 bits
```

With `/16`:

```text
16 bits fixed for network
16 bits remain
```

With `/24`:

```text
24 bits fixed for network
8 bits remain
```

More remaining host bits means more possible addresses.

Therefore:

```text
/16
65,536 addresses
```

is much larger than:

```text
/24
256 addresses
```

---

# 15. CIDR Range Example

Consider:

```text
10.20.0.0/16
```

The first two octets are effectively fixed at this level:

```text
10.20
```

The remaining space ranges from:

```text
0.0
```

through:

```text
255.255
```

Therefore:

```text
10.20.0.0
```

through:

```text
10.20.255.255
```

belongs to that CIDR block.

---

# 16. Another CIDR Example

Consider:

```text
192.168.50.0/24
```

Range:

```text
192.168.50.0
through
192.168.50.255
```

Total:

```text
256 addresses
```

Later, when we create subnets, CIDR calculations become extremely important.

For now, understand:

```text
CIDR
=
Starting network address
+
Prefix length
```

# 17. Public and Private IPv4 Addresses

Not every IPv4 address should be directly reachable across the public internet.

IPv4 includes ranges reserved for private networks.

The major private IPv4 ranges defined by RFC 1918 are:

```text
10.0.0.0/8
```

```text
172.16.0.0/12
```

```text
192.168.0.0/16
```

These ranges are commonly used inside:

* Corporate networks
* Home networks
* Data centers
* Cloud networks
* AWS VPCs

---

# 18. Private IP Address Example

Suppose your EC2 instance has:

```text
10.0.1.25
```

This belongs to:

```text
10.0.0.0/8
```

which is private address space.

Private addresses are not globally routable on the public internet.

That does not mean the machine cannot access the internet.

It means private addressing alone does not make the address itself globally internet-routable.

Other networking components may provide internet connectivity.

We will learn those components later.

---

# 19. Public IP Addresses

A public IP address is globally routable on the internet, subject to routing and security controls.

Conceptually:

```text
Internet
   |
   v
Public IP
   |
   v
AWS Resource
```

Your Part 3 EC2 instance may have had both:

```text
Private IPv4
```

and:

```text
Public IPv4
```

This often confuses beginners.

The instance can participate in its VPC using its private addressing while AWS provides public addressing capabilities for internet communication.

---

# 20. Private Does Not Mean Secure

This distinction is critical.

```text
Private IP
```

does not automatically mean:

```text
Secure
```

and:

```text
Public IP
```

does not automatically mean:

```text
Compromised
```

Security depends on multiple controls.

Later we will learn about:

* Security Groups
* Network ACLs
* Routing
* IAM
* Firewalls
* Application authentication
* Encryption

Private addressing describes addressing and routing characteristics.

It is not a complete security strategy.

---

# 21. Why Private IP Addresses Exist

IPv4 has a limited address space.

If every laptop, phone, virtual machine, container, database, and internal server required a unique permanent public IPv4 address, address exhaustion would be an even larger problem.

Private addressing allows organizations to reuse the same ranges internally.

Your home may use:

```text
192.168.1.10
```

Someone else's home can also use:

```text
192.168.1.10
```

because those networks are separate.

AWS customers can similarly have separate VPCs that both use:

```text
10.0.0.0/16
```

as long as those networks do not need to communicate in a way that creates overlapping-address problems.

# 22. Why AWS Needs VPCs

Imagine AWS without network isolation.

Millions of customers create:

```text
EC2
Databases
Applications
Containers
Load Balancers
```

If everything existed in one giant shared customer-visible network:

```text
Customer A EC2
Customer B Database
Customer C EC2
Customer D Application
```

network management would be unacceptable.

Customers need isolated networking environments.

AWS solves this through Amazon VPC.

# 23. What Is a VPC?

VPC means:

Virtual Private Cloud.

Amazon VPC allows you to create a logically isolated virtual network within AWS.

Think:

```text
AWS
 |
 +----------------------------------+
 |              VPC                 |
 |                                  |
 |   Your network address space     |
 |   Your networking resources      |
 |   Your routing decisions         |
 |   Your security controls         |
 |                                  |
 +----------------------------------+
```

The VPC becomes the primary network boundary for many AWS resources.

---

# 24. VPC as Your AWS Network

Suppose you create:

```text
VPC
10.0.0.0/16
```

You have defined an address space.

Conceptually:

```text
10.0.0.0
      |
      |
      |     Your VPC address space
      |
      v
10.0.255.255
```

Later, you will divide this address space into smaller networks called subnets.

For now:

```text
VPC
=
Large network boundary
```

# 25. VPCs Are Regional

A VPC belongs to one AWS Region.

Suppose you create a VPC in:

```text
us-east-1
```

That VPC belongs to that Region.

It does not stretch directly across:

```text
us-east-1
+
eu-west-1
```

as one VPC.

Conceptually:

```text
AWS

Region: us-east-1
|
└── VPC A


Region: eu-west-1
|
└── VPC B
```

If resources in different Regions need private network communication, additional connectivity must be designed.

---

# 26. VPCs Span Availability Zones Within a Region

Although a VPC belongs to one Region, it can span the Availability Zones in that Region.

This distinction is extremely important.

```text
AWS Region
|
└── VPC 10.0.0.0/16
    |
    ├── Availability Zone A
    |
    ├── Availability Zone B
    |
    └── Availability Zone C
```

The VPC is regional.

Later, subnets will be created inside individual Availability Zones.

So remember:

```text
VPC
=
Regional
```

while:

```text
Subnet
=
Availability Zone specific
```

We will explore this deeply in Part 6.

When you launched your first EC2 instance, you may not have manually created:

You were probably using the Region's default networking environment.

# 31. Why DevOps Engineers Need Custom VPCs

Production infrastructure usually requires deliberate design.

You may need:




# 32. Default VPC vs Custom VPC

| Default VPC                                        | Custom VPC                                     |
| -------------------------------------------------- | ---------------------------------------------- |
| Created automatically by AWS in applicable Regions | Created intentionally by you                   |
| Designed for quick use                             | Designed for your architecture                 |
| Includes default networking resources              | You decide what to create                      |
| Useful for basic learning/testing                  | Preferred for deliberate infrastructure design |
| Can hide networking details from beginners         | Forces you to understand networking            |

A custom VPC is not automatically secure simply because it is custom.

You still need correct design.

# 33. Choosing a VPC CIDR

When creating a VPC, one of the most important decisions is:

```text

```

For our lab:

```text

```

This provides:

```text

```

# 34. Why Not Use a Random CIDR?

Imagine choosing:

```text
10.0.0.0/28
```

for a large production VPC.

That is extremely small.

Later you want:

```text
Web servers
Application servers
Databases
Containers
Load balancers
Endpoints
Multiple AZs
Development resources
```

You may run out of address space.

The opposite mistake is choosing unnecessarily large ranges everywhere without planning how multiple networks must coexist.

CIDR planning should consider future architecture.

# 35. Network Range

A CIDR block defines a range.

For:

```text
10.0.0.0/16
```

the range is:

```text
10.0.0.0
```

through:

```text
10.0.255.255
```

For:

```text
10.1.0.0/16
```

the range is:

```text
10.1.0.0
```

through:

```text
10.1.255.255
```

These two ranges do not overlap.

That becomes useful when designing multiple VPCs.

```text

10.0.0.0/16

Development VPC
10.1.0.0/16
```

# 37. What Are Overlapping Networks?

Two networks overlap when some or all of their IP address spaces cover the same addresses.

Example:

```text
VPC A
10.0.0.0/16

VPC B
10.0.0.0/16
```

They completely overlap.

Now suppose:

```text
10.0.1.25
```

exists in VPC A.

And another:

```text
10.0.1.25
```

exists in VPC B.

If the networks remain isolated, this is possible.

But if you later try to connect them, routing becomes ambiguous.

---

# 38. Why Overlapping Networks Cause Problems

Suppose:

```text
VPC A
10.0.0.0/16

VPC B
10.0.0.0/16
```

A machine in VPC A wants:

```text
10.0.5.20
```

Question:

```text
Does 10.0.5.20 mean:

a local VPC A resource?

or

a resource in VPC B?
```

The address ranges are not uniquely distinguishable for straightforward routing.

This creates connectivity problems.

---

# 39. Overlap Example

Consider:

```text
Network A
10.0.0.0/16
```

and:

```text
Network B
10.0.1.0/24
```

Do they overlap?

Yes.

Why?

Because:

```text
10.0.0.0/16
```

contains:

```text
10.0.0.0
through
10.0.255.255
```

And:

```text
10.0.1.0/24
```

contains:

```text
10.0.1.0
through
10.0.1.255
```

Network B sits inside Network A's address range.

---

# 40. Non-Overlapping Example

Consider:

```text
10.0.0.0/16
```

and:

```text
10.1.0.0/16
```

First range:

```text
10.0.0.0
-
10.0.255.255
```

Second:

```text
10.1.0.0
-
10.1.255.255
```

They do not overlap.

This makes future network connectivity easier to design.

---

# 41. Think Beyond AWS

CIDR planning becomes especially important when AWS must connect to:

```text
Corporate office
Data center
VPN
Another cloud
Another AWS account
Another VPC
```

Suppose your corporate network already uses:

```text
10.0.0.0/8
```

Then casually creating AWS VPCs inside the same range can create future complications.

Before choosing production CIDRs, understand existing network allocations.

---

# 42. Beginner VPC CIDR Planning Rule

For labs, something simple like:

```text
10.0.0.0/16
```

is fine.

For production:

```text
Do not choose CIDRs in isolation.
```

Ask:

* What networks already exist?
* Will this VPC connect to another VPC?
* Will it connect to a data center?
* Will it connect through VPN?
* Will it connect to another cloud?
* How many environments are planned?
* How many subnets will be needed?
* How much future growth is expected?

Address planning is architecture.

# 51. Elastic Network Interfaces

Now we need to understand how an EC2 instance actually connects to a VPC.

It uses a network interface.

In AWS, this is called an:


# 60. Private IP Addresses on EC2

# 61. Public IPv4 Addresses on EC2

Depending on subnet configuration and launch settings, an EC2 instance may receive a public IPv4 address.

Conceptually:

```text
Internet
   |
Public IPv4
   |
AWS networking
   |
ENI
   |
Private IPv4
   |
EC2
```

An important AWS detail is that the public IPv4 address is not normally configured inside the guest operating system in the same way as the private IPv4 address.

Inside Linux, you typically see the private address on the interface.

AWS handles the public-address mapping.

---

# 62. Why Public IPv4 Can Change

A normal automatically assigned EC2 public IPv4 address is not necessarily permanent.

For example, after certain stop/start lifecycle operations, an instance can receive a different public IPv4 address.

Suppose:

```text
Before stop
54.x.x.x
```

After start:

```text
3.x.x.x
```

If customers or DNS records depend directly on the old address, this becomes a problem.

One option for a stable public IPv4 address is an Elastic IP address.

---

# 63. What Is an Elastic IP Address?

An Elastic IP address, or EIP, is a static public IPv4 address allocated to your AWS account for use with supported resources.

Conceptually:

```text
Elastic IP
Stable public IPv4
      |
      v
AWS Resource
```

Unlike an automatically assigned public IPv4 address that may change with instance lifecycle events, an EIP is allocated separately and can be associated with supported resources.

---

# 64. Why Use an Elastic IP?

Suppose a legacy external partner allows traffic only from:

```text
203.0.113.X
```

and expects your system to have a stable public source address.

A changing address would be difficult.

An Elastic IP can help provide stable public IPv4 addressing in architectures where that is required.

However:

```text
Stable IP
```

does not mean:

```text
Best architecture for every application
```

Modern applications often use DNS and load balancers instead of exposing individual EC2 addresses to users.

---

# 65. Elastic IPs Are Not Free to Ignore

Public IPv4 addresses are billable resources under current AWS pricing models.

Do not allocate addresses and forget them.

For labs:

```text
Create
 |
Use
 |
Release when finished
```

Always check current AWS pricing because pricing can change.

---

# 66. Elastic IP vs Automatically Assigned Public IPv4

Simplified comparison:

| Automatically Assigned Public IPv4                         | Elastic IP                                  |
| ---------------------------------------------------------- | ------------------------------------------- |
| Assigned as part of supported launch/network configuration | Allocated to your account                   |
| Can change with lifecycle events                           | Designed to remain allocated until released |
| Useful for simple temporary access                         | Useful when stable public IPv4 is required  |
| Should not be treated as permanent                         | Stable while you retain it                  |
| Public IPv4 charges can apply                              | Public IPv4 charges can apply               |

For public applications, we will eventually prefer architectures involving load balancers rather than treating EC2 IP addresses as the application's permanent public identity.

# 67. DNS

Humans are not good at remembering IP addresses.

```text

```

Instead, we use names:

```text

```

DNS means:

Conceptually:

```text

       |
       v

       |
       v

```

# 68. Why DNS Matters Inside a VPC

DNS is not only for public websites.

Resources inside AWS also need name resolution.

Instead of applications always communicating through hard-coded addresses:

```text

```

they may use DNS names.

This is important because IP addresses can change.

Names provide a more flexible abstraction.

# 69. VPC DNS Attributes

Two important VPC DNS-related attributes are commonly encountered:

```text

```

and:

```text

```

At beginner level:

`enableDnsSupport` relates to whether DNS resolution through the Amazon-provided DNS server is supported for the VPC.

`enableDnsHostnames` relates to whether instances with public IPv4 addresses can receive corresponding public DNS hostnames when the required conditions are met.

You will normally want to understand these settings rather than disabling them without reason.

# 70. DNS Resolution Flow

Conceptually:

```text

    |
    | asks:
    | "What address belongs to this name?"
    v

    |
    v
DNS Answer
    |
    v

```

DNS solves a naming problem.

Routing solves a path problem.

Security controls solve a permission problem.

Do not confuse them.

# 71. DNS Is Not Routing

Suppose:

```text

```

resolves successfully to:

```text

```

That only means:

```text

```

It does not prove:

```text

```

The route may be wrong.

Security controls may block traffic.

The database may be down.

A successful DNS lookup is one troubleshooting clue, not proof that the whole connection works.

# 91. Network Design Reasoning

# 95. Troubleshooting: "My CIDR Is Invalid"

## Problem

AWS rejects the CIDR you entered.

Example:

```text
10.0.0.1/16
```

when you intended to define the `/16` network beginning at `10.0.0.0`.

## Possible cause

The CIDR does not represent the network boundary you intended.

For:

```text
10.0.0.0/16
```

the network begins at:

```text
10.0.0.0
```

## Fix

Understand the network boundary before creating the VPC.

Do not randomly change numbers until AWS accepts something.

# 96. Troubleshooting: Overlapping CIDR

## Problem

You later attempt to connect two networks.

VPC A:

```text
10.0.0.0/16
```

VPC B:

```text
10.0.0.0/16
```

Connectivity design becomes difficult or unsupported for straightforward routing scenarios because the ranges overlap.

## Cause

Both networks use the same address space.

## Prevention

Plan non-overlapping CIDRs before creating interconnected networks.

Example:

```text
VPC A
10.0.0.0/16

VPC B
10.1.0.0/16
```

Prevention is easier than renumbering an established environment.

# What You Should Now Understand

Before moving to Part 6, you should confidently understand:

* A network allows systems to communicate.
* IP addresses identify network interfaces participating in IP communication.
* IPv4 addresses contain 32 bits.
* IPv4 addresses are displayed as four octets.
* Each octet ranges from 0 to 255.
* An IP address can be understood as network and host portions.
* CIDR defines how many bits belong to the network prefix.
* `/24` provides 256 total IPv4 addresses.
* `/16` provides 65,536 total IPv4 addresses.
* Smaller CIDR prefix numbers represent larger address spaces.
* Private IPv4 ranges are reserved for internal networking.
* Private IP does not automatically mean secure.
* Public IP does not automatically mean insecure.
* A VPC is a logically isolated virtual network in AWS.
* VPCs are regional.
* A VPC can span Availability Zones within its Region.
* Subnets are created within specific Availability Zones.
* A default VPC provides preconfigured networking for easier resource launching.
* A custom VPC gives you deliberate control over network design.
* VPC CIDR planning affects future growth and connectivity.
* Overlapping CIDRs create problems when networks need to communicate.
* Network planning should consider existing corporate and cloud networks.
* An ENI is a virtual network interface.
* EC2 instances use ENIs to participate in VPC networking.
* ENIs can have private addresses and security-related configuration.
* `ip addr` shows Linux interface addresses.
* `ip route` shows routing information.
* An Elastic IP provides stable public IPv4 addressing where required.
* Public IPv4 addresses should not be allocated without understanding cost and architecture.
* DNS translates names into information such as IP addresses.
* DNS resolution and routing solve different problems.
* VPCs form network boundaries.
* Network troubleshooting should proceed layer by layer.
* Production network design should consider security, availability, scalability, operations, and cost.
