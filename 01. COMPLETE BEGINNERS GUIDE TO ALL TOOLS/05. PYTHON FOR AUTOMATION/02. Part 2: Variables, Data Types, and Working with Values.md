# Part 2: Variables, Data Types, and Working with Values

Python automation depends on data.

A script may need to know:

* Which server to check
* Which port to connect to
* Which service to inspect
* Which environment it is running in
* What CPU threshold should trigger an alert
* Where a log file is stored
* Whether a feature is enabled
* Whether a value exists at all

To work with this information, Python uses variables and data types.

In this part, we will learn how Python stores values, how different kinds of values behave, how to convert between them, and how these ideas apply to DevOps and infrastructure automation.

---

# 1. What Is a Variable?

A variable is a name that refers to a value.

For example:

```python
server = "web01"
```

This creates a variable named:

```text
server
```

and gives it the value:

```text
web01
```

Think of it like this:

```text
Variable name
    |
    v
 server
    |
    v
"web01"
```

The variable allows you to reuse the value later.

For example:

```python
server = "web01"

print(server)
```

Output:

```text
web01
```

Without variables, you would have to repeatedly write the same value throughout your script.

Variables make automation easier to read, change, and maintain.

---

# 2. Why Variables Matter in Automation

Imagine this script:

```python
print("Checking web01")
print("Connecting to web01")
print("Collecting logs from web01")
print("Finished checking web01")
```

If the server changes from:

```text
web01
```

to:

```text
web02
```

you would need to update it in several places.

A better approach is:

```python
server = "web01"

print(f"Checking {server}")
print(f"Connecting to {server}")
print(f"Collecting logs from {server}")
print(f"Finished checking {server}")
```

Now you only need to change:

```python
server = "web02"
```

The rest of the script automatically uses the new value.

This is one of the core benefits of variables.

---

# 3. Variable Assignment

Python uses the equals sign:

```text
=
```

for assignment.

Example:

```python
server = "web01"
```

Read this as:

```text
Assign the value "web01" to the name server.
```

It does not mean the same thing as mathematical equality.

The left side is the variable name.

The right side is the value or expression being assigned.

```text
server = "web01"
   |        |
   |        +--> value
   |
   +--> variable name
```

Another example:

```python
port = 443
```

Here:

```text
port
```

refers to:

```text
443
```

# 4. Variables Can Store Different Kinds of Data

Python variables can refer to many different types of values.

For example:

```python
hostname = "app-server-01"
port = 443
cpu_threshold = 85.5
service_running = True
maintenance_window = None
```

These values are not all the same type.

They represent:

```text
hostname             -> string
port                 -> integer
cpu_threshold        -> floating-point number
service_running      -> Boolean
maintenance_window   -> None
```

These categories are called data types.

Understanding data types is essential because Python handles different kinds of data differently.

---

# 5. What Is a Data Type?

A data type describes what kind of value something is.

For example:

```python
server = "web01"
```

The value:

```text
web01
```

is text.

Python represents text using the:

```text
str
```

type.

Now consider:

```python
port = 443
```

The value:

```text
443
```

is a whole number.

Python represents whole numbers using:

```text
int
```

The type tells Python what operations make sense for that value.

For example:

```python
10 + 5
```

means numeric addition.

But:

```python
"web" + "01"
```

means string concatenation.

Same operator, different behavior based on the data types involved.

Python provides a built-in function called:

```python

```

You can use it to check the type of a value.

Example:

```python

print(type(server))
```

Output:

```text
<class 'str'>
```

This tells you that:

```text
server
```

contains a string.

Another example:

```python

print(type(port))
```

Output:

```text
<class 'int'>
```

Another:

```python
cpu_usage = 72.5

print(type(cpu_usage))
```

Output:

```text
<class 'float'>
```

Another:

```python
service_running = True

print(type(service_running))
```

Output:

```text
<class 'bool'>
```

`type()` is extremely useful while learning and troubleshooting.

# 23. Variable Naming Rules

Python has rules for variable names.

Valid:

```python
server
server_name
server1
web_server
cpu_usage
```

Invalid:

```python
1server
server-name
server name
```

Let's understand why.

---

# 24. Variable Names Cannot Start with a Number

Wrong:

```python
1server = "web01"
```

Correct:

```python
server1 = "web01"
```

A variable name may contain numbers, but it cannot begin with one.

---

# 25. Variable Names Cannot Contain Spaces

Wrong:

```python
server name = "web01"
```

Correct:

```python
server_name = "web01"
```

Use underscores instead of spaces.

---

# 26. Avoid Hyphens in Variable Names

Wrong:

```python
server-name = "web01"
```

The hyphen is interpreted as a subtraction operator.

Use:

```python
server_name = "web01"
```

---

# 27. Variable Names Are Case-Sensitive

These are different:

```python
server
Server
SERVER
```

Example:

```python
server = "web01"

print(Server)
```

This will fail because:

```text
Server
```

was never assigned.

---

# 28. Python Keywords Cannot Be Used as Variable Names

Python reserves certain words for language syntax.

Examples include:

```text
if
else
for
while
def
return
True
False
None
```

Do not do this:

```python
for = "production"
```

Python will raise a syntax error.

---

# 29. Good Naming Conventions

A variable name should describe what the value represents.

Weak:

```python
x = "prod-web-01"
```

Better:

```python
server = "prod-web-01"
```

Even better when necessary:

```python
primary_web_server = "prod-web-01"
```

Good names make automation easier to understand.

---

# 30. Use `snake_case`

Python convention commonly uses:

```text
snake_case
```

for normal variable names.

Examples:

```python
server_name = "web01"
cpu_usage = 74.5
max_retries = 3
log_file_path = "/var/log/app.log"
```

Words are lowercase and separated by underscores.

This is preferred over:

```python
serverName
ServerName
server-name
```

for ordinary Python variables.

---

# 31. Avoid Names That Are Too Short

This is legal:

```python
s = "web01"
```

But it is less clear.

Prefer:

```python
server = "web01"
```

Short variable names may occasionally make sense in small loops, but descriptive names are usually better for infrastructure automation.

---

# 32. Avoid Misleading Names

Bad:

```python
port = "nginx"
```

The name suggests a port number, but the value contains a service name.

Better:

```python
service_name = "nginx"
```

Variable names should match the meaning of the data.

# 34. Python Uses Dynamic Typing

Python does not require you to declare a variable's type before using it.

You can write:

```python

```

Python determines that the value is an integer.

Then, technically, you could later write:

```python

```

Now the same variable name refers to a string.

Python allows this.

However, just because something is allowed does not mean it is always a good idea.

Changing the expected type of a variable unexpectedly can create confusing bugs.

Prefer consistent meanings.

# 48. Constants by Convention

Python does not enforce true constants in the same way some languages do.

A constant is a value that should not normally change while the program runs.

Python convention uses uppercase names.

Example:

```python

MAX_RETRIES = 3
CPU_ALERT_THRESHOLD = 90
```

This signals to other programmers:

```text
Treat this value as fixed configuration.
```

Python will still technically allow:

```python
DEFAULT_PORT = 8080
```

But the uppercase naming communicates that the value should generally not be reassigned.

```python

```

For now, the key distinction is:

```text
Python variable
    |
    v
exists in your program

Environment variable
    |
    v
exists in the operating system/process environment
```

We will study actual environment variables later.

```python
environment = "production"
```

It may look like you changed the original string.

At the beginner level, think of it instead as:

```text
environment
    |
    v
"development"

then reassignment

environment
    |
    v
"production"
```

The variable name now refers to a different string value.

The original string itself was not modified in place.

# 63. Understanding Immutability with Integers

Example:

```python
retries = 3
```

Then:

```python
retries = retries + 1
```

Now:

```text
retries
```

refers to:

```text
4
```

Python did not mutate the integer `3`.

It evaluated:

```text
3 + 1
```

produced a new value:

```text
4
```

and reassigned the variable.

For example, a list of servers can be changed by adding another server.

```text
Strings, integers, floats, Booleans
are immutable.

Lists and dictionaries
are mutable.
```

# 83. Safe Infrastructure Thinking

Never assume that external values are correct just because they can be converted.

Suppose:

```python
port = int("99999")
```

This conversion succeeds.

But:

```text
99999
```

is not a valid normal TCP/UDP port number.

Likewise:

```python
cpu_threshold = float("500")
```

succeeds as a conversion.

But a CPU percentage threshold of 500 may not make sense for the way your script is designed.

Automation needs two layers of checking:

```text
Type validation
      |
      v
Is this the correct data type?

Value validation
      |
      v
Does this value make sense?
```

We will build these habits later.

# 84. What You Should Now Understand

You should now understand:

* A variable is a name that refers to a value.
* `=` performs assignment.
* Variables make scripts easier to reuse and maintain.
* Python values have data types.
* `str` represents text.
* `int` represents whole numbers.
* `float` represents decimal numbers.
* `bool` represents `True` or `False`.
* `None` represents the absence of a value.
* `type()` can show the type of a value.
* Strings and numbers are not interchangeable.
* Quotation marks usually indicate strings.
* `int()`, `float()`, and `str()` perform common type conversions.
* Invalid conversions can cause errors.
* Good variable names should describe their purpose.
* Python commonly uses `snake_case`.
* Variable names are case-sensitive.
* Python keywords should not be used as variable names.
* Uppercase names are commonly used to indicate constants by convention.
* Multiple assignment can assign several values at once.
* Python variables can represent infrastructure information such as hostnames, ports, service names, thresholds, file paths, and environment names.
* Strings, integers, floats, Booleans, and `None` are immutable.
* Lists and dictionaries, which we will study later, are commonly mutable.
* External configuration values often arrive as strings and may require conversion.
* Correct type does not automatically mean valid infrastructure data.
