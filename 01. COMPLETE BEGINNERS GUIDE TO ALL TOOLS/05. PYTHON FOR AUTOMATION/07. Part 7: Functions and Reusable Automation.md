# Part 7: Functions and Reusable Automation

As automation scripts grow, repetition becomes a problem.

Imagine you need to classify disk usage for several servers.

You could write:

```python
disk_usage = 92

if disk_usage >= 90:
    print("CRITICAL")
elif disk_usage >= 80:
    print("WARNING")
else:
    print("OK")
```

Then later:

```python
disk_usage = 84

if disk_usage >= 90:
    print("CRITICAL")
elif disk_usage >= 80:
    print("WARNING")
else:
    print("OK")
```

Then again for another server.

This works, but the same logic is being copied.

That creates several problems:

* More code to maintain.
* More places for bugs.
* Changes must be repeated.
* Scripts become difficult to read.
* Testing becomes harder.
* Reusing logic becomes inconvenient.

Python functions solve this problem.

Instead of repeating the disk-checking logic, we can create it once:

```python
def check_disk_usage(disk_usage):
    if disk_usage >= 90:
        return "CRITICAL"
    elif disk_usage >= 80:
        return "WARNING"
    else:
        return "OK"
```

Then use it whenever needed:

```python
print(check_disk_usage(92))
print(check_disk_usage(84))
print(check_disk_usage(61))
```

Output:

```text
CRITICAL
WARNING
OK
```

The automation model becomes:

```text
Repeated logic
      |
      v
Place logic in function
      |
      v
Give function input
      |
      v
Function performs task
      |
      v
Receive result
      |
      v
Reuse anywhere
```

Functions are one of the foundations of maintainable Python automation.

---

# 1. What Is a Function?

A function is a named, reusable block of code designed to perform a particular task.

For example:

```python
def show_status():
    print("System check started")
```

This creates a function named:

```text
show_status
```

The function contains:

```python
print("System check started")
```

But defining the function does not automatically execute it.

To execute it, we call the function:

```python
show_status()
```

Output:

```text
System check started
```

---

# 2. Why Functions Matter

Without functions, a script can become a long sequence of commands:

```text
Read server
Check server
Check disk
Format result
Print result
Read next server
Check server
Check disk
Format result
Print result
...
```

With functions, responsibilities can be separated:

```text
main automation
      |
      +--> check_server()
      |
      +--> check_disk_usage()
      |
      +--> process_file()
      |
      +--> format_alert()
      |
      +--> write_log()
```

Each function performs a focused task.

This improves:

* Reusability
* Readability
* Maintainability
* Testing
* Troubleshooting
* Organization

# 3. Functions Reduce Duplication

Consider:

```python
print("Checking web01")
print("Checking web02")
print("Checking web03")
```

We already learned that loops solve repetition across data.

But what if checking each server requires several operations?

You might eventually have:

```text

check disk
check CPU
check services
format result
```

Instead of placing all of that logic directly inside a loop, you can create:

```python

```

Then:

```python

```

This creates a useful relationship:

```text
Loop
decides how many resources to process

Function
defines what to do with one resource
```

# 16. Positional Arguments

Consider:

```python

    print(f"Checking {hostname}:{port}")

check_port("web01", 443)
```

These are positional arguments.

Python matches them according to position:

```text
First argument  -> hostname
Second argument -> port
```

So:

```text
"web01" -> hostname
443     -> port
```

---

# 17. Position Matters

Suppose:

```python

    print(f"{hostname} is in {environment}")
```

Correct:

```python
show_server("web01", "production")
```

Output:

```text
web01 is in production
```

But:

```python
show_server("production", "web01")
```

produces:

```text

```

Python does not know your intended meaning.

It only follows the argument positions.



The second call communicates more meaning.

Keyword arguments can make automation easier to read when functions accept several settings.

```python

```

outputs:


```text

```

because no port was supplied.

# 23. Overriding a Default Argument

You can still provide another value:

```python

```

Output:

```text
Checking api01:8080
```

The provided argument overrides the default.

---

# 24. Why Defaults Matter in Automation

Suppose most HTTPS health checks use:

```text
443
```

You can define:

```python
def check_endpoint(hostname, port=443):
    ...
```

Most calls remain simple:

```python
check_endpoint("app.example.com")
```

But exceptions are still possible:

```python
check_endpoint("internal-api.example.com", 8443)
```

Defaults help represent common behavior without removing flexibility.

---

# 25. Required Parameters Before Default Parameters

Correct:

```python
def check_server(hostname, port=443):
    ...
```

Incorrect:

```python
def check_server(port=443, hostname):
    ...
```

Python requires non-default parameters to appear before default parameters in this kind of function definition.

Otherwise Python cannot cleanly interpret the calling rules.

---

# 26. Be Careful with Mutable Default Arguments

You may eventually be tempted to write:

```python
def record_failure(hostname, failures=[]):
    failures.append(hostname)
    return failures
```

Avoid this pattern.

Lists are mutable, and Python creates that default object when the function is defined, not a brand-new list for every call.

That can cause values to persist unexpectedly between calls.

A safer pattern is:

```python
def record_failure(hostname, failures=None):
    if failures is None:
        failures = []

    failures.append(hostname)
    return failures
```

You do not need to master the underlying implementation yet.

Remember the practical rule:

```text
Avoid using mutable lists or dictionaries directly as default argument values.
```

# 27. Return Values

Printing and returning are not the same thing.

Consider:

```python

        print("CRITICAL")
    else:
        print("OK")
```

This displays a result.

But another part of the program cannot conveniently use that classification.

A better reusable design may return it.


Call:

```python

```

Output:

```text

```

The function gives a value back to the caller.

```text

        |
        v

        |
        v

        |
       Yes
        |
        v

        |
        v
Caller receives value
        |
        v

```

# 31. Why Returning Is Powerful

A returned value can be:

* Stored
* Compared
* Logged
* Added to a collection
* Passed into another function
* Used by a condition
* Included in a report

Example:


# 32. `return` Ends the Function

When Python reaches `return`, that function call ends.

Example:

```python
def check_status(status):
    if status == "healthy":
        return "OK"

    return "FAILED"
```

If:

```python
status == "healthy"
```

Python returns:

```text
OK
```

and does not continue to:

```python
return "FAILED"
```

---

# 33. Code After `return`

Consider:

```python
def test():
    return "done"
    print("This will not run")
```

The `print()` is unreachable during normal execution because the function has already returned.

Avoid placing meaningful code after an unconditional `return`.

Local variables prevent every temporary value from becoming globally available.


# 49. Global Variables

A variable defined outside functions is generally in global scope.

Example:

```python
disk_threshold = 90

def check_disk(disk_usage):
    if disk_usage >= disk_threshold:
        return "CRITICAL"

    return "OK"
```

This works.

But consider whether the threshold should instead be passed explicitly:

```python
def check_disk(disk_usage, threshold):
    if disk_usage >= threshold:
        return "CRITICAL"

    return "OK"
```

Then:

```python
status = check_disk(92, 90)
```

This makes the function's dependencies more visible.

---

# 50. Why Too Many Globals Become a Problem

Imagine:

```python
hostname = "web01"
port = 443
timeout = 5
environment = "production"
disk_threshold = 90
cpu_threshold = 90
```

and many functions silently depend on those variables.

It becomes harder to answer:

```text
What information does this function actually need?
```

Parameters make dependencies explicit.

Compare:

```python
check_server()
```

with:

```python
check_server(hostname, port, timeout)
```

The second call tells the reader more about the function's inputs.

---

# 51. Avoid Modifying Globals Without Good Reason

Consider:

```python
failure_count = 0

def record_failure():
    global failure_count
    failure_count += 1
```

The:

```python
global
```

keyword tells Python that the function intends to modify the global variable.

This works, but it introduces shared state.

A beginner-friendly alternative is often:

```python
def record_failure(failure_count):
    failure_count += 1
    return failure_count
```

Then:

```python
failure_count = 0
failure_count = record_failure(failure_count)
```

Whether this exact pattern is best depends on the larger program, but the important principle is:

```text
Prefer explicit data flow over hidden shared state.
```

---

# 52. Scope Mistake: Local Variable Shadows Global Variable

Example:

```python
environment = "production"

def change_environment():
    environment = "staging"
    print(environment)

change_environment()
print(environment)
```

Output:

```text
staging
production
```

Why?

The assignment inside the function creates a local `environment`.

It does not automatically modify the global one.

# 56. Be Aware of Mutable Arguments

Lists and dictionaries are mutable.

A function can therefore modify an object passed to it.

Example:

```python
def add_failure(failures):
    failures.append("web01")

failed_servers = []

add_failure(failed_servers)

print(failed_servers)
```

Output:

```text
['web01']
```

The original list changed.

This is not automatically wrong.

But the behavior should be intentional.

A function that unexpectedly changes its inputs can be difficult to troubleshoot.

# 57. Functions and Loops

Functions and loops work extremely well together.

# 58. Separating Responsibilities

```python
def format_alert(
```

# 156. Mini Project: Reusable Infrastructure Health Toolkit

We will refactor the multi-server script from Part 6 into reusable functions.

Create:

```text

```

Use:

```python
def classify_percentage(
    value: int,
    warning_threshold: int,
    critical_threshold: int
) -> str:
    """Classify a percentage as OK, WARNING, or CRITICAL."""

    if value < 0 or value > 100:
        return "INVALID"

    if warning_threshold >= critical_threshold:
        return "INVALID"

    if value >= critical_threshold:
        return "CRITICAL"
    elif value >= warning_threshold:
        return "WARNING"
    else:
        return "OK"


def check_disk(
    disk_usage: int
) -> str:
    """Classify disk usage."""

    return classify_percentage(
        value=disk_usage,
        warning_threshold=80,
        critical_threshold=90
    )


def check_cpu(
    cpu_usage: int
) -> str:
    """Classify CPU usage."""

    return classify_percentage(
        value=cpu_usage,
        warning_threshold=75,
        critical_threshold=90
    )


def check_services(
    services: dict
) -> list[str]:
    """Return the names of services that are not running."""

    failed_services = []

    for service, status in services.items():
        if status != "running":
            failed_services.append(service)

    return failed_services


def check_server(
    server: dict
) -> dict:
    """Evaluate one server and return structured health information."""

    hostname = server["hostname"]
    reachable = server["reachable"]

    if not reachable:
        return {
            "hostname": hostname,
            "reachable": False,
            "disk_status": "UNKNOWN",
            "cpu_status": "UNKNOWN",
            "failed_services": [],
            "overall_status": "CRITICAL"
        }

    disk_status = check_disk(
        server["disk_usage"]
    )

    cpu_status = check_cpu(
        server["cpu_usage"]
    )

    failed_services = check_services(
        server["services"]
    )

    if (
        disk_status == "CRITICAL"
        or cpu_status == "CRITICAL"
        or failed_services
    ):
        overall_status = "CRITICAL"

    elif (
        disk_status == "WARNING"
        or cpu_status == "WARNING"
    ):
        overall_status = "WARNING"

    else:
        overall_status = "OK"

    return {
        "hostname": hostname,
        "reachable": True,
        "disk_status": disk_status,
        "cpu_status": cpu_status,
        "failed_services": failed_services,
        "overall_status": overall_status
    }


def format_alert(
    severity: str,
    hostname: str,
    message: str
) -> str:
    """Create a standardized alert message."""

    return (
        f"[{severity}] "
        f"{hostname}: {message}"
    )


def format_server_report(
    result: dict
) -> str:
    """Create a readable one-server health report."""

    hostname = result["hostname"]

    if not result["reachable"]:
        return format_alert(
            severity="CRITICAL",
            hostname=hostname,
            message="Server is unreachable"
        )

    message = (
        f"Disk={result['disk_status']}, "
        f"CPU={result['cpu_status']}, "
        f"Failed services="
        f"{len(result['failed_services'])}"
    )

    return format_alert(
        severity=result["overall_status"],
        hostname=hostname,
        message=message
    )


def check_infrastructure(
    servers: list[dict]
) -> list[dict]:
    """Check all servers and return their health results."""

    results = []

    for server in servers:
        result = check_server(server)
        results.append(result)

    return results


def log_message(
    message: str,
    level: str = "INFO"
) -> None:
    """Print a simple educational log message."""

    print(f"[{level.upper()}] {message}")
```
