
# 3. The Four Main Modules

We will focus on:

```python
import os
import shutil
import sys

from pathlib import Path
```

Each has a different role.

A useful beginner model is:

| Module    | Think of it as                                                 |
| --------- | -------------------------------------------------------------- |
| `os`      | Operating-system environment and low-level OS interfaces       |
| `pathlib` | Modern path and filesystem handling                            |
| `shutil`  | Higher-level file and directory operations                     |
| `sys`     | Python runtime, arguments, platform information, exit behavior |

There is some overlap.

For example, both:

```text
os
```

and:

```text
pathlib
```

can work with directories.

That does not mean one is always wrong.

Modern Python code often prefers `pathlib` for path-oriented operations while still using `os` for features such as environment variables.

# 4. What Is `os`?


```text
Process environment
Operating-system interfaces
```

# 9. Environment Variables

An environment variable is a named value provided to a process through its operating-system environment.

Examples:

```text
PATH
HOME
USER
SHELL
TEMP
TMP
APP_ENV
LOG_LEVEL
DATABASE_HOST
API_URL
```

Applications frequently use environment variables for configuration.

For example:

```text
APP_ENV=production
LOG_LEVEL=INFO
API_URL=https://api.example.com
```

Your Python program can read these values.

---

# 10. Why Environment Variables Exist

Suppose you write:

```python
environment = "development"
```

inside your code.

When deploying to production, you must change the source code.

That is often undesirable.

Instead:

```text
Code
 |
 | reads
 v
APP_ENV
```

Then:

```text
Development machine:
APP_ENV=development

Staging:
APP_ENV=staging

Production:
APP_ENV=production
```

The same program can run in different environments.

---

# 11. Configuration Outside Code

This creates separation:

```text
Application logic
        |
        +---- separate from ----+
                                |
                         Environment config
```

The code might contain:

```python
environment = os.getenv(
    "APP_ENV"
)
```

while deployment supplies the actual value.

This is common in:

* Containers.
* CI/CD pipelines.
* Kubernetes.
* Cloud applications.
* Server automation.
* Platform engineering.

# 12. Environment Variables Are Strings

This is extremely important.

Suppose the shell provides:

```text

```

Python typically receives:

```python
"8080"
```

not:

```python
8080
```

The first is a string.

The second is an integer.

Therefore:

```python
port = int(
    os.getenv(
        "PORT"
    )
)
```

may be necessary.

But this introduces possible conversion failure.

We will handle that safely.

# 14. What If the Variable Does Not Exist?

# 15. Providing a Default Value

You can write:

```python
environment = os.getenv(
    "APP_ENV",
    "development"
```

```text

        |
        v

        |
```

# 16. Defaults Must Be Chosen Carefully

This may look convenient:

```python
environment = os.getenv(
    "APP_ENV",
    "development"
)
```

But should a production deployment silently become:

```text
development
```

when configuration is missing?

Maybe not.

For critical configuration, failure may be safer.

Example:

```python
environment = os.getenv(
    "APP_ENV"
)

if environment is None:
    raise RuntimeError(
        "APP_ENV is required"
    )
```

Choose defaults based on operational requirements.


# 20. `os.getenv()` vs `os.environ[...]`

Important difference:

```python
os.getenv(
    "APP_ENV"
)
```

returns:

```python
None
```

if missing.

```python
os.environ[
    "APP_ENV"
```

```text

```

if the variable does not exist.

---

# 21. Which Should You Use?

For optional values:

```python
os.getenv()
```

is convenient.

For required values, either can work.

You could deliberately use:

```python
os.environ[
    "DATABASE_HOST"
]
```

and handle `KeyError`.

But explicit validation often creates clearer error messages.

Example:

```python
database_host = os.getenv(
    "DATABASE_HOST"
)

if database_host is None:
    raise RuntimeError(
        "Missing required environment "
        "variable: DATABASE_HOST"
    )
```

# 22. Setting an Environment Variable in Python

You can write:

```python
os.environ[
    "APP_ENV"
] = "development"
```

This changes the environment available to the current Python process and child processes it starts.

It does not generally mean:

```text
Permanently configure this variable
for the entire operating system.
```

That distinction matters.

# 23. Process Environment

Think of:

```text
Operating system / shell
          |
          v
   Python process
          |
          v
   Child process
```

Environment variables can be inherited when processes are started.

Changing the Python process environment does not normally travel backward and permanently modify the parent shell.

# 24. Reading Numeric Environment Variables

Suppose:

```text
DISK_THRESHOLD=85
```

Code:

```python
raw_threshold = os.getenv(
    "DISK_THRESHOLD",
    "85"
)

threshold = int(
    raw_threshold
)
```

Now:

```python
threshold
```

is an integer.

---

# 25. Invalid Numeric Environment Variable

Suppose:

```text
DISK_THRESHOLD=high
```

Then:

```python
int(
    "high"
)
```

raises:

```text
ValueError
```

Safe version:

```python
raw_threshold = os.getenv(
    "DISK_THRESHOLD",
    "85"
)

try:
    threshold = int(
        raw_threshold
    )

except ValueError as error:
    raise RuntimeError(
        "DISK_THRESHOLD must "
        "be an integer"
    ) from error
```

---

# 26. Validate the Value Too

Conversion is not enough.

Suppose:

```text
DISK_THRESHOLD=900
```

It converts successfully.

But a percentage threshold of:

```text
900%
```

does not make sense.

Add:

```python
if not 0 <= threshold <= 100:
    raise ValueError(
        "DISK_THRESHOLD must be "
        "between 0 and 100"
    )
```

Remember:

```text
Valid type
does not automatically mean
valid configuration.
```

---

# 27. Boolean Environment Variables

Environment variables do not automatically become Python booleans.

Suppose:

```text
DRY_RUN=false
```

This is still the string:

```python
"false"
```

And:

```python
bool(
    "false"
)
```

returns:

```python
True
```

because non-empty strings are truthy.

This surprises beginners.

---

# 28. Parse Boolean Configuration Explicitly

Example:

```python
raw_dry_run = os.getenv(
    "DRY_RUN",
    "true"
)

dry_run = (
    raw_dry_run
    .strip()
    .lower()
    == "true"
)
```

Now:

```text
true
TRUE
 True
```

can become:

```python
True
```

---

# 29. Better Boolean Validation

You may want to reject invalid values.

```python
def parse_boolean(
    value: str
) -> bool:

    normalized = (
        value
        .strip()
        .lower()
    )

    if normalized == "true":
        return True

    if normalized == "false":
        return False

    raise ValueError(
        f"Invalid boolean: {value}"
    )
```

Usage:

```python
dry_run = parse_boolean(
    os.getenv(
        "DRY_RUN",
        "true"
    )
)
```

This is safer than silently treating every unknown value as false.

---

# 30. Never Print All Environment Variables Blindly

You might see:

```python
print(
    os.environ
)
```

during debugging.

Be careful.

The environment may contain:

```text
API_TOKEN
DATABASE_PASSWORD
AWS credentials
CI/CD secrets
authentication tokens
private configuration
```

Printing the complete environment can leak secrets into:

* Terminal history.
* CI logs.
* Monitoring systems.
* Support tickets.
* Screenshots.

Inspect only what you need.

# 31. Environment Variable Security

Avoid:

```python
print(

)
```

# 33. Current Working Directory

You already learned:


You can also use:

```python
import os

```

Difference in return type:

```python

```

returns a string.

```python
Path.cwd()
```

returns a `Path` object.

---

# 34. Why Prefer `Path.cwd()` in Path-Oriented Code?

Suppose you need:

```text
current directory
+
logs
+
app.log
```

With `Path`:

```python
path = (
    Path.cwd()
    / "logs"
    / "app.log"
)
```

This is convenient.

With a raw string, you would need another path-building operation.

Therefore, for modern filesystem-oriented code:

```python
Path.cwd()
```

is often convenient.

# 35. Changing the Current Working Directory

`os` provides:

```python
os.chdir()
```

Example:

```python
os.chdir(
    "/tmp"
)
```

This changes the current working directory of the Python process.

---

# 36. Be Careful with `os.chdir()`

Changing CWD affects later relative paths.

Example:

```python
print(
    Path.cwd()
)

os.chdir(
    "/tmp"
)

print(
    Path.cwd()
)
```

Now:

```python
Path(
    "report.txt"
)
```

refers to a different location.

This can make programs difficult to reason about.

---

# 37. Prefer Explicit Paths When Possible

Instead of:

```text
Change directory
      |
      v
Perform operation with relative paths
      |
      v
Change directory again
```

often prefer:

```text
Keep CWD stable
      |
      v
Use explicit Path objects
```

Example:

```python
report = (
    Path("/tmp")
    / "report.txt"
)
```

This makes the target obvious.

# 45. File Size

Use:

```python

```

```python

)
```

---

# 46. Bytes and Human-Readable Sizes

Raw size:

```text
1048576 bytes
```

is less convenient for humans than:

```text
1 MiB
```

You can convert sizes.

For example:

```python
size_bytes = path.stat().st_size

size_mib = (
    size_bytes
    / 1024
    / 1024
)

print(
    f"{size_mib:.2f} MiB"
)
```

---

# 47. KB, MB, KiB, and MiB

Be aware that storage units can use decimal or binary definitions.

Decimal:

```text
1 KB = 1000 bytes
1 MB = 1000 KB
```

Binary:

```text
1 KiB = 1024 bytes
1 MiB = 1024 KiB
```

If your calculation divides by:

```text
1024 × 1024
```

the technically accurate label is:

```text
MiB
```

rather than MB.

# 51. Directory Traversal

Directory traversal means walking through directory contents.

Example:

```text
project/
|
+-- logs/
|    |
|    +-- app.log
|
+-- config/
|    |
|    +-- app.json
|
+-- reports/
     |
     +-- report.txt
```

Automation may need to inspect everything under:

```text
project/
```

---

# 52. `Path.iterdir()`

For immediate entries:

```python
directory = Path(
    "project"
)

for path in directory.iterdir():
    print(
        path
    )
```

This gives entries directly inside:

```text
project/
```

---

# 53. Recursive Traversal with `rglob()`

```python
for path in directory.rglob(
    "*"
):
    print(
        path
    )
```

This recursively finds descendants.

---

# 54. Filter Regular Files

```python
for path in directory.rglob(
    "*"
):

    if not path.is_file():
        continue

    print(
        path
    )
```

Now you process only files.

---

# 55. Filter Directories

```python
for path in directory.rglob(
    "*"
):

    if path.is_dir():
        print(
            f"Directory: {path}"
        )
```

---

# 56. `os.walk()`

Another important directory traversal tool is:

```python
os.walk()
```

Example:

```python
import os


for (
    root,
    directories,
    files
) in os.walk(
    "project"
):
    print(
        root
    )

    print(
        directories
    )

    print(
        files
    )
```

---

# 57. Understanding `os.walk()`

For each directory visited, `os.walk()` provides:

```text
root
=
current directory being visited

directories
=
names of subdirectories

files
=
names of files
```

Conceptually:

```text
Visit project/
    |
    +--> directories: logs, config
    +--> files: README.md

Visit project/logs/
    |
    +--> files: app.log

Visit project/config/
    |
    +--> files: app.json
```

---

# 58. `os.walk()` vs `Path.rglob()`

Both can recursively traverse directories.

`Path.rglob()` is often concise when you want:

```text
Find all paths matching this pattern.
```

`os.walk()` is useful when you want more explicit control over:

```text
current root
subdirectory names
filenames
```

Learn both.

Do not turn this into:

```text
one is always correct
and the other is always wrong.
```

---

# 59. Building Paths from `os.walk()`

The filenames returned by `os.walk()` are not necessarily complete paths.

You may build one using:

```python
from pathlib import Path


for root, directories, files in os.walk(
    "project"
):

    root_path = Path(
        root
    )

    for filename in files:

        path = (
            root_path
            / filename
        )

        print(
            path
        )
```

Now you have `Path` objects.

---

# 60. Avoid Traversing Huge Trees Accidentally

Never casually run recursive automation from:

```text
/
```

or another huge filesystem root unless that is truly intended.

Ask:

```text
What is the traversal root?

How many entries may exist?

Should some directories be excluded?

Could there be mounted filesystems?

Could there be permission failures?

Could symbolic links affect behavior?

How long could the scan take?
```

Scope is part of safe automation.

# 84. Disk Monitoring Function

Using Part 7 function design:

```python
from pathlib import Path
import shutil


def get_disk_usage(
    path: Path
) -> dict:

    usage = shutil.disk_usage(
        path
    )

    if usage.total <= 0:
        raise RuntimeError(
            "Invalid disk capacity"
        )

    percent_used = (
        usage.used
        / usage.total
        * 100
    )

    return {
        "total": usage.total,
        "used": usage.used,
        "free": usage.free,
        "percent_used": percent_used
    }
```

# 104. Do Not Return Success After Failure

Bad:

```python
try:
    perform_backup()

except PermissionError:
    print(
        "Backup failed"
    )

sys.exit(
    0
)
```

The human sees:

```text
Backup failed
```

but the operating system sees:

```text
success
```

That is inconsistent.

---

# 105. Better Exit-Code Design

```python
def main() -> int:

    try:
        perform_backup()

    except PermissionError as error:
        print(
            f"Backup failed: "
            f"{error}"
        )

        return 1

    return 0
```

Then:

```python
if __name__ == "__main__":
    sys.exit(
        main()
    )
```

This is a clean pattern.

---

# 106. Why `main()` Returning an Integer Is Useful

It separates:

```text
application logic
```

from:

```text
process termination
```

Your function can be tested:

```python

```

without necessarily terminating another importing program.

Then the script entry point converts the result into a process exit status.

---

# 107. `sys.exit()` Raises an Exception Internally

Technically:

```python
sys.exit()
```

raises:

```text
SystemExit
```

which normally causes the interpreter to terminate.

This is one reason you generally should not scatter `sys.exit()` throughout deeply nested reusable functions.

Instead, reusable functions can:

```text
return values
```

or:

```text
raise meaningful exceptions
```

and the top-level application decides the final exit code.

---

# 108. Better Layering

Prefer:

```text
Low-level function
      |
      +--> returns value
      |
      +--> raises meaningful exception
               |
               v
main()
      |
      +--> decides application outcome
               |
               v
sys.exit()
```

This creates reusable automation.

```python
    normalized = (
        value
        .strip()
        .lower()
    )

    if normalized == "true":
        return True

    if normalized == "false":
        return False

    raise ValueError(
        f"Invalid boolean value: "
        f"{value}"
    )
```

# 143. Preserve Failures

```python
def inspect_files(
```

```python
from pathlib import Path


def validate_cleanup_target(
    target: Path,
    allowed_root: Path
) -> None:

    resolved_target = (
        target.resolve()

        allowed_root.resolve()

        resolved_target
```

# 146. Delete Function

```python
def delete_file(
    target: Path,
    allowed_root: Path,
    dry_run: bool
) -> dict:

    validate_cleanup_target(
        target,
        allowed_root
    )

    size = target.stat().st_size

    if dry_run:

        return {
            "path": str(target),
            "status": "DRY_RUN",
            "bytes_freed": 0,
            "candidate_bytes": size
        }

    target.unlink()

    if target.exists():
        raise RuntimeError(
            f"Deletion verification "
            f"failed: {target}"
        )

    return {
        "path": str(target),
        "status": "DELETED",
        "bytes_freed": size,
        "candidate_bytes": size
    }
```
