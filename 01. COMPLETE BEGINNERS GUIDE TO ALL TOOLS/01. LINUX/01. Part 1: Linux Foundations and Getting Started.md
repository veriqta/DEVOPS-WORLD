# Part 1: Linux Foundations and Getting Started

Linux can feel difficult when you first see a terminal full of commands, paths, symbols, and unfamiliar words.

The best way to learn Linux is not to memorize commands first.

You should first understand:

* What Linux is
* What problem an operating system solves
* How Linux is structured
* What the kernel does
* What a distribution is
* What the shell and terminal do
* How commands are structured
* How to safely practice Linux

This part builds that foundation.

By the end of this part, you should be able to open a Linux terminal, understand what you are looking at, run basic commands, interpret simple output, and know where to get help when you do not understand a command.

# 1. What Is an Operating System?

Before understanding Linux, you need to understand what an operating system is.

An operating system, often shortened to OS, is the main software that manages a computer.

Examples include:

* Linux
* Windows
* macOS
* Android
* iOS

The operating system sits between:

* The physical computer hardware
* The programs you use

A simplified view looks like this:

```text
Applications
    |
    v
Operating System
    |
    v
Hardware
```

Your hardware includes things such as:

* CPU
* Memory
* Disk
* Network card
* Keyboard
* Screen

Your applications include things such as:

* Web browsers
* Text editors
* Databases
* Web servers
* Development tools
* Monitoring systems

Without an operating system, every application would have to communicate with the hardware directly.

That would make software extremely difficult to build.

Instead, the operating system provides a controlled way for applications to use the hardware.

For example, when a program wants to save a file, the program does not normally control the physical disk directly.

It asks the operating system to handle that operation.

The operating system decides:

* Where the file is stored
* Whether the user has permission
* How the data reaches the disk
* How storage resources are managed

The same principle applies to:

* Memory
* CPU time
* Networking
* Devices
* Processes
* Files

## Major Responsibilities of an Operating System

An operating system is responsible for several important areas.

### Process Management

A process is a running program.

The operating system determines:

* Which processes can run
* How much CPU time they receive
* When they start
* When they stop
* How they interact with each other

You will study Linux processes later in this series.

### Memory Management

Programs need memory to operate.

The operating system controls:

* Which program gets memory
* How much memory it receives
* What happens when memory becomes limited
* How programs are separated from each other

### File Management

The operating system provides a filesystem that organizes information into:

* Files
* Directories
* Paths

Linux has its own filesystem structure, which you will study in Part 2.

### Device Management

The operating system communicates with hardware such as:

* Disks
* Network devices
* USB devices
* Keyboards
* Screens

### Security and Access Control

The operating system controls:

* Users
* Passwords
* File permissions
* Ownership
* Administrative privileges

These controls prevent every user from automatically having access to everything.

### Networking

The operating system provides networking capabilities such as:

* IP addressing
* Routing
* Network connections
* Ports
* Network interfaces

Linux networking becomes especially important in cloud and DevOps environments.

# 4. Unix vs Linux

Beginners often hear both Unix and Linux and assume they are the same thing.

They are related, but they are not identical.

## What Is Unix?

Unix is an operating system family that originated in the late 1960s and early 1970s at Bell Labs.

Unix introduced many ideas that later influenced Linux.

These include:

* Multi-user systems
* Hierarchical filesystems
* Small tools that perform specific tasks
* Combining tools together
* Command-line shells
* Permissions
* Processes
* Pipes

Several commercial Unix systems appeared over time.

Examples historically included:

* AIX
* HP-UX
* Solaris

macOS also has Unix foundations and is certified as a Unix operating system.

## What Is Linux?

Linux was created later.

Linux was inspired heavily by Unix concepts, but it was developed separately.

Linux is generally described as Unix-like.

That means it behaves similarly to Unix in many ways without being the original Unix system.

## Simplified Comparison

```text
Unix
 |
 | influenced
 v
Unix-like operating systems
 |
 +---- Linux
 |
 +---- BSD family
 |
 +---- others
```

As a beginner, the important idea is this:

Linux inherited many Unix concepts.

That is why Linux uses concepts such as:

* Shells
* Processes
* Permissions
* Pipes
* Hierarchical filesystems
* Command-line tools

# 5. Brief History of Linux

Understanding a little history helps explain why Linux looks the way it does today.

## Unix

Unix was developed at Bell Labs beginning around 1969.

It became influential in universities, research institutions, and commercial computing.

Many modern operating-system concepts came from Unix.

## GNU Project

In 1983, Richard Stallman announced the GNU Project.

GNU aimed to build a free Unix-like operating system.

GNU developers created many important tools that are still widely used today.

Examples include:

* Bash
* GCC
* Core command-line utilities
* Libraries
* Development tools

However, the GNU project needed a kernel.

## Linux Kernel

In 1991, Linus Torvalds, then a student in Finland, began developing a kernel.

That kernel became Linux.

When the Linux kernel was combined with GNU tools and other software, complete Linux operating systems became possible.

This is one reason you may sometimes see the term:

```text
GNU/Linux
```

In normal industry conversation, most people simply say Linux.

## Linux Today

Linux now runs a huge amount of modern infrastructure.

It is widely used in:

* Cloud computing
* Web hosting
* Containers
* Kubernetes
* DevOps
* Networking
* Supercomputing
* Embedded systems
* Enterprise applications

# 6. What Is the Linux Kernel?

The kernel is the core part of the operating system.

It directly manages communication between software and hardware.

Think of the kernel as the central manager of the system.

A simplified architecture looks like this:

```text
Applications
     |
     v
Shell and Utilities
     |
     v
Linux Kernel
     |
     v
Hardware
```

The Linux kernel manages areas such as:

* CPU
* Memory
* Devices
* Processes
* Filesystems
* Networking
* Security mechanisms

## Example

Suppose you run:

```bash
cat report.txt
```

You are asking Linux to display the contents of a file.

Several things happen behind the scenes.

```text
You
 |
 v
Shell
 |
 v
cat program
 |
 v
Linux kernel
 |
 v
Filesystem and disk
```

The `cat` program does not directly control the physical disk.

It asks the kernel to access the file.

The kernel:

* Checks permissions
* Finds the file
* Reads the data
* Returns the data to the program

The program then displays it in your terminal.

Different groups have different priorities.

One organization may prioritize:

* Stability

Another may prioritize:

* New features

Another may focus on:

* Enterprise support

Another may focus on:

* Cloud workloads

Another may focus on:

* Desktop users

Although distributions may look different, many core Linux concepts remain the same.

# 33. Understanding the Linux Command Prompt

When you open a terminal, you may see something similar to:

```text
ann@linux-server:~$
```

Let us break it down.

```text
ann
```

is the username.

```text
linux-server
```

is the hostname.

```text
~
```

represents the user's home directory.

```text
$
```

usually indicates that you are logged in as a regular user.

So:

```text
ann@linux-server:~$
```

roughly means:

```text
User ann
on computer linux-server
currently inside the home directory
using a regular-user shell
```

# 37. Root vs Regular Users

Linux has a special administrative account called:

```text
root
```

Root has extremely broad control over the system.

Root can typically:

* Modify system files
* Install software
* Delete important data
* Change users
* Change permissions
* Stop services
* Modify networking

Because root is powerful, using it carelessly can damage the system.

A safer approach is usually:

1. Work as a regular user.
2. Use elevated privileges only when required.

This is often done using:

```bash
sudo
```

You will study sudo properly in Part 4.

# 38. Linux Case Sensitivity

Linux is case-sensitive.

This means:

```text
File.txt
```

and:

```text
file.txt
```

are different names.

These could all exist at the same time:

```text
report.txt
Report.txt
REPORT.txt
```

The same applies to commands.

For example:

```bash
pwd
```

works.

But:

```bash
PWD
```

does not mean the same command.

Case sensitivity is a common source of beginner mistakes.

# 56. Short vs Long Options

Linux commands often support short and long option forms.

Short options commonly begin with one hyphen:

```bash

```

Long options commonly begin with two hyphens:

```bash

```

Example:

```bash

```

may be equivalent to:

```bash
ls --all
```

depending on the command.

Another example:

```bash
uname --help
```

Long options are often easier for beginners to understand because their names are descriptive.

# 67. Common Beginner Mistakes

## Mistake 1: Wrong Capitalization

You run:

```bash
PWD
```

instead of:

```bash
pwd
```

Linux treats them differently.

Fix:

Check capitalization carefully.

---

## Mistake 2: Typing the Prompt Symbol

You may see instructions such as:

```text
$ pwd
```

The `$` represents the shell prompt.

You usually type only:

```bash
pwd
```

Do not type:

```bash
$ pwd
```

unless `$` is genuinely part of a command.

---

## Mistake 3: Using the Wrong Option

You run:

```bash
uname -A
```

instead of:

```bash
uname -a
```

Because Linux is case-sensitive, these are not automatically equivalent.

---

## Mistake 4: Running Commands Without Understanding Them

A beginner finds an internet command and pastes it into the terminal.

This is risky.

Before running unfamiliar commands:

* Read the command
* Check its options
* Look at the manual
* Understand whether it modifies or deletes anything

Commands executed with administrative privileges can make significant system changes.

---

## Mistake 5: Forgetting Which Machine You Are On

This becomes important when using SSH.

You may think you are working on your laptop when you are actually connected to a production server.

Always pay attention to:

* Username
* Hostname
* Prompt

Commands such as:

```bash
hostname
```

and:

```bash
whoami
```

help confirm where and who you are.
