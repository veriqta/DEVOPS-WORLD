# 1. What Is Python?

Python is a general-purpose programming language.

A programming language gives humans a structured way to tell computers what to do.

For example, you might want a computer to:

* Check whether a server is responding.
* Read a configuration file.
* Search application logs for errors.
* Call a cloud API.
* Check disk usage.
* Restart a failed service.
* Process hundreds of files.
* Query Kubernetes resources.
* Generate a report.
* Send an alert when something goes wrong.

You could perform many of these tasks manually.

Python allows you to describe the steps once and let the computer perform them repeatedly.

A very simple Python program looks like this:

```python
print("Hello from Python")
```

The `print()` function tells Python to display something on the screen.

Running the program produces:

```text
Hello from Python
```

This example is simple, but the same language can be used to build much more useful automation.

For example:

```python
server = "web-server-01"
status = "running"

print(f"{server} is {status}")
```

Output:

```text
web-server-01 is running
```

Later, instead of manually setting the status to `running`, your script could retrieve the actual status from Linux, AWS, Kubernetes, Docker, or an API.

That is where Python becomes particularly useful for infrastructure engineers.

# 6. What Is the Python Interpreter?

Computers do not directly understand Python source code the same way humans read it.

Something must process your Python instructions.

That is the job of the Python interpreter.

Suppose you create:

```text
hello.py
```

containing:

```python
print("Hello DevOps")
```

When you execute:

```bash
python3 hello.py
```

the Python interpreter reads and executes the program.

Conceptually:

```text
hello.py
   |
   v
Python Interpreter
   |
   v
Program Execution
   |
   v
Hello DevOps
```

The interpreter is the program responsible for running your Python code.

When you install Python, you are installing the Python runtime and interpreter needed to execute Python programs.

---

# 7. How Python Executes Code

A beginner-friendly model is:

```text
Python source code
       |
       v
Python interpreter
       |
       v
Python bytecode
       |
       v
Python virtual machine
       |
       v
Program executes
```

Let's unpack that.

## Step 1: You Write Source Code

For example:

```python
server = "web01"
print(server)
```

This human-readable code is called source code.

## Step 2: Python Processes the Code

In the standard CPython implementation, Python compiles source code into an intermediate representation called bytecode.

You normally do not need to perform this compilation manually.

## Step 3: Python Executes the Bytecode

The Python virtual machine executes the bytecode.

The important beginner takeaway is:

**You write Python source code, and the Python runtime handles the work required to execute it.**

You do not need to manually compile a normal Python script before running it.

# 14. Installing Python on Linux

The exact installation method depends on the Linux distribution.

Before installing Python, check:

```bash
python3 --version
```

Many Linux distributions already include Python 3.

## Ubuntu/Debian

First update the package information:

```bash
sudo apt update
```

Then install Python 3:

```bash
sudo apt install python3
```

You may also need `pip` later:

```bash
sudo apt install python3-pip
```

Verify:

```bash
python3 --version
```

And:

```bash
pip3 --version
```

### What is happening?

`sudo` runs the command with elevated privileges when your account is authorized to do so.

`apt` is the package-management tool used by Debian-based systems such as Ubuntu.

`update` refreshes package information.

`install` tells `apt` to install a package.

`python3` is the package being requested.

Do not randomly remove or replace the system Python installation on Linux. Some operating-system tools may depend on it.

For learning and automation projects, we will later use virtual environments rather than modifying system Python unnecessarily.

# 27. Comments

Comments allow you to write notes inside your code.

Python ignores normal comments during execution.

A single-line comment begins with:

```text
#
```

Example:

```python
# Check the production server
server = "prod-web-01"
```

You can also write:

```python
server = "prod-web-01"  # Primary web server
```

Comments are useful for explaining:

* Why something is being done.
* Safety considerations.
* Non-obvious behavior.
* Temporary operational context.

Avoid comments that merely repeat obvious code.

Weak:

```python
# Print server
print(server)
```

More useful:

```python
# This server must be checked before starting the deployment.
print(server)
```

Comments should explain useful context, especially the reason behind a decision.

# 28. Indentation in Python

Indentation is extremely important in Python.

Many languages use symbols such as braces to identify blocks of code.

Python uses indentation.

Consider:

```python
if server_status == "down":
    print("Investigate server")
```

The second line is indented.

That tells Python that the `print()` statement belongs to the `if` block.

Conceptually:

```text
IF server is down
|
+--> print warning
```

Incorrect indentation can cause an error or change program behavior.

For example:

```python
if server_status == "down":
print("Investigate server")
```

Python expects an indented block after the `if` statement.

You might receive:

```text
IndentationError
```

A common Python convention is four spaces per indentation level.

VS Code can help manage this automatically.

# 31. How to Read a Python Error

Suppose you create:

```python
print(server)
```

without defining `server`.

Python may produce output similar to:

```text
Traceback (most recent call last):
  File "check.py", line 1, in <module>
    print(server)
NameError: name 'server' is not defined
```

Do not panic when you see a traceback.

Start from the bottom.

The final line often tells you the type of error:

```text
NameError
```

and gives a description:

```text
name 'server' is not defined
```

Then identify the relevant line:

```text
line 1
```

Then inspect:

```python
print(server)
```

Ask:

```text
Where was server defined?
```

It was not.

Fix:

```python
server = "web01"
print(server)
```

Expected result:

```text
web01
```

This is the beginning of troubleshooting Python.

# 38. Safe Automation Matters

Automation increases your power.

It also increases the potential impact of mistakes.

A manual mistake might affect one file.

A badly designed automation script might affect thousands.

Consider the difference:

```text
Manual action
   |
   v
One server
```

versus:

```text
Automation
   |
   +--> Server 1
   +--> Server 2
   +--> Server 3
   +--> ...
   +--> Server 500
```

This is why infrastructure automation should eventually include:

* Input validation
* Error handling
* Logging
* Least privilege
* Dry-run modes
* Verification
* Safe defaults
* Clear failure messages
* Controlled permissions

You will learn these progressively throughout this series.

For now, do not run unfamiliar Python automation against production systems simply because you found the script online.

# 41. Common Problems in This Lab

## Problem: `python3: command not found`

### What you see

Your terminal cannot find `python3`.

### Possible causes

* Python 3 is not installed.
* Python is installed under another command.
* Python is not available through your `PATH`.

### Investigate

Try:

```bash
python --version
```

and:

```bash
python3 --version
```

On Windows:

```powershell
py --version
```

### Fix

Install or correctly configure Python for your operating system.

### Verify

Run the version command again.

---

## Problem: Python Cannot Find Your Script

### What you see

An error indicating that the file cannot be opened or does not exist.

### Possible cause

You are in the wrong directory.

### Investigate

Linux/macOS:

```bash
pwd
ls
```

Windows PowerShell:

```powershell
Get-Location
Get-ChildItem
```

Check whether your `.py` file appears.

### Fix

Move to the correct directory using `cd`.

### Verify

Run the script again.

---

## Problem: `SyntaxError`

### What you see

Python reports invalid syntax.

### Possible causes

* Missing quote
* Missing parenthesis
* Incorrect punctuation
* Invalid Python syntax

### Investigate

Read the error message and inspect the indicated line.

### Fix

Correct the syntax.

### Verify

Run the script again.

---

## Problem: `IndentationError`

### What you see

Python complains about indentation.

### Possible cause

A block of Python code is not indented correctly.

### Fix

Use consistent indentation. Four spaces per indentation level is the standard convention.

---

## Problem: `NameError`

### What you see

Something similar to:

```text
NameError: name 'server' is not defined
```

### Possible cause

You are trying to use a name that Python does not currently know.

### Investigate

Check:

* Was the variable created?
* Is the spelling correct?
* Is the capitalization correct?

### Fix

Define the value or correct the name.
