# 2. What Is JSON?

JSON stands for:

```text
JavaScript Object Notation
```

Despite the name, JSON is not limited to JavaScript.

It is a language-independent text format used to represent structured data.

For example:

```json
{
    "service": "payments",
    "port": 443,
    "healthy": true
}
```

This is text.

But the text follows JSON syntax rules that allow programs to interpret its structure.

---

# 3. Why JSON Exists

Programs frequently need to exchange information.

Imagine:

```text
Python automation
      |
      v
Cloud API
      |
      v
Server information
```

The cloud API needs a predictable format for sending that information back.

JSON provides such a format.

Instead of returning an informal sentence:

```text
The server called web01 is running
and its CPU usage is 42 percent.
```

an API can return:

```json
{
    "name": "web01",
    "status": "running",
    "cpu": 42
}
```

Programs can process this much more reliably.

# 7. JSON Objects

A JSON object contains key-value pairs.

Example:

```json
{
    "hostname": "web01",
    "port": 443
}
```

The keys are:

```text
hostname
port
```

Their values are:

```text
web01
443
```

Conceptually:

```text
hostname ---> web01
port -------> 443
```

---

# 8. Object Syntax

A JSON object begins with:

```text
{
```

and ends with:

```text
}
```

Key-value pairs are separated by commas.

A key and its value are separated by:

```text
:
```

Example:

```json
{
    "environment": "production",
    "region": "us-east-1",
    "replicas": 3
}
```

---

# 9. JSON Object Keys Must Be Strings

JSON object keys are strings.

Correct:

```json
{
    "port": 443
}
```

The key:

```text
port
```

is enclosed in double quotes.

This differs from Python dictionaries, where keys can have several data types.

---

# 10. JSON Arrays

A JSON array is an ordered collection of values.

Example:

```json
[
    "web01",
    "web02",
    "web03"
]
```

Conceptually:

```text
index 0 --> web01
index 1 --> web02
index 2 --> web03
```

Arrays are similar to Python lists.

---

# 11. Arrays Inside Objects

A JSON object can contain an array.

Example:

```json
{
    "environment": "production",
    "servers": [
        "web01",
        "web02",
        "web03"
    ]
}
```

Structure:

```text
environment
   |
   +--> production

servers
   |
   +--> web01
   +--> web02
   +--> web03
```

---

# 12. Objects Inside Arrays

Arrays can also contain objects.

Example:

```json
[
    {
        "name": "web01",
        "status": "running"
    },
    {
        "name": "web02",
        "status": "stopped"
    }
]
```

This pattern is extremely common in APIs.

It represents a collection of resources.

---

# 13. JSON Strings

Strings represent text.

Example:

```json
{
    "service": "payments",
    "region": "us-east-1"
}
```

The values:

```text
payments
us-east-1
```

are strings.

JSON strings must use double quotes.

---

# 14. JSON Requires Double Quotes

Correct JSON:

```json
{
    "service": "payments"
}
```

Invalid JSON:

```text
{
    'service': 'payments'
}
```

Python allows single-quoted strings.

JSON does not.

This is one of the most common beginner mistakes.

---

# 15. JSON Numbers

JSON supports numeric values.

Example:

```json
{
    "port": 443,
    "cpu": 67.5,
    "replicas": 3
}
```

These values are numbers, not strings.

Compare:

```json
{
    "port": 443
}
```

with:

```json
{
    "port": "443"
}
```

The first is numeric.

The second is text.

That distinction matters.

---

# 16. Why Number Types Matter

Suppose Python needs to check:

```text
CPU > 80
```

If CPU is numeric:

```python
cpu = 85

if cpu > 80:
    print("High CPU")
```

That works naturally.

If CPU is text:

```python
cpu = "85"
```

you may need conversion first.

Correct data types make automation easier and safer.

---

# 17. JSON Booleans

JSON supports:

```text
true
false
```

Example:

```json
{
    "healthy": true,
    "maintenance": false
}
```

Notice the lowercase spelling.

JSON uses:

```text
true
false
```

Python uses:

```python
True
False
```

Do not confuse them.

---

# 18. JSON Null

JSON supports:

```text
null
```

This represents the absence of a value.

Example:

```json
{
    "public_ip": null
}
```

This may mean the resource currently has no public IP address.

In Python, JSON `null` becomes:

```python
None
```

# 19. JSON Type Summary

| JSON           | Example              | Typical Python Type |
| -------------- | -------------------- | ------------------- |
| Object         | `{"name": "web01"}`  | `dict`              |
| Array          | `["web01", "web02"]` | `list`              |
| String         | `"web01"`            | `str`               |
| Number         | `42`                 | `int`               |
| Decimal number | `42.5`               | `float`             |
| Boolean        | `true`               | `True` / `bool`     |
| Boolean        | `false`              | `False` / `bool`    |
| Null           | `null`               | `None`              |

This mapping is fundamental.

JSON objects look very similar to Python dictionaries.


JSON:

```json

    "name": "web01",
    "status": "running",
    "healthy": true
```

They look similar.

They are not the same thing.


# 23. Why the Difference Matters

Suppose an API returns:

```text

```

Python may initially receive that as text.

Before doing:

```python

```

you need to convert:

```text

```

into:

```text

```

That conversion is called parsing or deserialization.

# 29. `json.loads()`

Example:

```python

    "name": "web01",
    "status": "running"
}

    json_text
)

print(
    server
)
```

Now:

```python
server
```

is a Python dictionary.

---

```text

     |
```

# 47. What `dump()` Does

```text

      |
      v

      v

      |
      v
File
```


# 48. Pretty Printing JSON

# 92. Safe JSON File Loader

```python
import json
from pathlib import Path


def load_json_file(
    path: Path
) -> dict:

    try:
        with path.open(
            "r",
            encoding="utf-8"
        ) as file:

            data = json.load(
                file
            )

    except FileNotFoundError as error:

        raise RuntimeError(
            f"JSON file not found: "
            f"{path}"
        ) from error

    except PermissionError as error:

        raise RuntimeError(
            f"Permission denied: "
            f"{path}"
        ) from error

    except json.JSONDecodeError as error:

        raise RuntimeError(
            f"Invalid JSON in "
            f"{path}: "
            f"line {error.lineno}, "
            f"column {error.colno}"
        ) from error

    return data
```

```python
import json
from pathlib import Path


def load_json_file(
    path: Path
) -> dict:

    try:
        with path.open(
            "r",
            encoding="utf-8"
        ) as file:

            data = json.load(
                file
            )

    except FileNotFoundError as error:

        raise RuntimeError(
            f"File not found: "
            f"{path}"
        ) from error

    except PermissionError as error:

        raise RuntimeError(
            f"Permission denied: "
            f"{path}"
        ) from error

    except json.JSONDecodeError as error:

        raise RuntimeError(
            f"Invalid JSON in "
            f"{path} at "
            f"line {error.lineno}, "
            f"column {error.colno}"
        ) from error

    return data
```

# 202. Security Checklist for JSON

Before processing external JSON, ask:

* Where did the data come from?
* Is the source trusted?
* Can a user control it?
* Can an API return unexpected structures?
* Are required fields validated?
* Are types validated?
* Are numeric ranges validated?
* Are resource IDs trusted?
* Will any field later become a command argument?
* Does the JSON contain secrets?
* Will the JSON be logged?
* Will it be committed to Git?
* Could maliciously large input consume resources?
* Could nested data cause unexpected behavior?
* Are destructive actions based on JSON values?

JSON is data.

But data can influence powerful automation.

Treat external data as untrusted until validated appropriately.

---

# 203. JSON Plus `subprocess`: Security Boundary

Imagine:

```json
{
    "service": "nginx"
}
```

Then Python does:

```python
service = data[
    "service"
]
```

and:

```python
subprocess.run(
    [
        "systemctl",
        "restart",
        service
    ]
)
```

The JSON value now influences a system command.

Therefore:

```text
JSON input
   |
   v
Validation
   |
   v
Approved value
   |
   v
Command argument
```

Do not blindly trust the field just because the JSON was syntactically valid.

---

# 204. Validate Before Infrastructure Actions

For example:

```python
allowed_services = {
    "nginx",
    "api",
    "worker"
}


service = data.get(
    "service"
)


if service not in allowed_services:

    raise ValueError(
        "Unsupported service"
    )
```

Only then should controlled automation consider using it.

This combines JSON security with Part 13 command security.

---

# 205. Do Not Use JSON as an Excuse for Dynamic Execution

Dangerous design:

```json
{
    "command": "some arbitrary command"
}
```

followed by unrestricted shell execution.

A JSON file is not automatically trusted code.

Prefer data describing approved operations.

For example:

```json
{
    "action": "check_disk"
}
```

Then map:

```text
check_disk
```

to predefined safe Python behavior.

---

# 206. Prefer Intent Over Raw Commands

Better:

```json
{
    "action": "check_service",
    "service": "nginx"
}
```

Then Python validates:

```text
action
service
```

and chooses a predefined operation.

Avoid designs where external JSON directly dictates arbitrary shell commands.

# 207. Production Consideration: JSON Schema

As applications become larger, manually checking every field becomes repetitive.

There are formal approaches for describing expected JSON structure, including JSON Schema and validation libraries.

These can define things such as:

* Required fields.
* Types.
* Allowed values.
* Numeric ranges.
* Nested structures.

For this beginner series, manual validation is useful because it teaches what validation actually means.

Later, tools can automate more of it.

# 208. Production Consideration: Large JSON Documents

`json.load()` and `json.loads()` generally build the parsed object in memory.

For normal API responses and configuration files, this is often fine.

For extremely large JSON datasets, memory usage may become important.

Large-scale systems may use:

* Pagination.
* Streaming.
* Chunked processing.
* Specialized parsers.
* Databases.

Do not optimize prematurely, but understand the limitation.

---

# 209. Production Consideration: JSON Is Not a Database

JSON files are useful for:

* Configuration.
* Small inventories.
* Reports.
* Data exchange.
* Test fixtures.

They are not automatically a good replacement for a database.

If many processes need concurrent updates, searching, transactions, or large-scale persistence, a database may be more appropriate.

---

# 210. Production Consideration: Do Not Rewrite Important Files Carelessly

This:

```python
json.dump(
    data,
    file
)
```

with write mode can replace an existing file.

For critical automation configuration, consider safer update patterns:

```text
Read existing
     |
     v

     |
     v
Modify copy
     |
     v
Validate new result
     |
     v
Write temporary file
     |
     v
Replace carefully
     |
     v
Verify
```

The exact strategy depends on the application.
