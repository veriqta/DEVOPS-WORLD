# Production Troubleshooting Practice

A DevOps engineer should eventually be able to investigate situations such as:

- A server cannot reach the Internet
- An application cannot connect to a database
- DNS resolves to the wrong address
- DNS does not resolve
- A TCP connection times out
- A connection is refused
- A port is not listening
- A firewall blocks traffic
- A load balancer reports unhealthy targets
- HTTPS fails
- A TLS certificate is invalid
- A cloud instance cannot reach another subnet
- A container cannot reach another container
- A Kubernetes Pod cannot reach a Service
- External users cannot reach an application
- Network latency suddenly increases
- Packets are being dropped

Use a troubleshooting sequence instead of guessing:

**DNS → IP → Route → Port → Firewall → TLS → Load Balancer → Service → Application**
