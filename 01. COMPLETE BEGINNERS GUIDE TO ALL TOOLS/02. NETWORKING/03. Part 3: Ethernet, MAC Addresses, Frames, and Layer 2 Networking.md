# Part 3: Ethernet, MAC Addresses, Frames, and Layer 2 Networking

In Part 2, you learned that networking is divided into layers.

You learned this simplified stack:

```text
Application
    |
Transport
    |
Network
    |
Data Link
    |
Physical
```

Now we move deeper into Layer 2, the Data Link layer.

This is where Ethernet, MAC addresses, frames, switches, and local network communication become important.

By the end of this part, you should understand what actually happens when one Ethernet-connected device needs to send data to another device on the local network.

You should also understand why a switch needs a MAC address table, why broadcasts exist, what happens when a switch does not know where a destination is, and how to begin troubleshooting Layer 2 problems.

---

# 1. What Is Ethernet?

Ethernet is a family of networking technologies used extensively for communication on local area networks.

When you connect:

```text
Computer
   |
Ethernet cable
   |
Switch
```

you are commonly using Ethernet technologies.

Ethernet defines important rules concerning:

* How network interfaces communicate
* How data is organized into frames
* MAC addressing
* Physical transmission standards
* Supported speeds
* Cabling and media
* Frame delivery across a local link

Ethernet primarily spans concepts associated with:

```text
Layer 2
Data Link

and

Layer 1
Physical
```

Layer 2 deals with Ethernet frames and MAC addressing.

Layer 1 deals with how the information is physically transmitted.

---

# 2. Why Ethernet Exists

Imagine connecting several computers to a local network.

```text
Computer A
     \
Computer B --- Switch
     /
Computer C
```

The devices need agreed rules.

They need to know:

* How data should be packaged
* How interfaces are identified
* How the receiving device is identified
* How errors can be detected
* How bits are transmitted
* What speeds and physical media can be used

Ethernet provides standardized mechanisms for these tasks.

Without standards, equipment from different manufacturers could have difficulty communicating.

---

# 3. Ethernet Is More Than a Cable

Beginners sometimes think:

```text
Ethernet = Ethernet cable
```

That is incomplete.

Ethernet includes standards governing both physical transmission and Layer 2 communication.

The cable is only one component.

Ethernet involves:

```text
Ethernet
   |
   +---- Physical media
   |
   +---- Signaling
   |
   +---- Network interfaces
   |
   +---- MAC addresses
   |
   +---- Ethernet frames
   |
   +---- Link speeds
```

Modern Ethernet can operate over:

* Twisted-pair copper
* Fiber optic media
* Other standardized physical implementations

---

# 4. Ethernet Standards

Ethernet standards are primarily developed within the IEEE 802.3 family.

IEEE stands for:

Institute of Electrical and Electronics Engineers.

You do not need to memorize every Ethernet standard as a beginner.

You should understand that Ethernet has evolved significantly.

Common Ethernet speeds include:

```text
10 Mbps
100 Mbps
1 Gbps
10 Gbps
25 Gbps
40 Gbps
100 Gbps
```

There are even faster Ethernet standards.

Different standards specify things such as:

* Speed
* Cable type
* Fiber type
* Maximum distances
* Signaling
* Connector and transceiver requirements

---

# 5. Common Ethernet Naming

You may encounter names such as:

```text
10BASE-T
100BASE-TX
1000BASE-T
10GBASE-T
```

Let's understand the general idea.

For:

```text
1000BASE-T
```

`1000` refers to approximately 1000 Mbps, which is 1 Gbps.

`BASE` refers to baseband signaling.

`T` indicates twisted-pair copper cabling.

So:

```text
1000BASE-T
```

is commonly known as Gigabit Ethernet over twisted-pair copper.

You do not need to memorize every naming variation yet.

The important idea is that Ethernet standards define how compatible equipment communicates.

# 6. Network Interface Cards

A computer needs hardware or a virtual equivalent that allows it to participate in a network.

This is commonly called a Network Interface Card, or NIC.

You may also hear:

* Network adapter
* Ethernet adapter
* Network interface

Conceptually:

```text
Computer
   |
   v
NIC
   |
   v
Ethernet Cable
   |
   v
Switch
```

The NIC handles important network communication functions.

---

# 7. Physical and Virtual Network Interfaces

Network interfaces are not always physical cards.

A physical server might have:

```text
eth0
eth1
```

A virtual machine can also have a virtual network interface.

Containers and cloud environments heavily use virtual interfaces.

For example:

```text
Physical Server
     |
     +---- Physical NIC
     |
     +---- Virtual Interface
     |
     +---- Virtual Interface
```

The underlying implementation differs, but the operating system still works with network interfaces.

This becomes very important later when studying:

* Virtual machines
* Docker
* Kubernetes
* Cloud networking

# 8. What Is a MAC Address?

MAC stands for Media Access Control.

A MAC address is a Layer 2 address associated with a network interface.

A typical 48-bit MAC address looks like:

```text
00:1A:2B:3C:4D:5E
```

Depending on the system, you may also see formats such as:

```text
00-1A-2B-3C-4D-5E
```

A MAC address is used for local Layer 2 delivery.

Remember the distinction from Part 2:

```text
Layer 2
MAC address

Layer 3
IP address

Layer 4
Port number
```

These identifiers solve different problems.

---

# 9. Why Do We Need MAC Addresses If We Have IP Addresses?

This is an important question.

Suppose:

```text
Computer A
192.168.1.10

Computer B
192.168.1.20
```

They are connected to the same Ethernet network.

Computer A wants to send an IP packet to Computer B.

At Layer 3, Computer A knows:

```text
Destination IP:
192.168.1.20
```

But Ethernet needs Layer 2 information for local delivery.

It needs a destination MAC address.

Conceptually:

```text
IP packet
Destination IP: 192.168.1.20

        |
        v

Ethernet frame
Destination MAC: ?
```

Computer A therefore needs to determine which MAC address corresponds to the local destination IP.

This is one of the jobs ARP performs for IPv4.

We will introduce ARP shortly.

---

# 10. MAC Address Structure

A traditional Ethernet MAC address is 48 bits long.

That equals:

```text
48 bits
=
6 bytes
```

It is commonly written as six hexadecimal groups:

```text
00:1A:2B:3C:4D:5E
```

Each hexadecimal pair represents one byte.

Conceptually:

```text
00 : 1A : 2B : 3C : 4D : 5E
|     |    |    |    |    |
1     2    3    4    5    6
byte  byte byte byte byte byte
```

Historically, globally assigned MAC addresses include a manufacturer-related prefix, called an Organizationally Unique Identifier, or OUI, along with interface-specific bits.

However, modern operating systems can also use:

* Locally administered addresses
* Randomized MAC addresses
* Virtual MAC addresses

So you should not assume that every MAC address permanently identifies a particular physical device or manufacturer.

---

# 11. MAC Addresses Are Usually Local-Link Addresses

An important beginner principle is:

MAC addresses normally matter on the local Layer 2 link.

They are not used like IP addresses to route traffic across the entire Internet.

Suppose:

```text
Laptop
   |
Switch
   |
Router
   |
Internet
   |
Router
   |
Server
```

The laptop does not normally create one Ethernet frame addressed directly to the remote server's MAC address and send that unchanged across the Internet.

Instead, Layer 2 delivery happens link by link.

The first Ethernet frame may be addressed to the local router.

The router removes that Layer 2 framing, examines the IP packet, then creates appropriate Layer 2 framing for the next link.

Conceptually:

```text
Laptop
   |
   | Frame A
   v
Router
   |
   | Frame B
   v
Next Hop
```

The Layer 2 addresses can change as traffic moves between links.

---

# 12. Unicast MAC Addresses

A unicast MAC address identifies one network interface for ordinary one-to-one Layer 2 delivery.

Conceptually:

```text
Computer A
    |
    | Frame
    v
Computer B
```

The Ethernet frame contains:

```text
Source MAC:
MAC of Computer A

Destination MAC:
MAC of Computer B
```

The switch uses the destination MAC address to determine where to forward the frame.

---

# 13. Broadcast MAC Address

Ethernet also has a broadcast MAC address.

It is:

```text
FF:FF:FF:FF:FF:FF
```

This means:

```text
Deliver this frame to every relevant device
within this Layer 2 broadcast domain.
```

Conceptually:

```text
              ---> Computer B
             /
Computer A --+----> Computer C
             \
              ---> Computer D
```

Broadcasting is important when the sender does not yet know which specific device needs to respond.

ARP requests are a major example.

---

# 14. Ethernet Frames

Ethernet does not simply transmit a raw IP packet by itself.

It packages Layer 3 data inside an Ethernet frame.

A simplified Ethernet frame looks like:

```text
+-------------------------+
| Destination MAC         |
+-------------------------+
| Source MAC              |
+-------------------------+
| EtherType / Length      |
+-------------------------+
| Payload                 |
+-------------------------+
| Frame Check Sequence    |
+-------------------------+
```

There are additional details associated with Ethernet transmission, such as preamble and start-of-frame information, but this simplified structure is enough to build the beginner mental model.

---

# 15. Why Frames Exist

Layer 2 needs its own structure.

The Ethernet frame tells network interfaces and switches important information, including:

* Who sent the frame
* Who should receive it
* What higher-layer protocol is being carried
* Whether corruption was detected during transmission

Think of an Ethernet frame as a local delivery envelope.

Inside the envelope might be an IP packet.

```text
Ethernet Frame
|
+---- Destination MAC
|
+---- Source MAC
|
+---- EtherType
|
+---- IP Packet
|
+---- Frame Check Sequence
```

---

# 16. Destination MAC Address

The destination MAC address tells the Layer 2 network where the frame should go.

Example:

```text
Destination MAC:
AA:BB:CC:DD:EE:FF
```

A switch reads this field.

It checks its MAC address table.

Conceptually:

```text
Frame arrives
     |
     v
Read destination MAC
     |
     v
Check MAC table
     |
     v
Determine outgoing port
```

This is fundamental to Ethernet switching.

---

# 17. Source MAC Address

The source MAC address identifies the interface that sent the Ethernet frame on that link.

Example:

```text
Source MAC:
00:11:22:33:44:55
```

Switches use source MAC addresses for an important process called MAC learning.

When a frame arrives, the switch learns:

```text
I received this source MAC
on this switch port.
```

It records that relationship in its MAC address table.

---

# 18. EtherType

EtherType identifies what protocol is carried inside the Ethernet frame.

For example, common values include:

```text
0x0800 = IPv4

0x86DD = IPv6

0x0806 = ARP
```

Conceptually:

```text
Ethernet Frame
    |
    +---- EtherType: IPv4
    |
    v
IPv4 Packet
```

or:

```text
Ethernet Frame
    |
    +---- EtherType: ARP
    |
    v
ARP Message
```

This allows the receiving system to know what should process the payload next.

---

# 19. Frame Check Sequence

Ethernet includes a Frame Check Sequence, or FCS.

The FCS helps detect whether a frame was corrupted during transmission.

The sender calculates a value based on the frame contents.

The receiver performs its own calculation.

If the result does not match what was expected, corruption is detected.

Conceptually:

```text
Sender
  |
  | Calculate FCS
  v
Frame
  |
  v
Network
  |
  v
Receiver
  |
  | Verify FCS
  v
Valid or corrupted?
```

Ethernet commonly uses a cyclic redundancy check mechanism for this purpose.

---

# 20. What Happens to a Corrupted Ethernet Frame?

If the receiving Ethernet hardware detects that a frame is corrupted, the frame is generally discarded.

Ethernet itself does not provide TCP-style retransmission.

This is an important distinction.

Layer 2 can detect certain corruption.

Higher layers may be responsible for recovering from data loss.

For example, TCP may eventually retransmit missing data.

Conceptually:

```text
Corrupted frame
      |
      v
Discarded
      |
      v
TCP may later detect missing data
      |
      v
Retransmission
```

This demonstrates how networking layers work together.

---

# 21. Ethernet Payload

The payload contains the data Ethernet is carrying.

For ordinary IPv4 communication:

```text
Ethernet Frame
      |
      v
IPv4 Packet
      |
      v
TCP Segment
      |
      v
Application Data
```

This is encapsulation again.

From Part 2:

```text
Application Data
      |
      v
TCP Segment
      |
      v
IP Packet
      |
      v
Ethernet Frame
```

Ethernet provides the Layer 2 wrapper around the Layer 3 packet.

---

# 22. What Is MTU?

MTU stands for Maximum Transmission Unit.

MTU describes the maximum Layer 3 packet size that can normally be carried in a frame payload on a link without needing IP-layer fragmentation, depending on the protocol and path.

For ordinary Ethernet, a commonly encountered IP MTU is:

```text
1500 bytes
```

This does not mean the complete Ethernet frame is only 1500 bytes.

The Ethernet frame also contains Layer 2 overhead.

The 1500-byte figure commonly refers to the Ethernet payload available to carry a Layer 3 packet.

---

# 23. Why MTU Matters

Suppose a system attempts to send packets larger than what part of the path can support.

Possible consequences include:

* IPv4 fragmentation, if allowed and appropriate
* Packet drops
* Path MTU discovery behavior
* Application problems
* VPN connectivity issues
* Strange partial connectivity

MTU problems can be difficult for beginners because basic connectivity might work while certain larger transmissions fail.

For example:

```text
Small packets
SUCCESS

Large packets
FAILURE
```

This can be a clue to investigate MTU-related problems.

MTU and fragmentation will appear again later in the networking series.

---

# 24. Jumbo Frames

Jumbo frames allow Ethernet environments to carry payloads larger than the traditional 1500-byte Ethernet MTU.

A commonly used jumbo MTU is around:

```text
9000 bytes
```

Exact support depends on the network equipment and configuration.

Jumbo frames can reduce some processing overhead in environments where large amounts of data are transferred.

However, jumbo frames must be configured carefully.

If:

```text
Server A
MTU 9000
```

but an intermediate network component only supports:

```text
MTU 1500
```

you may encounter communication problems.

Do not enable jumbo frames simply because a larger number sounds better.

The path must support the configuration appropriately.

---

# 25. Layer 2 Communication

Let's now follow a local Ethernet communication.

Suppose:

```text
Computer A

IP:
192.168.1.10

MAC:
AA:AA:AA:AA:AA:AA
```

wants to communicate with:

```text
Computer B

IP:
192.168.1.20

MAC:
BB:BB:BB:BB:BB:BB
```

Both are on the same local network.

```text
Computer A
    |
    v
Switch
    |
    v
Computer B
```

Computer A creates an IP packet.

Conceptually:

```text
Source IP:
192.168.1.10

Destination IP:
192.168.1.20
```

But Ethernet also needs:

```text
Source MAC:
AA:AA:AA:AA:AA:AA

Destination MAC:
BB:BB:BB:BB:BB:BB
```

How does Computer A discover Computer B's MAC address?

ARP helps solve this problem.

---

# 26. Introduction to ARP

ARP stands for Address Resolution Protocol.

ARP is used in IPv4 Ethernet-style local networking to discover the Layer 2 address associated with a local IPv4 address.

Computer A knows:

```text
Destination IP:
192.168.1.20
```

but does not know:

```text
Destination MAC:
?
```

It asks:

```text
Who has 192.168.1.20?
```

This ARP request is sent using Ethernet broadcast.

---

# 27. ARP Request

Computer A creates an ARP request.

Conceptually:

```text
Who has 192.168.1.20?

Tell 192.168.1.10.
```

The Ethernet destination is:

```text
FF:FF:FF:FF:FF:FF
```

the broadcast MAC address.

The switch forwards the broadcast to relevant ports within the broadcast domain.

```text
              ---> Computer B
             /
Computer A -- Switch ---> Computer C
             \
              ---> Computer D
```

All relevant hosts can receive the request.

But only the host that owns:

```text
192.168.1.20
```

should respond normally.

---

# 28. ARP Reply

Computer B responds:

```text
192.168.1.20 is at
BB:BB:BB:BB:BB:BB
```

Computer A can now associate:

```text
192.168.1.20
        |
        v
BB:BB:BB:BB:BB:BB
```

It stores this information temporarily in its ARP or neighbor cache.

Now Computer A can create the Ethernet frame:

```text
Source MAC:
AA:AA:AA:AA:AA:AA

Destination MAC:
BB:BB:BB:BB:BB:BB
```

and send the actual traffic.

Part 6 will explore ARP in much greater depth.

---

# 29. What If the Destination Is on Another Network?

This is a critical concept.

Suppose Computer A wants to communicate with:

```text
203.0.113.50
```

which is on a remote network.

Computer A does not normally ARP for the remote server's MAC address.

Instead, it determines that the destination is remote.

It sends the Ethernet frame to its local router, commonly its default gateway.

Suppose the router has:

```text
IP:
192.168.1.1

MAC:
CC:CC:CC:CC:CC:CC
```

The frame may contain:

```text
Destination MAC:
CC:CC:CC:CC:CC:CC
```

while the IP packet contains:

```text
Destination IP:
203.0.113.50
```

Notice the difference:

```text
Ethernet destination
=
Local next hop

IP destination
=
Final remote destination
```

This is one of the most important networking concepts you can learn.

---

# 30. Local vs Remote Destination

For a local destination:

```text
Computer A
    |
    | Destination MAC = Computer B
    v
Computer B
```

For a remote destination:

```text
Computer A
    |
    | Destination MAC = Router
    v
Router
    |
    v
Remote networks
    |
    v
Server
```

The IP packet still identifies the remote server.

The Ethernet frame handles delivery to the next Layer 2 destination.

Routing will be covered deeply in Part 8.

---

# 31. What Is a Broadcast Domain?

A broadcast domain is the set of Layer 2 devices that can receive a Layer 2 broadcast from one another without a router separating them.

Suppose:

```text
Computer A
     |
Computer B
     |
   Switch
     |
Computer C
```

If these devices belong to the same VLAN and Layer 2 broadcast domain, a broadcast from Computer A can reach B and C.

Conceptually:

```text
A broadcasts
    |
    v
Switch
 |     |
 v     v
B     C
```

---

# 32. Routers Separate Broadcast Domains

Suppose:

```text
Network A
   |
Router
   |
Network B
```

Layer 2 broadcasts normally do not pass through the router from one broadcast domain into another.

Conceptually:

```text
A ---> Broadcast ---> Router X ---> Network B
```

The router acts as a Layer 3 boundary.

This prevents ordinary Ethernet broadcasts from spreading across every network.

---

# 33. Why Broadcast Domains Matter

Broadcasts consume network resources because multiple devices must receive and process them.

If a Layer 2 domain becomes extremely large, excessive broadcast traffic can become undesirable.

Networks are therefore segmented using technologies such as:

* Routers
* VLANs
* Layer 3 interfaces

You will learn VLANs in Part 7.

---

# 34. What Is a Collision Domain?

A collision domain is a network area where simultaneous transmissions could interfere with each other under shared-medium, half-duplex Ethernet operation.

This concept was especially important with older Ethernet technologies such as hubs.

Imagine:

```text
Computer A
     |
     |
    Hub
   /   \
  B     C
```

A hub repeats traffic.

If A and B transmitted simultaneously in classic shared half-duplex Ethernet, their signals could collide.

---

# 35. Collision Domains and Switches

Modern switched Ethernet dramatically changed this behavior.

Consider:

```text
A -----\
        Switch
B -----/
```

Each switch port provides a separate point-to-point Ethernet link.

With modern full-duplex Ethernet, devices can transmit and receive simultaneously without the old shared-medium collision behavior.

Therefore:

```text
Hub
Shared collision domain

Switch
Separate links per port
```

This is one reason switches replaced hubs.

---

# 36. Ethernet Hubs vs Switches

A hub is a simple Layer 1 device.

If a frame arrives:

```text
Port 1
```

the hub repeats the signal to other ports.

Conceptually:

```text
       ---> B
      /
A --- Hub ---> C
      \
       ---> D
```

It does not intelligently inspect destination MAC addresses to decide which one port should receive a unicast frame.

A switch is different.

It learns where MAC addresses are located.

Then it forwards known unicast frames more intelligently.

---

# 37. What Is an Ethernet Switch?

An Ethernet switch is primarily a Layer 2 network device.

It connects devices within a local Ethernet network.

Example:

```text
Computer A ----\
                \
Computer B ----- Switch ----- Server
                /
Printer -------/
```

The switch receives Ethernet frames and decides where to forward them.

Its most important information for ordinary Layer 2 forwarding is:

```text
Destination MAC address
```

---

# 38. Switch Ports

A switch contains physical or virtual ports.

Example:

```text
Switch

Port 1 ---- Computer A
Port 2 ---- Computer B
Port 3 ---- Server
Port 4 ---- Printer
```

The switch needs to learn which MAC addresses are reachable through which ports.

This information is stored in a MAC address table.

---

# 39. MAC Address Table

A switch MAC address table may conceptually look like:

| MAC Address       | Port |
| ----------------- | ---- |
| AA:AA:AA:AA:AA:AA | 1    |
| BB:BB:BB:BB:BB:BB | 2    |
| CC:CC:CC:CC:CC:CC | 3    |

This means:

```text
MAC AA...
reachable through Port 1

MAC BB...
reachable through Port 2

MAC CC...
reachable through Port 3
```

The switch builds this table dynamically by observing traffic.

---

# 40. How MAC Learning Works

Suppose Computer A is connected to Port 1.

Its MAC address is:

```text
AA:AA:AA:AA:AA:AA
```

Computer A sends a frame.

The switch receives it on Port 1.

The switch examines:

```text
Source MAC
```

It learns:

```text
AA:AA:AA:AA:AA:AA
is reachable through Port 1.
```

This is MAC learning.

The switch learns from the source address, not from guessing.

---

# 41. Why the Source MAC Is Used for Learning

Imagine receiving a letter.

The return address tells you where the sender is.

Similarly, when a switch receives:

```text
Source MAC:
AA:AA:AA:AA:AA:AA
```

on:

```text
Port 1
```

it learns:

```text
To reach AA:AA:AA:AA:AA:AA,
use Port 1.
```

The destination MAC is used to decide where the current frame should go.

The source MAC helps the switch learn where the sender lives.

---

# 42. Frame Forwarding

Suppose the switch already knows:

```text
AA:AA:AA:AA:AA:AA -> Port 1

BB:BB:BB:BB:BB:BB -> Port 2
```

Computer A sends:

```text
Source MAC:
AA:AA:AA:AA:AA:AA

Destination MAC:
BB:BB:BB:BB:BB:BB
```

The switch checks the destination.

It finds:

```text
BB:BB:BB:BB:BB:BB
-> Port 2
```

So it forwards the frame out Port 2.

```text
A
|
Port 1
|
Switch
|
Port 2
|
B
```

It does not need to send that known unicast frame to every port.

---

# 43. What Happens When the Switch Does Not Know the Destination?

Suppose Computer A sends to:

```text
DD:DD:DD:DD:DD:DD
```

but the switch does not have that MAC address in its table.

The switch cannot yet determine the correct outgoing port.

So it performs flooding.

---

# 44. Frame Flooding

Flooding means the switch sends the frame out relevant ports in the same VLAN except the port on which the frame arrived.

Suppose:

```text
A ---- Port 1

B ---- Port 2

C ---- Port 3

D ---- Port 4
```

A sends a frame to an unknown MAC.

The switch may forward it:

```text
            ---> Port 2
           /
Port 1 --- Switch ---> Port 3
           \
            ---> Port 4
```

The frame is not sent back out the ingress port.

Eventually, if the destination responds, the switch can learn where that MAC address is located.

---

# 45. Unknown Unicast

A unicast frame whose destination MAC address is not currently known to the switch is called an unknown unicast.

Important distinction:

```text
Unicast
One intended destination

Unknown unicast
One intended destination,
but switch does not know its port
```

Because the switch does not know the location, it floods the frame within the relevant Layer 2 domain.

This does not turn the frame into a broadcast frame.

The destination MAC is still a unicast address.

The switch is simply flooding it because it lacks forwarding information.

---

# 46. Broadcast Traffic

Broadcast traffic is different.

A broadcast frame already has:

```text
Destination MAC:
FF:FF:FF:FF:FF:FF
```

The switch intentionally forwards it to relevant ports within the VLAN because all devices in that broadcast domain are potential recipients.

Example:

```text
ARP Request
   |
   v
Switch
 |   |   |
 v   v   v
A   B   C
```

Broadcasting is expected behavior.

Flooding an unknown unicast is also expected switch behavior, but for a different reason.

---

# 47. Broadcast vs Unknown Unicast

This distinction matters.

## Broadcast

Destination:

```text
FF:FF:FF:FF:FF:FF
```

Meaning:

```text
Everyone in this broadcast domain
should receive this.
```

## Unknown unicast

Destination:

```text
AA:BB:CC:DD:EE:FF
```

Meaning:

```text
One specific device should receive this,
but the switch does not currently know where it is.
```

The switch floods both types under normal circumstances, but the reason is different.

---

# 48. MAC Table Aging

Switches do not normally keep every learned MAC address forever.

Dynamic entries age out after a period of inactivity.

Suppose:

```text
AA:AA:AA:AA:AA:AA -> Port 1
```

is learned.

If the device disappears and no traffic is seen for a sufficient period, the switch can remove the entry.

Why?

Because devices can:

* Disconnect
* Move to another port
* Reboot
* Change network location

A stale table should not permanently direct frames incorrectly.

---

# 49. What Happens When a Device Moves?

Suppose:

```text
Computer A
MAC AA:AA:AA:AA:AA:AA
```

was connected to:

```text
Port 1
```

and later moves to:

```text
Port 5
```

When the switch sees frames from that source MAC on Port 5, it can update its table.

Conceptually:

```text
Old:

AA... -> Port 1

New:

AA... -> Port 5
```

Dynamic MAC learning allows switches to adapt.

---

# 50. Full Duplex

Full duplex means both sides of a link can transmit and receive simultaneously.

```text
Device A
   <=========>
Device B
```

Modern switched Ethernet normally operates full duplex.

For example:

```text
Server
   <=========>
Switch
```

Both sides can send traffic at the same time.

---

# 51. Half Duplex

Half duplex allows communication in both directions, but not simultaneously.

Conceptually:

```text
A --------> B

then

A <-------- B
```

Older shared Ethernet networks using hubs commonly operated in half-duplex mode.

Collision detection was therefore important.

---

# 52. Duplex Mismatch

A duplex mismatch can occur when one side expects full duplex while the other operates half duplex.

For example:

```text
Server
Full duplex

Switch
Half duplex
```

This can cause serious performance problems.

Symptoms can include:

* Poor throughput
* Errors
* Retransmissions
* Intermittent performance
* Collisions reported on the half-duplex side

Modern auto-negotiation makes these problems less common than historically, but the concept remains important for troubleshooting.

---

# 53. Speed Negotiation

Ethernet interfaces may support multiple speeds.

For example:

```text
100 Mbps
1 Gbps
10 Gbps
```

Interfaces often use auto-negotiation to determine appropriate link parameters.

Suppose:

```text
Server NIC:
Supports 1 Gbps

Switch port:
Supports 1 Gbps
```

They may negotiate:

```text
Speed: 1 Gbps
Duplex: Full
```

But problems with:

* Cabling
* Configuration
* Hardware
* Negotiation

can sometimes result in unexpected link speeds.

For example:

```text
Expected:
1 Gbps

Actual:
100 Mbps
```

This can explain unexpected performance limitations.

# 71. Troubleshooting Requires Comparison


2. Reproduce the problem.
3. Check the counter again.


Now you have stronger evidence of an active problem.

# 89. Common Beginner Mistakes

## Mistake 1: Thinking MAC and IP addresses are interchangeable

They are not.

```text
MAC
Layer 2 local-link addressing

IP
Layer 3 logical addressing and routing
```

---

## Mistake 2: Thinking the remote server's MAC travels across the Internet

Normally, it does not.

Layer 2 framing changes as packets cross different Layer 2 links.

---

## Mistake 3: Thinking switches route using IP addresses

A traditional Layer 2 switch primarily forwards Ethernet frames based on MAC addresses.

Layer 3 switches can also perform routing, but that is a separate function.

---

## Mistake 4: Thinking flooding means broadcasting

Unknown unicast flooding and broadcasting are not the same thing.

The switch may flood both, but the destination addresses and reasons differ.

---

## Mistake 5: Assuming a switch knows every MAC immediately

Switches learn MAC locations dynamically by examining source MAC addresses.

Before learning a destination, unknown unicast traffic may be flooded.

---

## Mistake 6: Assuming every MAC address permanently identifies physical hardware

Virtualization, locally administered addresses, and MAC randomization mean this assumption is unsafe.

---

## Mistake 7: Ignoring physical evidence during Layer 2 troubleshooting

Before investigating complicated switch behavior, check:

```text
Interface
Link
Cable
Speed
Duplex
Errors
```

Simple failures are common.

```text
Switch floods broadcast
        |
        v
B receives request
        |
        v
B sends ARP reply
        |
        v
A learns B's MAC
```

A can then send:

```text
Ethernet:

Source MAC:
AA:AA:AA:AA:AA:AA

Destination MAC:
BB:BB:BB:BB:BB:BB


IP:

Source IP:
192.168.1.10

Destination IP:
192.168.1.20
```

The switch forwards the frame toward B once B's MAC location is known.

## Scenario 2: A communicates with a remote server

Destination:

```text
203.0.113.50
```

A determines that the server is not local.

It needs the router.

The first Ethernet frame contains:

```text
Source MAC:
AA:AA:AA:AA:AA:AA

Destination MAC:
CC:CC:CC:CC:CC:CC
```

But inside that frame, the IP packet contains:

```text
Source IP:
192.168.1.10

Destination IP:
203.0.113.50
```

The router receives the frame.

It removes the incoming Layer 2 framing.

It examines:

```text
Destination IP:
203.0.113.50
```

It makes a Layer 3 forwarding decision.

It then uses appropriate Layer 2 framing for the next link.

That is how Layer 2 and Layer 3 work together without doing the same job.

```text

       |

     |
```


and forwards using:


```text

       |
```

```text

        |
```

The most important distinction to carry forward is:

```text
MAC addresses handle local Layer 2 delivery.

IP addresses handle Layer 3 addressing and routing.

Switches primarily forward frames using MAC addresses.

Routers primarily forward packets using IP addresses.
```

Once you understand that distinction, many networking concepts that initially appear complicated become much easier to reason about.
